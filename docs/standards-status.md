# 標準の達成状況

`node scripts/standards.mjs` で作る表です（手で直さない）。項目の定義・判定の方法・宣言の書き方は [standards.md](standards.md) にあります。

- ✓：満たしている／✗：満たしていない／n/a：当てはまらない（ゲームの package.json の宣言か、判定の条件で決まる）
- 判定はファイルの文字列を見るだけなので、誤ることがあります。誤りに気づいたら、判定（scripts/standards.mjs）か宣言を直します

## 宣言

各ゲームの package.json の `standards` に書いた、当てはまらない項目と理由。「判定」は、宣言がなかったときの判定です（✓ なら宣言はいらないかもしれない）。

| ゲーム | id | 理由 | 判定 |
|---|---|---|:-:|
| dominion | cpu-level | CPU はカードごとに手で調整した動き方を1組だけ持ち、強さを変える仕組みがない | ✗ |
| katan | undo | サイコロ・発展カードの山札・奪うカードの乱数と、相手の手札という隠れた情報があり、戻すと有利になる | ✗ |
| lucky-numbers | bgm | 独自の音（js/sound.js）を使い、packages/sound のエンジンは使わない（packages/sound/README.md の決まり） | ✗ |
| lucky-numbers | undo | 伏せたタイルを山から引くゲームで、1手戻すと引いて見えたタイルの情報を使えてしまう | ✗ |
| mine-blocks | cpu | 1人で解くパズルで、競う相手はオンラインの人だけ（CPU の相手がいない） | ✗ |
| mine-blocks | replay | 生成した問題を解くパズルで、局面は問題と置いたピースの盤面そのもの。手番の操作を記録して再現する作りが当てはまらない | ✗ |
| mine-blocks | bgm | 独自の音（js/sound.js）を使い、packages/sound のエンジンは使わない（packages/sound/README.md の決まり） | ✗ |
| mine-blocks | undo | 置いたピースはいつでもタップで外して置き場に戻せる（どのピースも戻せるので、1手戻す操作は要らない） | ✗ |
| panel-de-pon | resume | リアルタイムの落ち物パズルで1試合が短く、途中で止めて後から続ける遊び方をしない | ✗ |
| panel-de-pon | replay | リアルタイムで操作の時刻が結果を決めるため、手番の操作を記録して再現する作りが当てはまらない | ✗ |
| panel-de-pon | undo | リアルタイムで、1手戻すことがない | ✗ |
| panel-de-pon | bgm | 独自の音（js/sound.js）を使い、packages/sound のエンジンは使わない（packages/sound/README.md の決まり） | ✗ |
| panel-de-pon | hint | リアルタイムの落ち物パズルで、考えて選ぶ手番がない（おすすめの手を示す場面がない） | ✗ |
| pokemon-card-game | undo | 山札・手札・サイドが隠れていて、引く・混ぜる・コインの乱数もあるので、戻すと有利になる | ✗ |
| wordle | cpu | 答えを当てる1人用の言葉のパズルで、競う相手はオンラインの人だけ（CPU の相手がいない） | ✗ |
| wordle | replay | 局面は答えと入力した単語の一覧そのもの。手番の操作を記録して再現する作りが当てはまらない | ✗ |
