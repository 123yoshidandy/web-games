# ラー

太陽駒を出してタイルを競り落とし、古代エジプトで名声を集めるボードゲーム「ラー（Ra、Reiner Knizia、alea 1999）」の基本ゲームを、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

タイルの絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方

### 準備

- タイル180枚を袋に入れる。各自10点
- 太陽駒の組を1つずつ配る。中央に太陽駒1を置く。一番大きい太陽駒を持つ人から始める

| 人数 | 太陽駒の組 | ラーのトラック |
|---|---|---|
| 2人 | 9・6・5・2 ／ 8・7・4・3 | 6 |
| 3人 | 13・8・5・2 ／ 12・9・6・3 ／ 11・10・7・4 | 8 |
| 4人 | 13・6・2 ／ 12・7・3 ／ 11・8・4 ／ 10・9・5 | 9 |
| 5人 | 16・7・2 ／ 15・8・3 ／ 14・9・4 ／ 13・10・5 ／ 12・11・6 | 10 |

タイル180枚：ラー30、神8、金5、ファラオ25、ナイル河25、洪水12、文明25（天文学・農業・文字・宗教・芸術×5）、モニュメント40（要塞・オベリスク・宮殿・ピラミッド・神殿・像・階段ピラミッド・スフィンクス×5）、災害10（葬式2・干ばつ2・内乱4・地震2）。

### 手番

次のどれか1つ。表の太陽駒がない人は、時代の終わりまで休み。

| 行動 | 内容 |
|---|---|
| 引く | 袋から1枚引いて、競りのトラックに置く（8枚まで。8枚なら引けない）。ラーなら、ラーのトラックに置いて競り |
| ラー | 競りを始める |
| 神 | 持っている神1枚につき、競りのトラックから1枚取る（神は取れない）。使った神は捨てる |

### 競り

- ラーの人の左から1回ずつ、前より大きい表の太陽駒を1枚出すか、見送る。ラーの人は最後
- 自分でラー宣言した競りで、ほかの全員が見送ったら、ラーの人は出さなければならない。ただし、競りのトラックが8枚でラー宣言したときは見送れて、全員見送りならトラックのタイルを捨てる
- ラーを引いて始まった競りで全員が見送ったら、タイルはそのまま残る
- 勝った人は、競りのトラックのタイルをすべて取り（なければ太陽駒だけ）、出した太陽駒を中央に置き、中央の太陽駒を裏向きで受け取る（この時代では使えない）
- 災害を取った人は、種類ごとに2枚捨てる（1枚しかなければ1枚、なければ0枚）：葬式はファラオ、干ばつは洪水を先に・足りなければナイル河、内乱は文明、地震はモニュメント

### 時代の終わりと得点

- ラーのトラックが埋まったら、そのラーでは競りをせず、両方のトラックのタイルを捨てて終わり。全員の太陽駒が裏になっても終わり
- 得点のあと、太陽駒をすべて表に戻し、一番大きい太陽駒の人から次の時代

| タイル | 点 | 時代のあと |
|---|---|---|
| 神 | 1枚2点 | 捨てる |
| 金 | 1枚3点 | 捨てる |
| ファラオ | 一番多い人+5、一番少ない人-2（同じなら全員。全員同じなら点なし） | 残る |
| ナイル河・洪水 | 洪水が1枚以上あれば、ナイル河と洪水1枚1点 | 洪水は捨て、ナイル河は残る |
| 文明 | 0種-5、3種+5、4種+10、5種+15（1〜2種は0） | 捨てる |
| モニュメント（最後だけ） | 種類の数で1〜6点（7種10点、8種15点）＋同じ種類3/4/5枚で5/10/15点 | 残る |
| 太陽駒（最後だけ） | 合計の一番大きい人+5、一番小さい人-5 | — |

- 点は0より下がらない
- 3つ目の時代のあとで終わり。同点なら、一番大きい太陽駒を持つ人が上

### 資料と、資料で分からない点の決め方

読み比べた資料：

- [A] alea 1999 年の原版のルール（オランダ語のファン訳の全文）：https://spellenlab.be/media/files/8d82b6aea0854e152f278351e0ecc4bc3f2ce9fc.pdf
- [B] Rio Grande 版の英語の公式ルールの全文（ルールブックの表記は © 2008）：https://github.com/Lehi-Innovation/boardgame-rules/blob/main/extracted/ra-rules.txt
- [C] 25th Century Games 版（2022年）のロシア語の公式訳（2023年）：https://media.lavkaigr.ru/uploads/ra_rules.pdf
- 有志の実装のデータ：chibimagic/ra-board-game（Ruby）、kandluis/raHelper
- 版の流れ：https://en.wikipedia.org/wiki/Ra_(board_game)

確かめたこと：タイル180枚の内訳、太陽駒の組、ラーのトラックの長さ、競りと災害の決まり、点の表、同点の決め方は、[A]・[B]・[C] と実装のデータで一致した（実装の1つは、点が0より下がらない決まりを入れていないが、[A]・[B]・[C] は下がらない）。

版の違い：

| 版 | 人数 | 違い |
|---|---|---|
| alea 1999（原版） | 3〜5人 | 2人の遊び方はない |
| Rio Grande 第3版（2009年発売、ルールブックは © 2008） | 2〜5人 | 2人の遊び方を追加：太陽駒は 9・6・5・2 ／ 8・7・4・3、ラーのトラックは最初の4マスを使わず、ラー6枚で時代の終わり。ほかは同じ |
| 25th Century Games（2022年） | 2〜5人 | タイルの枚数と点の表は同じ。モニュメントの要塞と宮殿が別の名前（霊廟と祠）に、内乱が「戦争」に変わった。ラーのタイルは並べずに捨て、太陽の舟の駒を進める |

この版は、2〜5人を遊べる Rio Grande 版に合わせた（モニュメントの名前は原版のまま）。依頼のときに挙がった「2009年の Fantasy Flight Games 版」「2023年の Grail Games 版」は、どの資料にも出てこなかった。

日本語の用語：日本語版の公式のルールは見つからなかった。ボドゲーマの解説（https://bodoge.hoobby.net/games/ra ）では「ラー宣言」「太陽駒」「神々」「ナイル河」「モニュメント」「第3時代」などの語が使われている。この版の名前（洪水・モニュメントの種類・災害の名前など）は自分で訳した。

自分で決めた点：

- 災害で捨てるタイルの選び方が結果に関わらないとき（同じ種類しかない、2枚以下、葬式、干ばつ）は自動で捨てる。選ぶ意味があるときだけ、捨てるタイルを選ぶ画面を出す
- 時代の点は、増減をまとめてから足す（0より下がるときは0にする）
- ほかの人の裏向きの太陽駒の数字は、画面に出さない（数だけ）。ただし、その太陽駒は中央から受け取った表の太陽駒なので、記録をたどれば分かる（実物と同じ）

### 画面の操作

- 自分の番は、下の「引く」「ラー」「神で取る」を押す。「神で取る」のあとは、光った競りのトラックのタイルを押して選び、「取る」
- 競りの番は、出せる自分の太陽駒が光る。押すと出す。「見送る」は、出さなくてよいときだけ出る
- 上の欄は、ほかの人の点・表の太陽駒（裏の太陽駒は「?」）・手元のタイル。競りでの答え（「出す 6」「見送り」）とラーの印も出る。押すと、その人の手元が大きく見られる
- 時代が終わると、得点の表が出る
- タイルを押すと、点の数え方が出る
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（公開の情報と自分の太陽駒）だけを見て決め、袋の並びやほかの人の裏の太陽駒はのぞかない。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

**ふつう**

- 競りの価値：競りのトラックのタイルを手元に足したときの点の増え方を、得点の表から差分で見積もる。神・金・ファラオの順位（ほかの人の枚数と比べる）・洪水とナイル河・文明の種類数・モニュメントの種類と組（残りの時代で組になる見込みも足す）。災害は、失って一番困らないタイルを捨てたとして、その分を引く
- 見送ったときに相手が得る点の一部と、受け取る中央の太陽駒と出す太陽駒の差も足す
- 出す：前より大きい太陽駒のうち一番小さいもの。価値が「太陽駒の大きさに応じた値段」を超えるときだけ出す。ラーのトラックが終わりに近いときと、太陽駒が多く残っているときは値段を下げる
- 手番：トラックの価値が高く、自分の一番大きい太陽駒がほかの人より大きいときにラー宣言する。神があり、値打ちの高いタイルがあれば神で取る。ほかは引く
- 災害で捨てるタイルは、点が一番下がらない組み合わせを選ぶ
- 値段やラー宣言の目安の数（`TUNING`）は、やさしい相手の勝率を `scripts/cpu-match.mjs` で比べて決めた

**やさしい**：価値の見積もりに大きな迷いを足し、出す太陽駒は当てずっぽう。トラックがある程度たまったらラー宣言する。神は、値打ちの高いタイルのときにときどき使う。

```bash
# 試合数・人数・席ごとの強さ（easy・normal）
node scripts/cpu-match.mjs 1000 2 easy,normal
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 平均の点 |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 1000 | 73.3% | 26.7% | ふつう 50・やさしい 36 |
| 2人（ふつう・ふつう） | 1000 | 48.2%・51.8% | — | 44 |
| 3人（やさしい・ふつう・やさしい） | 500 | 63.0% | 15.6%・21.4% | ふつう 50・やさしい 35〜38 |
| 4人（やさしいとふつうを交互） | 500 | 37.8%・43.6% | 10.4%・8.2% | ふつう 38〜40・やさしい 27 |
| 5人（やさしいとふつうを交互） | 300 | 33.0%・35.3% | 8.7%・12.3%・10.7% | ふつう 35〜37・やさしい 26〜27 |

どの組み合わせでも、止まった試合はない。

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜5人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'ra' })`。web-games の1つのスタックから `?game=ra` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

テスト（`test/`）：

- `game.test.js`：タイルの内訳、人数ごとの太陽駒とラーのトラック、引く（8枚のとき）、ラーを引いた競りの順、競り（大きい太陽駒だけ・太陽駒の入れ替え・次の手番）、自分でラー宣言した競りで出さなければならないこと（8枚のときの例外）、ラーを引いた競りで全員見送り、神、太陽駒のない人の休み、災害（葬式・干ばつ・地震で選ぶ）、時代の終わり（ラーのトラック・全員の太陽駒）、時代の点、0より下がらない、モニュメントと太陽駒の点、同点、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（2〜5人）、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、袋の並びとほかの人の裏の太陽駒を変えても同じ手を選ぶこと（のぞかない）、見積もり、ラー宣言する場面
- `game-definition.test.js`：オンライン対戦の定義と、ビューに袋の並び・ほかの人の裏の太陽駒・シードが入らないこと
- `game-controller.test.js`：CPU との対戦の進行、断られた操作の知らせ、保存からの再開
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン
