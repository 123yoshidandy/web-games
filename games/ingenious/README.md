# インジーニアス

6色の記号の列を伸ばし、いちばん低い色の点を競うタイル配置ゲーム「インジーニアス（Ingenious／Einfach Genial、Reiner Knizia、Kosmos 2004）」を、ブラウザで遊べるようにしたもの。2〜4人（あなた＋CPU）、4人のペア戦、1人用。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

記号・タイル・アイコンの絵は、すべて SVG で自作している（公式の画像は使っていない）。6色の記号は、色覚に配慮して形も変えている（赤：8つのとがりの星、緑：丸、青：六芒星、橙：六角、黄：太陽、紫：輪）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- タイル120枚（2つの六角がつながったもの。各六角に色の記号が1つ）を袋に入れ、各自6枚を手札にする
- 盤は、平らな辺を上にした小さな六角が縦の列に並ぶ大きな六角形。印刷された6色の記号がある。2人は内側（中心から距離5まで）、3人はその外の1列まで（距離6）、4人は全部（距離7）を使う
- 手番：手札の1枚を、空いたとなり合う2マスに置く。最初の手番は、まだとなりにタイルがない印刷の記号のとなりに置く。2回目からは範囲の中ならどこでもよい（ほかのタイルにつながっていなくてよい）
- 得点：置いた2つの記号それぞれから、もう一方の記号の向きを除く5方向に、まっすぐ同じ記号が続く数（印刷の記号も数える。空きか違う記号で止まる）を、その色の得点に足す。上限は18
- インジーニアス：ある色が18に届いたら、補充の前にすぐもう1枚置く（断れない）。2色同時なら2枚。続けて届けば、さらに置く
- 取り替え：補充の前に、得点がいちばん低い色（同じ点で並ぶ色はすべて）の記号が手札に1枚もなければ、手札を見せて全部取り替えてよい
- 手札を6枚に補充して、次の人へ
- 置ける2マスがなくなったら終わり。各自のいちばん低い色の点が高い人の勝ち。同じなら次に低い色で比べる（同じ点の色が2つあれば、低い方と次の方として数える）。6色とも18に届いたら、その場で勝ち
- **4人のペア戦**：向かいの2人（あなたとソウタ、ハルカとミオ）が得点を共有する。得点は36まで（得点板2枚分）。18と36に届いたら、置いた人がもう1枚置く
- **1人用**：手札は持たず、袋から1枚引いてすぐ置く。得点は36まで、もう1枚と取り替えはない。使うのは2人と同じ範囲。最後のいちばん低い色の点をできるだけ高くする

### 資料と、資料で分からない点の決め方

ルールは、2つの英語のルールブックを読んで合わせた。

- FFG／Sophisticated Games 版（2010年）
- Thames & Kosmos 版（2023年）

盤の形とタイルの内訳は、次で照らし合わせた。

- **盤の形**：2023年版の盤の絵で、マスの数と記号の位置を数えた。真ん中の縦の列が15マスで、中心から距離7までの169マス。記号は距離5の六角形の頂点にある（上：紫、右上：赤、右下：緑、下：青、左下：橙、左上：黄）。人数ごとの範囲は、どちらのルールブックも「2人は白、3人は白と薄い灰色、4人は全部」。Wikipedia の「外側の2つの輪が3人用と4人用」とも合う
- **タイルの内訳**：同じ色の組（赤赤など6種）が各5枚で30枚、違う色の組（15種）が各6枚で90枚。Wikipedia による。合わせて120枚で、ルールブックの枚数と合う。BGA の実装は、遊ぶには登録が要るため確かめていない

資料の食い違いと、どちらに合わせたか：

- **最初の手番**：2010年版は「最初の1巡は、それぞれ別の記号のとなりに置く」、2023年版は「最初の手番は、まだとなりにタイルがない記号のとなりに置く」。2023年版の書き方に合わせた（ほとんど同じ意味。ほかの人が別の記号のとなりに置いた結果、まだとなりにタイルのない記号がなくなることは、6つあるのでない）
- **取り替え**：2023年版だけが「1手番に1回だけ」と書いている。この版では取り替えたらすぐ補充して次の人へ進むので、1回だけになる
- **同点の比べ方**：2023年版の「同じ点の色が2つあれば、低い方と次の方として数える」の例に合わせ、6色を低い順に並べて低いほうから比べる
- **ペア戦**：2010年版は「もう1枚は、18と36に届いたとき」、2023年版も同じ。どちらも、置いた人がもう1枚置く
- **2人の決闘**（得点を綱引きで取り合う変種）は2023年版にだけあり、入れていない

自分で決めた点：

- 最初の人はシードから決める（ルールブックでは「いちばん若い人」）
- 取り替えは、袋に6枚以上あるときだけできる
- もう1枚置ける権利が残っていても、手札がなければそこで終える
- 手札がなくなった人（袋が空のとき）は飛ばす。全員の手札がなくなったら終わり（ふつうは、その前に盤が埋まる）
- ペア戦で、36の6色そろいはその場で勝ちにした（ルールブックはペア戦について書いていない）

### 画面の操作

- 手札のタイルを押して選ぶ（もう一度押すと上下が入れ替わる）。盤のマスを押すと、そこに上の記号、となりに下の記号の下書きが出る。となりのマスを押すか回転のボタンで向きを変え、「置く」で決める
- 最初の手番は、置けるマス（記号のとなり）が光る
- 盤のマスが小さく描かれるとき（3人と4人のスマホ）は、最初に押した辺りが大きく出る（1マス約44px）。小さく戻すボタンもある
- 下書きを出すと、得点の見込み（色ごとの点）が下に出る
- 取り替えられるときは「取り替え」「そのまま」のボタンが出る
- 上に、各人（ペア戦は組ごと）の6色の得点。いちばん低い色に下線、18に届いた色は金色、今の番の人は金色の枠。前の手番に置いたタイルは金色の縁
- 右上のボタンで記録と遊び方が見られる。操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（自分の手札・盤・全員の得点）だけを見て決め、ほかの人の手札や袋の並びはのぞかない（`chooseCommand(view, level, rand)`）。CPU の迷いにはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

**ふつう**

- 伸び：得点を低い順に並べ、低いものほど重く数えた値（重み 16・6・3・1.5・0.8・0.4）がどれだけ上がるかで手を比べる。いちばん低い色を伸ばす手ほどよい
- インジーニアス（もう1枚）に届く手は、さらに高く見る
- 相手の伸びを止める：見込みのよい24手について、置いたあとに相手が伸ばせる量（空いたマスにその色を置いたときの最大の点を、相手のいちばん低い色ほど重く数えたもの）がどれだけ減るかを、重み 0.3 で足す。重みは、止めない版との対戦で決めた（下の表）
- 取り替えられるときは、いつも取り替える

**やさしい**：半分は合計の点がいちばん多い手、半分はでたらめ。取り替えは半々。

```bash
# 試合数・人数・席ごとの強さ（easy・normal。grow はふさがない比べ用）・遊び方（standard・team・solo）
node scripts/cpu-match.mjs 400 2 easy,normal
```

勝率と、最終得点（いちばん低い色の点）の平均。ペア戦の得点は36まで。

| 対戦 | 試合数 | ふつうの勝率 | 相手の勝率 | 最終得点の平均（ふつう／相手） |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 400 | 99.8% | 0.3% | 7.5／1.2 |
| 2人（ふつう・やさしい） | 400 | 99.8% | 0.3% | 7.4／1.2 |
| 3人（やさしい・ふつう・やさしい） | 200 | 99.0% | 0.5%・0.5% | 8.3／1.7・1.9 |
| 4人（やさしい・ふつう・やさしい・ふつう） | 200 | 51.5%・48.0% | 0%・0.5% | 9.8・9.7／1.6・1.7 |
| 4人ペア戦（やさしい組・ふつう組） | 200 | 100% | 0% | 23.9／4.7 |
| 2人（ふさがない・ふつう） | 300 | 62.0% | 38.0% | 7.8／7.3 |
| 2人（ふつう・ふさがない） | 300 | 62.0% | 38.0% | 7.8／7.3 |
| 2人（ふつうどうし） | 400 | 45.8%・54.3% | — | 5.8・6.0 |
| 3人（ふつうどうし） | 200 | 32.5%・36.0%・31.5% | — | 7.2〜7.3 |
| 1人用 | 200 | — | — | ふつう 13.4、やさしい 5.0 |

相手の伸びを止める分を足すと、足さない版（伸ばすだけ）に62%勝つ。止める分の重みは 0.3（0.5 では約57%、1.0 では約51%だった）。どの組み合わせでも、止まった試合はない。

操作の欄の電球（ヒント）を押すと、ふつうの CPU が選ぶ手を示す（タイルと向き・置く2マスを選んでおき「置く」を光らせる。取り替えるかは、そのボタンを光らせる）。CPU と同じく、自分のビューだけで決める。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/colors.js` | 6色の記号とタイルの内訳 |
| `public/js/board.js` | 盤の形（マスの位置、6方向のとなり、印刷の記号、人数ごとの範囲） |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（ほかの人の手札と袋の並びを隠す） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦と1人用（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率・最終得点 |

テスト（`test/`）：

- `game.test.js`：盤（169マス、人数ごとの範囲、記号の位置）、タイルの内訳、最初の手番、置ける場所、得点（5方向・止まる・もう一方を数えない・印刷の記号）、上限18とインジーニアス（2色同時も）、その場で勝ち、取り替え（並んで低い色も）、終わりと比べ方（ルールブックの例）、1人用、ペア戦（18と36）、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（1人用・2〜4人・ペア戦）、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらずタイルが120枚のままで再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数・遊び方・強さ・シードを変えても止まらないこと、ふつうがやさしいとふさがない CPU に勝ち越すこと、いちばん低い色を伸ばす・18に届く手を選ぶ、取り替え
- `game-definition.test.js`：オンライン対戦の定義（ペア戦も）と、ビューでほかの人の手札・袋の並び・シードが漏れないこと
- `game-controller.test.js`：CPU との対戦で CPU が人の番で止まること、断った操作を伝えること、1人用
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン
- `offline.test.js`：service worker を差し替えた入れ物で動かし、ネットワークが切れてもページと JS をキャッシュから返すこと

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'ingenious' })`。web-games の1つのスタックから `?game=ingenious` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
