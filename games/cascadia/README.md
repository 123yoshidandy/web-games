# カスカディア

六角の地形タイルをつなげて自分の地を広げ、動物を住まわせるタイル配置ゲーム「カスカディア（Cascadia、Randy Flynn、Flatout Games／AEG 2021、2022 年ドイツ年間ゲーム大賞）」の基本ゲームを、ブラウザで遊べるようにしたもの。1〜4人（あなた＋CPU、1人用もある）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

地形・動物・アイコンの絵は、すべて SVG で自作している（公式の画像は使っていない）。地形は自然の淡い色に、色に頼らなくても見分けられる模様を重ねている（山：三角、森：木、草原：草、湿地：葦、川：波）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 部品：地形タイル85枚（山・森・草原・湿地・川。1地形のキーストーン25枚と2地形60枚。各タイルに、置ける動物の印が1〜3つ）、最初のタイル5組（3枚の三角形）、動物トークン100個（クマ・ヘラジカ・サケ・タカ・キツネ各20）、自然トークン
- 準備：山は人数×20＋3枚（2人43・3人63・4人83。1人は43）。各自、最初のタイルを1組持つ。場にタイルとトークンの組を4つ並べる
- 場のトークンが4つとも同じ動物なら、自動で4つとも流し直す（そろわなくなるまで）
- 手番
  1. 場のトークンが3つ同じ動物なら、その3つを1回だけ流し直してよい
  2. 自然トークンを1つ使うごとに、好きなトークンを好きな数だけ流し直してよい（何度でも）
  3. 組を1つ取る。自然トークンを1つ使えば、タイルとトークンを別々の組から取れる
  4. タイルを自分の地のとなりに、好きな向きで置く。トークンは、その動物の印があってまだトークンのないタイルに置く（取ったタイルでなくてよい）。置かずに袋に戻してもよい
  5. キーストーンに動物を置いたら、自然トークンを1つ得る
  6. 取った分を山と袋から補う。山が空で補えなければ終わり（各自20手番）
- 流したトークンは、新しいトークンを引いてから袋に戻す
- 得点
  - 動物：動物ごとに選んだ得点カード（A〜D）の点
  - 地形：地形ごとの、いちばん大きいつながりのタイル数。となり合うタイルの向かい合う辺の地形が同じなら、つながる
  - 最大のつながりのボーナス：2人は大きい方に2点（同じなら1点ずつ）。3〜4人は1番に3点・2番に1点。1番が2人なら2点ずつ、3人以上なら1点ずつで、2番はなし。2番が並んだら0点
  - 残った自然トークン1つにつき1点
- 同点なら、残った自然トークンが多い人の勝ち。それも同じなら勝ちを分ける
- **1人用**：2人と同じ43枚。手番のあと、補う前に、山からいちばん遠い（右端の）タイルとトークンを捨て（ゲームから除く）、残りを右へ寄せて左から2組補う。20手番。地形ごとに、いちばん大きいつながりが7以上なら2点のボーナス

### 得点カード

タイトル画面で「A（A をすべて）」「ランダム（動物ごとに A〜D をでたらめに）」「選ぶ（動物ごとに選ぶ）」から決める。ゲーム中は右上のカードのボタンで、効果と今の自分の点が見られる。

| 動物 | A | B | C | D |
|---|---|---|---|---|
| クマ | ちょうど2頭の群れの数：1→4・2→11・3→19・4以上→27 | ちょうど3頭の群れ1つにつき10 | 1〜3頭の群れ：2・5・8。3つの大きさのそろい1組につき＋3 | 2〜4頭の群れ：5・8・13 |
| ヘラジカ | まっすぐな列：2・5・9・13（4頭まで） | 形：1頭2・2頭5・三角9・ひし形13 | 群れの大きさ：2・4・7・10・14・18・23・28 | 1つのマスを囲む輪（欠けても、間が空いてもよい）：2・5・8・12・16・21 |
| サケ | 列：2・5・8・12・16・20・25（7以上） | 列：2・4・9・11・17（5以上） | 3〜5匹の列：10・12・15 | 3匹以上の列：サケの数＋となりのトークンの数 |
| タカ | となりにタカのいないタカの数：2・5・8・11・14・18・22・26 | となりにタカがいなくて視線が通るタカの数：0・5・9・12・16・20・24・28 | 視線1本につき3 | 視線の通る2羽の組の、あいだの動物の種類：1→4・2→7・3以上→9 |
| キツネ | となりの動物の種類の数（キツネも数える） | となりに2つ以上いる動物の種類：1→3・2→5・3→7 | となりのいちばん多い動物の数（キツネを除く） | となり合う2匹の組のまわりの、2つ以上いる動物の種類：1→5・2→7・3→9・4→11 |

ヘラジカ A・B・D、タカ D、キツネ D のように1頭を1つの形・組にしか数えないカードは、いちばん点が高くなる分け方で数える（ルールブックのとおり）。

### 資料と照らし合わせ

ルールは、英語の公式ルールブック（AEG／Flatout Games、[PDF](https://lot.ahml.info/Cascadia-Rules.pdf)。カードの点数は、11ページのカードの絵を画像にして読んだ）を基にし、次の資料と照らし合わせた。

- 作者 Randy Flynn の BoardGameGeek での回答：[rulespal.com の FAQ](https://rulespal.com/cascadia/faq) にまとめられたもの（BGG のスレッドそのものは読めなかった）
- ルールの要約：[officialgamerules.org](https://officialgamerules.org/game-rules/cascadia/)、[rulespal.com](https://rulespal.com/cascadia/rulebook)
- 有志の実装：[davidxmoody/cascadia-ai](https://github.com/davidxmoody/cascadia-ai)（Python）、[exp111/Cascadia](https://github.com/exp111/Cascadia)（JS）、[TMahls/Cascadia](https://github.com/TMahls/Cascadia)（MATLAB）、[phyrwork/cascadai](https://github.com/phyrwork/cascadai)（Python）、[lshrnd/SoPra-Cascadia](https://github.com/lshrnd/SoPra-Cascadia)（Kotlin）、[alexodavies/cascadia-photoreal](https://github.com/alexodavies/cascadia-photoreal)（JS）
- BGA（Board Game Arena）のヘルプのページは見つからず（404）、BGA の実装は確かめていない

**タイルの内訳**：davidxmoody・exp111・lshrnd・alexodavies の一覧を照らし合わせ、85枚が1枚の違いもなく一致した。各地形29枚（キーストーン5＋2地形24）、各動物の印32個、キーストーンは各動物5枚で、ルールブックの部品の数（タイル85・キーストーン25）とも合う。最初のタイル5組（上にキーストーン、左下に動物3種・右下に動物2種の2地形）も一致した。2地形のタイルの向きは、キーストーンに接する辺が1つ目の地形、下の2枚が接し合う辺が2つ目の地形（davidxmoody と lshrnd の辺の並びで一致。実物の写真とは照らし合わせていない）（`public/js/tiles.js`）。

**得点カード**：

- 20枚すべての点数を、ルールブック11ページのカードの絵を拡大して読み、有志の実装の点数表（TMahls は20枚、exp111 は17枚（ヘラジカは A だけ）、phyrwork はクマ・ヘラジカ・キツネ D、davidxmoody は A の5枚）と照らし合わせた。食い違いはなかった
- ルールブックの得点の例（クマのペア2組で11、ヘラジカの直線 5＋9、サケの4匹の列で12、タカ4羽で11、キツネ3匹で 3＋5＋3）とも合う

**ボーナス・1人用・同点・流し直し**：公式ルールブック・officialgamerules.org・rulespal.com の3つで一致した。人数ごとの枚数は、officialgamerules.org だけ「1人43・2人63・3人83・4人83」と1人分ずれて書いていたので、ルールブックと rulespal.com（2人43・3人63・4人83）に合わせた。

### 作者の回答とルールブックの文が食い違う点（作者の回答に合わせた）

作者の回答はカードの意図を説明したものなので、3つとも作者の回答に合わせた。

- **クマ C のボーナスの回数**：ルールブックは「3つの大きさがそろえば3点」。作者は「そろいが2組なら2回もらえる」と答えている（TMahls・exp111 の実装は1回まで）。**そろいの組の数だけ3点**にした
- **サケの列に、3匹以上のサケと接するサケがあるとき**：ルールブックの文面では、その群れは列にならない（0点）。作者は「そのサケだけを外し、残りを小さな列として数える。外したサケも、ほかの動物の得点には数える」と答えている（TMahls も同じ）。**3匹以上と接するサケを外し（外して新たにそうなったものも外す）、残りを列として数える**ようにした
- **流したトークンを袋に戻す時**：ルールブックは「過密をすべて解決してから戻す」。作者は「代わりを引いた直後に戻す（自然トークンで流したときも同じ）」と答えている。**代わりを引いた直後に戻す**ようにした（4つ同じが続けて起きたとき、戻したトークンをまた引くことがある）

### 作者の回答で決めた点

- **ヘラジカ D の輪**：1つのマス（中身は何でもよい）を囲む6マスのうちの何頭か。欠けた輪や、間が空いた輪でもよい
- **ヘラジカ A**：5頭の直線は「4頭＋1頭」、7頭は「4頭＋3頭」。**ヘラジカ B**：3頭の直線は三角に数えない
- **ヘラジカ C の8頭を超える群れ**：8頭ずつに分けて数える（10頭なら 28＋4）
- **サケ D は3匹以上の列だけ**（カードに印刷されている条件）。となりのトークンは、同じトークンを1回だけ数える
- **タカの視線**：辺の向きのまっすぐな線で、あいだにタカがいないもの。あいだのマスにタイルがなくても通る。**となりどうしは視線に数えない**。タカ B の相手のタカは、となりにタカがいてもよい。タカ D は、あいだに動物がいない組は0点
- **キツネ B・D**：同じ動物が3つ以上いても「組」は1種類。同じ2匹を、複数のキツネ（やキツネの組）で数えてよい

### 資料で分からない点の決め方

- **サケ C の6匹以上**は15点（カードの「5以上」の表のとおり）
- 最初の人はシードから決める（ルールブックは「ゲームの動物をいちばん最近見た人。でたらめに決めてもよい」）
- 4つ同じの自動の流し直しは、袋の中身によって終わらないことがあるので、30回で止める
- 1人用で捨てたトークンは、ゲームから除く（袋に戻さない）。1人用のずらす向きは、ルールブックの本文と例の絵のとおり「山から遠ざかる方」（rulespal.com だけ「山の方へ」と書いている）
- ファミリー・中級の遊び方、1人用のシナリオ、実績の表は入れていない

### 画面の操作

- 場の組のタイルを押して選ぶ。別の組のトークンを押すと、自然トークンを1つ使って別々に取る形になる
- 自分の地の光る空きマスを押すと、タイルの下書きが出る（最初は地形がいちばんそろう向き）。右下の回転のボタンか、下書きをもう一度押して回す
- 光る輪のタイルを押すと、トークンの置き場になる。「袋へ」で置かずに戻す。「決定」で決める。下に、この手で増える点の見込みが出る
- 自分の地は、1本指で動かし、2本指（PC はホイール）で拡大・縮小できる。右上のボタンで全体に戻る
- 上の名前を押すと、その人の地が見られる。点は、地の点＋自然トークン（最大のつながりのボーナスは終わりに足す）
- 「3つ流す」「自然トークンで流す」のボタンは、できるときだけ出る
- 右上のボタンで、得点カード・記録・遊び方が見られる。操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（全員の地・場・自分の自然トークン）だけを見て決め、山と袋の順はのぞかない（`chooseCommand(view, level, rand)`）。CPU の迷いにはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

**ふつう**：組ごとに、タイルの置き方（場所と向き）とトークンの置き方を見積もり、いちばん値の高い手を選ぶ。

- 動物：得点カードの点の増え＋「その動物をあと1つ置けたら増える点」の半分（残りの手番が6を切ると薄め、最後の手番は数えない）。トークンでふさいだ空きの印の分（ほかの動物の見込み）も差し引く
- 地形：各地形のいちばん大きいつながり＋2番目のつながりの 0.25 倍＋いちばん大きいつながりの空いた辺の 0.12 倍。ほかの人のつながりと比べた、最大のつながりのボーナスの見込みも足す
- キーストーンに置いて得る自然トークンは 1.6 点と見る。自然トークンで別々に取るのは、1.4 点を引いても得なときだけ
- 3つ同じの流し直しと、自然トークンでの流し直しは使わない

**やさしい**：場の組をでたらめに選び、半分は今の点の増えだけで置き場を選び、半分はでたらめに置く。

```bash
# 試合数・人数・席ごとの強さ（easy・normal）・得点カード（A・random・例 BCDAB）
node scripts/cpu-match.mjs 100 2 easy,normal
```

勝率と点の平均（最初の人は試合ごとに入れ替える）。

| 対戦 | 得点カード | 試合数 | ふつうの勝率 | 点の平均（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | A | 100 | 100% | 94.8／58.1 |
| 2人（やさしい・ふつう） | ランダム | 60 | 100% | 95.0／54.8 |
| 3人（やさしい2・ふつう） | A | 30 | 100% | 100.7／約60 |
| 4人（やさしい3・ふつう） | A | 30 | 100% | 99.1／約60.6 |

ランダム・3人・4人の行は、サケの列の数え方を作者の回答に合わせる前（3匹以上と接する群れを0点にしていたころ）に測ったもの。

1人用（30試合ずつ、カード A）：ふつう 平均 90.8点（ルールブックの目安で「Excellent!」の90点台）、やさしい 平均 60.0点（やさしいはサケの数え方を直す前に測ったもの）。

ふつうは、やさしいに負けたことがない。人どうしの目安（ルールブックの例の3人は 98・97・95）に近い点を取る。

## 開発

```bash
npm install
npm test                       # ルール・得点カード・記録からの再現・CPU どうしの試合・コントローラー・オンラインの定義・PWA・オフライン
python3 -m http.server 8000    # http://localhost:8000/ を開く（public/ へ移動する）
```

- 素の HTML・CSS・JavaScript（ES Modules）。ビルドはない。テストは Vitest
- `public/js/game.js`：ルールと進行（DOM に依存しない）。操作はすべて `applyCommand` を通し、記録（`commands`）とシードから `Game.replay` で同じ状態を作り直せる。断る操作は状態を変えない
- `public/js/scoring.js`・`habitat.js`・`score-tools.js`：得点の計算。`tiles.js`：部品のデータ。`hex.js`：六角の座標
- `public/js/game-view.js`：プレイヤーから見てよい情報（山と袋は数だけ）
- `public/js/cpu-player.js`：CPU。`game-controller.js`：ローカル対戦（CPU を間を置いて進め、途中経過を保存する）
- `public/js/ui.js`・`art.js`・`cards.js`：画面と絵と説明の文
- `server/src/game-definition.js`：オンライン対戦の部品 netplay-kit の「ゲームの定義」の形。`server/src/handler.js`（サーバーの入口）・`public/js/online-config.js`（接続先）・`public/js/netplay/`（netplay-kit の写し。手で直さない）は、下の「オンライン対戦」
- `public/sw.js`・`manifest.webmanifest`：PWA。自分のファイルはネットワークを先に、Google Fonts はキャッシュを先に使う

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'cascadia' })`。web-games の1つのスタックから `?game=cascadia` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
