# ギズモ

エネルギーを集めてギズモ（発明品）を建て、行動のたびに効果がつながる機械を組み立てるボードゲーム「ギズモ（Gizmos）」の基本ゲームを、ブラウザで遊べるようにしたもの。CPU を相手に 2〜4 人で遊べる（人間 1 人＋CPU 1〜3 人）。スマホの縦画面と PC に対応し、ホーム画面に追加するとオフラインでも遊べる（PWA）。

カードとエネルギーの絵、アイコンは自作。

## 遊ぶ

ビルドは要らない。リポジトリのルートで HTTP サーバーを立てて開く。

```bash
python3 -m http.server 8080
# http://localhost:8080/public/ を開く（ルートを開くと public/ へ移る）
```

## ルール

- 準備
  - エネルギーは 4 色（赤・黄・青・黒）13 個ずつ、計 52 個をディスペンサーに入れ、6 個を列に出す
  - ギズモは基本セットの 112 枚（最初のギズモ 4 枚、レベル 1〜3 が 36 枚ずつ）。レベル 3 は 20 枚を見ずに除き、16 枚で遊ぶ
  - 場にレベル 1 を 4 枚、レベル 2 を 3 枚、レベル 3 を 2 枚並べる
  - 各自、最初のギズモ（保管したら、エネルギーを 1 個引く）を建てた状態で始める。最初の手番の人はランダム
  - 上限は、エネルギー 5 個・保管庫 1 枚・研究 3 枚から始まり、強化のギズモで増える
- 手番：次のうち 1 つを行う
  1. 保管：場のギズモを 1 枚、保管庫に置く
  2. 取る：列のエネルギーを 1 個取る。列はディスペンサーから 1 個補充する
  3. 建てる：場か保管庫のギズモを、その色のエネルギーを費用の数だけ払って建てる。払ったエネルギーはディスペンサーに戻す
  4. 研究：山札を 1 つ選んで研究の数だけ引き、1 枚を建てるか保管してよい。残りは山札の下に戻す
- 連鎖：行動のあと、その行動に合うギズモ（保管したら・取ったら・建てたら）が働く。使うかどうかと順番は選べる。効果で行う行動（取る・保管・研究・建てる）も、さらにギズモを働かせる。各ギズモは 1 手番に 1 回だけ。建てたギズモ自身は、その建てた行動では働かない
- 変換のギズモ：建てるときに、エネルギー 1 個を好きな色として扱う、または同じ色 2 個として扱う。これも 1 手番に 1 回だけ
- 全色のギズモ（レベル 3 の 4 枚）は、どの色のエネルギーでも払える。建てたときの「この色を建てたら」の条件では、全色として数える
- 終わり：だれかが 16 枚（最初のギズモを含む）建てるか、レベル 3 を 4 枚建てたら、その巡の終わり（最初の手番の人の前）まで続けて終わる
- 得点：建てたギズモの点＋得点チップ。同点なら、建てた枚数が多い人、残りのエネルギーが多い人、最初の手番の人から遠い人の順に上

カードのデータは、Board Game Arena 版の実装と、実物のカードの写真からの書き起こしの 2 つを 1 枚ずつ照らし合わせ、一致したものを使っている（`public/js/cards.js` の冒頭）。終わりの条件（最初のギズモを含めて 16 枚）と同点の決め方も、Board Game Arena 版と同じにしてある。

## 資料で分からない点の決め方

ルールブックに書かれていない、または読み方が分かれる点は、次のように決めた（`public/js/game.js` の冒頭にも同じことを書いている）。

| 場面 | 決め方 |
|---|---|
| ディスペンサーが空 | 引けない。列も補充しない（空いた所のまま） |
| 山札がなくなった | 場の空いた所はそのまま |
| 得点チップの数 | 限りがないものとする |
| どの行動もできない | そのときだけ、何もせずに手番を終えられる（パス）。全員が続けてパスしたら、その時点で終わる |
| 研究で戻すカードの順番 | 引いた順のまま山札の下に入れる |
| 変換のギズモをどれだけ使うか | 払えるうちで一番少ない数を使う。払い方が何通りもあるときは、画面で選べる（払い方の横のボタン） |
| 引く効果を自動で使うか | 選ぶ余地のない効果（得点チップ、空きが十分あるときの「引く」）は自動で使う。空きが足りず、どれを先に使うかで結果が変わるときは、本人に選ばせる |

## 操作

- 場のギズモ・列のエネルギー・山札を押すと選ばれ、下の欄に「建てる」「保管」「取る」「研究」のボタンが出る。払い方が何通りもあるときは、払い方の横のボタンで切り替える
- 連鎖で働いたギズモは、下の欄に並ぶ。押して使う（取る・保管・研究・無料で建てる、は続けて相手を選ぶ）。「終える」で残りを使わずに手番を終える
- 上の欄は相手の点・建てた枚数・持っているエネルギーの数。押すと、その人の機械を見られる
- 自分の機械は、強化・変換・保管・取る・建てるの列に分けて並ぶ
- 途中で閉じても、タイトルの「続きから」で再開できる（操作の記録を保存して再現する）

## CPU

自分のビュー（山札の並びは見ない。研究で引いたカードは自分が引いたものだけ）で判断する。場と保管庫のギズモを「点と、これから働く見込み」で評価し、建てられる良いものがあれば建てる。なければ、ねらうギズモに足りない色を取るか、保管するか、研究する。判断の揺れには、ゲームの乱数とは別の乱数（シード・手数・席から作る）を使うので、記録の再現はずれない。

- やさしい・ふつう の 2 段階（画面で選ぶ）。`strong`（見落としと揺れのない比較用）は強さを測るときだけ使う
- 強さの測定：`npm run cpu-match -- <試合数> <人数> <席ごとの強さ>`（最初の手番は試合ごとに入れ替える）

2026-11-18 に測った勝率：

| 対戦 | 試合数 | 勝率 |
|---|---|---|
| やさしい 対 ふつう（2 人） | 200 | 29.0% 対 71.0% |
| ふつう 対 strong（2 人） | 200 | 42.5% 対 57.5% |
| やさしい・ふつう・やさしい・ふつう（4 人） | 100 | 8%・37%・8%・47% |

どの組み合わせでも全試合が最後まで進み（全員パスでの終わりは 0）、平均 23〜24 巡、勝者の点は平均 27〜29 点だった。

## 開発

```bash
npm install
npm test                                  # Vitest（ロジック・支払い・CPU・ビュー・記録の再現・ファズ・PWA）
npm run cpu-match -- 200 2 easy,normal    # CPU どうしの勝率
```

- ロジック（`game.js`）は DOM に依存しない。操作の入口は `applyCommand` の 1 つで、受け付けた操作を記録し、`Game.replay` で同じゲームを再現できる（山札の並びとディスペンサーの出方はシードから決まる）
- 画面を確かめるときは、`python3 -m http.server <port>` で配信し、スマホの縦の大きさ（375×548 など）で開く。`window.__app` から画面の状態に触れられる
- service worker（`public/sw.js`）が先に読むファイルの一覧は、JS を足したら書き足す（`test/pwa.test.js` が確かめる）

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'gizmos' })`。web-games の1つのスタックから `?game=gizmos` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
