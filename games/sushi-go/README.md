# スシゴー！

回ってくる手札から1枚ずつすしを取り、組み合わせで点を競うカードゲーム「スシゴー！（Sushi Go!、Phil Walker-Harding、Gamewright 2013）」の基本ゲーム（Party 版ではない）を、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

札の絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 108枚：天ぷら14・刺身14・餃子14・巻き寿司（●1つ6・●2つ12・●3つ8）・にぎり（玉子5・サーモン10・イカ5）・わさび6・プリン10・箸4
- 手札：2人10枚・3人9枚・4人8枚・5人7枚。3ラウンド
- 全員が同時に手札から1枚を選んで伏せ、そろったら表にして自分の前に置く。残りの手札は左（次の席）の人へ渡す。最後の1枚は、そのまま自分の前に置く
- わさびがあれば、次に取ったにぎりは必ずわさびに載せる（3倍）。わさび1枚に、にぎりは1枚まで
- 箸が前にあれば、あとの番に手札から2枚を取れる。使った箸は手札に戻り、次の人へ渡る。1回に使える箸は1つ
- ラウンドの終わりに得点を数え、プリン以外を捨てる。プリンはゲームの終わりまで残す

| 札 | 得点 |
|---|---|
| 天ぷら | 2枚で5点 |
| 刺身 | 3枚で10点 |
| 餃子 | 1・2・3・4・5枚以上で 1・3・6・10・15点 |
| 巻き寿司 | ●の数が最多で6点、2番目で3点 |
| にぎり | 玉子1・サーモン2・イカ3点（わさびの上で3倍） |
| わさび・箸 | 0点 |
| プリン | ゲームの終わりに、最多で6点、最少（0枚も含む）で−6点 |

- 巻き寿司：最多が同点なら6点を等分（端数は切り捨て）し、2番目の点はない。2番目が同点なら3点を等分
- プリン：同点は等分（端数は切り捨て）。全員が同じ数なら点なし。2人のときは、最少の減点はない
- 3ラウンドのあと、合計点の多い人の勝ち。同点ならプリンの多い人

### 資料と、資料で分からない点の決め方

ルールは、公式のルールブック（Gamewright の英語版 PDF）を読んで合わせた。札の内訳、手札の枚数、得点、同点の分け方は、ルールブックの例（巻き寿司 5・3・3・2 で 6・1・1・0、プリン 4・3・0・0 で +6・0・−3・−3）をそのままテストにした。

自分で決めた点：

- 巻き寿司が0の人は、2番目にもならない（全員が0なら、だれも点を取らない）。ルールブックは「最多」「2番目」としか書いていないため
- 箸で2枚を取るときは、選んだ順に置く（わさび → にぎりの順なら、そのにぎりはわさびに載る）
- その番に取った箸は、その番には使えない（ルールブックの「すでに前にあれば」から）
- 選んだ札は、全員がそろうまで変えられない
- 合計点もプリンも同じなら、同点の全員が勝ち
- ルールブックの変種（2人のときの「ダミー」の3人目、ラウンドごとに渡す向きを変える）は入れていない
- 手札の札では、にぎりの名前を「玉子・サーモン・イカ」と短く書く（小さい画面で名前が切れないため。右上の点の数字でにぎりと分かる）。記録と遊び方では「サーモンにぎり」などの名前のまま

### 画面の操作

- 手札の札を押して選び、「決める」。箸が前にあれば「箸で2枚」を押してから2枚を選ぶ（選んだ順に 1・2 の印）
- 上の欄は、ほかの人の得点・巻き寿司の数（●）・プリンの数（プ）と、前に置いた札。名前の横の印は、選び終えたら ✓、選んでいる途中は「…」。いちばん下の金色の欄は自分
- 前に置いた札の、緑の縁のにぎりはわさびに載ったもの。巻き寿司の赤い数字は●の数
- ラウンドの終わりに得点の表（巻・天・刺・餃・握と、各人の前の札）が開く。ゲームの終わりは、ラウンドごとの点とプリンと合計
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（自分の手札、全員の前の札とプリン）だけを見て決め、ほかの人の手札や選んだ札はのぞかない。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう：札ごとに「取ったら点がどれだけ増えそうか」を見積もり、一番よい札を取る
  - 天ぷら・刺身：そろえば確実な点。まだそろわないときは、残りの番の数と手札の同じ札から、そろう見込みで割り引く
  - 餃子は増える点、にぎりはわさびの有無で3倍、わさびは残りの番でにぎりを載せられる見込み
  - 巻き寿司：ラウンドの終わりの数を見積もり（ほかの人もこれから取る）、順位が上がる分を割り引いて見る
  - プリン：最後の順位が上がる分。ラウンドが進むほど重く見る
  - 箸：残りの番が多いほど高い。前に箸があれば、1枚目を置いたあとの場で2枚目を選び直し、十分に高ければ2枚取る
- やさしい：札ごとの決まった値に大きな迷いを足して選ぶ。箸はたまにしか使わない

```bash
# 試合数・人数・席ごとの強さ（easy・normal）
node scripts/cpu-match.mjs 1000 2 easy,normal
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 平均点（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 1000 | 97.4% | 2.6% | 56.7／38.1 |
| 3人（やさしい・ふつう・やさしい） | 1000 | 87.1% | 6.6%・6.3% | 45.8／32.6 |
| 4人（やさしい・ふつう・やさしい・ふつう） | 1000 | 42.9%・44.9% | 6.2%・6.0% | 36.5／27.4 |
| 5人（やさしい3・ふつう2） | 1000 | 43.0%・42.2% | 4.7%・4.6%・5.6% | 30.7／22.0 |
| 2人（ふつう・ふつう） | 1000 | 49.5%・50.5% | — | 49.4 |

同点で複数が勝った試合は、勝ちを等分して数えた。どの組み合わせでも、止まった試合はない。やさしいは、ルールを覚える相手としてかなり弱めにしてある。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/cards.js` | 札のデータ（枚数・色・手札の枚数） |
| `public/js/scoring.js` | 得点の計算（巻き寿司とプリンの同点の分け方を含む） |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（ほかの人の手札と、公開前の選んだ札を隠す） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率・平均点 |

テスト（`test/`）：

- `scoring.test.js`：札ごとの得点、巻き寿司とプリンの同点・0の扱い・2人のとき（ルールブックの例を含む）
- `game.test.js`：配る枚数、同時に選んで渡す、わさびとにぎり、箸（戻って渡る・その番に取った箸は使えない）、最後の1枚、ラウンドの終わり、プリンと勝ち（同点）、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず札が108枚のままで再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数（2〜5）・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、場面ごとの判断
- `game-definition.test.js`：オンライン対戦の定義と、ビューで手札・選んだ札・山・シードが漏れないこと
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜5人で、足りない席は CPU で埋められる。全員が同時に札を選ぶ。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'sushi-go' })`。web-games の1つのスタックから `?game=sushi-go` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
