# チェス

8×8 の盤で、相手のキングをチェックメイトする2人のボードゲーム。ブラウザで遊べる（スマホの縦持ち向け、PC でも遊べる）。

- CPU と対戦（やさしい・ふつう・つよい・とてもつよい）。白（先手）・黒（後手）を選べる
- 2人で1台を使って対戦
- 待った（1手戻す）、引き分けの提案、投了、盤の向きを変える、続きから
- 棋譜（代数式表記）、取った駒と駒得、直前の手・チェックの表示
- ホーム画面に追加すると、オフラインでも遊べる（PWA）

絵（盤・駒・アイコン）はすべて自作の SVG。駒は台座・胴・頭を単純な図形の組み合わせで描いた。

## 遊び方

### ルール

FIDE Laws of Chess に合わせた。

- 白が先手。交互に1手ずつ指す。チェックを外さない手・自分のキングを攻撃される升に置く手は指せない
- **キャスリング**：キングとそのルークが一度も動いておらず、間に駒がなく、キングがチェックされておらず、キングが通る升と着く升が攻撃されていないときだけできる。長い側（O-O-O）は b1・b8 が攻撃されていてもできる（キングが通らないため）。ルークが取られたときも、その側の権利は消える
- **アンパッサン**：相手のポーンが2マス進んで自分のポーンの真横に来た直後の1手だけ。取ると横の列が開いて自分のキングが攻撃される形（Position 3 の形）では取れない
- **プロモーション**：クイーン・ルーク・ビショップ・ナイトのどれかに必ず成る。画面では4つから選ぶ（選ばずに閉じたら、その手はやめる）
- **終わり**：チェックメイト（勝ち）・ステイルメイト（引き分け）・同じ局面が3回・50手・駒不足・引き分けの合意・投了
- 同じ局面は、手番・駒の配置・キャスリングの権利・アンパッサンの権利が同じもの（FIDE 9.2）。アンパッサンは、合法に取れるときだけ権利として数える
- 50手は、両者が50手ずつ（100手）ポーンを動かさず駒も取らなかったとき。100手目でメイトしたら、メイトが優先
- 駒不足：キング同士、キングと小駒1つ対キング、ビショップがすべて同じ色の升（両者合わせて）。これ以外は、メイトできる形が残るとして続ける

### FIDE のルールと違う点・決めた点

- **3回同一局面と 50手は自動で引き分け。** FIDE では、手番の人が申し立てたときに引き分けになる（5回・75手は自動）。画面では申し立ての操作を置かず、その局面になったら自動で引き分けにした
- **駒不足は、上の決まった形だけ。** FIDE の「どちらもメイトできない局面（デッドポジション）」は、ほかにもポーンが固まった形などがあるが、判定していない（その場合は 50手か3回同一局面で終わる）
- **引き分けの提案は、自分の番にだけ・1手につき1回。** FIDE では、自分の手を指してから時計を押すまでの間に提案する。画面では手番の人が提案し、相手が「受ける」「断る」を答えるまで待つ（断られたら、提案した人がそのまま指す）。CPU は、形勢が悪い（1.5 ポーン以上）か、30手を過ぎて互角なら受ける。やさしいは、少し有利でなければ受ける
- **投了は、手番に関係なくいつでもできる。**
- **待った。** 公式のルールにはない。ローカルの対戦だけで使える（オンライン対戦の定義には入れていない）。投了や終わったあとでも戻せる
- **時間切れでメイトできない相手は引き分け。** FIDE では「どう指してもメイトできない」なら引き分け。ここでは、相手の駒がキングだけか、キングと小駒1つのときだけを引き分けにする
- **時計は、操作を待っている人の分が減る。** 引き分けの提案中は答える人の時計が進む。フィッシャーの加算は指し手だけ（提案・答えには足さない）

### 持ち時間

タイトル画面（オンラインはロビー）で選ぶ。既定は「なし」。

| 選び方 | 中身 |
|---|---|
| 3分・5分・10分 | 切れ負け（使い切ったら負け） |
| 3分+2秒・5分+5秒 | フィッシャー（1手指すたびに2秒・5秒を足す） |

- 帯の右に残りの時間を出す。手番の時計は明るく、残り10秒で赤くして、知らせの音（notify）を1回鳴らす。10秒を切ったら 0.1 秒まで出す
- CPU は、残りの時間を30手で割った分と加算の7割を目安に考え、その時間で読みを打ち切る（時間切れにならない）。持ち時間が少ないと、手を見せる間も縮める
- CPU 戦では、アプリが隠れている間は時計を止める。2人で1台のときとオンラインでは止めない
- 記録の各操作に、かかった時間（ミリ秒）を残す。時間切れも記録の操作（`timeout`。端末からは送れない）なので、記録から時計と終わりを同じに再現できる。時間のない前の記録も、0秒として再現できる
- 「続きから」と待ったでは、その手番の時計は0から数え直す（それまでに使った時間は記録に残っている分だけ）
- オンラインでは、時刻はサーバーが決める。手番の始まった時刻（サーバーの時刻）を部屋に保存し、操作が届いた時刻との差をその手の時間にする。時間切れは、次の操作が届いたときと、期限（netplay-kit の `deadline`）で確かめる。Lambda はタイマーを持てないので、端末は手番の時計が0になったら ping を送る。端末は、サーバーの時刻に合わせて手元で時計を減らして見せる

### 操作

- 自分の駒を押すと、動ける升に点（取れる升は輪）が出る。点か輪を押すと動かす。別の自分の駒を押すと選び直す
- 動いた駒は元の升から滑って見える（CPU の手も同じ）。直前の手の2升に色を付け、チェックされたキングを赤く光らせる
- 上のバー：左がホーム。右は、盤の向きを変える・待った・引き分けの提案・投了・遊び方
- 盤の上が相手、下が自分の帯。名前・取った駒・駒得（ポーン1・ナイトとビショップ3・ルーク5・クイーン9で数えた差）を出し、操作を待っている側を金の枠で囲む
- 盤の下に棋譜（代数式表記）。左右にスクロールでき、最新の手が見えるようにする
- **待った**：CPU 戦では、あなたの直前の手と、そのあとの CPU の手をまとめて戻す。2人で対戦するときは1手ずつ戻す
- **続きから**：操作のたびに記録を保存する。タイトル画面の「続きから」で再開する。決着したら消す
- CPU 戦で黒を持つと、黒を下にして描く。2人で対戦するときは白が下（向きはボタンで変えられる）

## CPU

CPU は自分の席のビュー（開始の局面と指した手。チェスに隠す情報はない）だけを見て決める（`public/js/cpu-player.js`）。ゲームに乱数はなく、CPU の判断にも使わない。弱い CPU の迷いは、ビュー（局面の FEN）から作った別の乱数で足すので、同じ局面なら同じ手になる。

ブラウザでは Web Worker（`public/js/cpu-worker.js`）で読み、考えている間も画面が止まらない。Worker が使えないときは、その場で計算する。

読みは `public/js/engine.js`：

- ネガマックスのアルファベータ法（PVS）を、1手ずつ深くしながら繰り返す（反復深化）
- 末端は、駒を取る手とクイーンへの昇格だけを読み進めてから評価する（静止探索）
- 手の順番：前の読みの最善手（置換表）→ 取る手（価値の高い駒を、価値の低い駒で取る順）→ キラー → ヒストリー
- 置換表・ヌルムーブ（駒が少ないときはしない）・後ろの手を浅く読む（LMR）・チェックの延長
- 同じ局面の繰り返しと 50手・駒不足は、読みの中でも引き分け（0点）として扱う。対局のこれまでの局面も数える
- 評価：駒の価値、駒の位置の表（キングは中盤と終盤で別の表を使い、残りの駒で混ぜる）、ビショップ2つ、ポーンの形（二重・孤立・通ったポーン）、ルークの開いた列。駒が少ない終盤は、勝っている側が相手のキングを隅へ追う点を足す
- 読む量は局面の数で打ち切る。時間では打ち切らない（端末の速さで手が変わらないように。テストで再現できるように）。上限に届いた深さの読みは捨て、前の深さの答えを使う。時間（8秒）は、思わぬ重さで止まらないための安全弁だけ
- 置換表などは、読むたびに空にする（前に読んだ局面で答えが変わらないように）

| 強さ | 読み | 迷い |
|---|---|---|
| やさしい | 1手先と、その先の取り合いだけ | 点に 0〜2.2 ポーンの迷いを足す（駒をただで取られる手をときどき指す） |
| ふつう | 3手先まで（局面 2万まで） | 点に 0〜0.35 ポーンの迷いを足す |
| つよい | 局面 15万まで深く（中盤でおよそ7手先） | なし |
| とてもつよい | 局面 60万まで深く（中盤でおよそ9手先） | なし |

やさしい・ふつうは、根の手をすべて全幅で読んで正確な点を出し、迷いを足してから一番点の高い手を選ぶ。メイトが決まる手・決まってしまう手には迷いを足さない。

### 勝率

`node scripts/cpu-match.mjs <試合数> <強さA> <強さB>` で測った。同じ強さの CPU は同じ局面で同じ手を指すので、最初の4手（両者2手ずつ）をシード付きの乱数で指してから CPU に任せ、試合ごとに席（白・黒）を入れ替えた。

| 対戦 | 試合数 | 勝ち 対 負け | 引き分け | 終わり方 |
|---|---|---|---|---|
| ふつう 対 やさしい | 20 | 100% 対 0% | 0% | チェックメイト 20 |
| つよい 対 ふつう | 20 | 100% 対 0% | 0% | チェックメイト 20 |
| とてもつよい 対 つよい | 16 | 68.8% 対 6.3% | 25.0% | チェックメイト 12・駒不足 2・3回同一局面 2 |

どの組み合わせでも、止まった試合・400手で終わらなかった試合はない。とてもつよい 対 つよいは、席による偏り（白の勝ち 56.3%・黒 18.8%）が出た（16試合なので揺れは大きい）。

### 1手の時間

開発用の Mac（Apple M2 Pro、Node 22）で、読みは1秒に約 110万局面。スマホでは、この数倍（およそ3倍と見込む）かかる。

| 強さ | 平均 | 99% | 最長 |
|---|---|---|---|
| やさしい | 1ms | 5ms | 7ms |
| ふつう | 9〜14ms | 22ms | 26ms |
| つよい | 116ms | 147ms | 191ms |
| とてもつよい | 461ms | 588ms | 660ms |

とてもつよいの最長は約 0.66 秒で、スマホでは約2秒の見込み。

CPU は、前の手で駒が動くのが見えるように、0.45秒おいてから考え始める。

## 開発

素の HTML / CSS / JavaScript（ES Modules）。ビルドはない。

```bash
npm install
npm test                                         # Vitest
python3 -m http.server 8080 --directory public   # http://localhost:8080/
node scripts/cpu-match.mjs 20 strong normal      # CPU どうしの勝率と1手の時間
```

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で、足りない席は CPU（ふつう）で埋められる。席0が白、席1が黒で、自分の色を下にして描く。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントと待ったを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'chess' })`。web-games の1つのスタックから `?game=chess` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
