# バックギャモン

ダイスを振って15個の駒を自分のインナーボードへ運び、先にすべて盤の外へ出した人が勝ちのボードゲーム「バックギャモン（Backgammon）」を、ブラウザで CPU と遊べるようにしたもの。あなたと CPU の2人。スマホの縦持ち向け（横持ちでも遊べる）。ホーム画面に置くと、オフラインでも遊べる。

絵（盤・駒・ダイス・キューブ・アイコン）は、すべて SVG で自作している。

## 遊び方

- 盤は24のポイント。駒は15個ずつで、最初の並べ方は自分から見て 24 に2・13 に5・8 に3・6 に5。あなたは白で、24 から 1 へ進む（インナーボードは右下の 1〜6）
- 最初は1個ずつ振り、大きい目を出した人がその2つの目で動かす（同じ目は振り直し）
- ダイス2つの目の数だけ駒を進める。ゾロ目は4回。相手の駒が2個以上のポイントには止まれない
- 使える目はできるだけ多く使う。片方の目しか使えず、どちらでも使えるときは大きい目を使う。動かせなければ相手の番
- 相手の駒が1個（ブロット）のポイントに止まると、打ってバーへ送る。バーに駒があれば、先に相手のインナーボードへ入れる
- 15個すべてがインナーボードに入ったらベアオフできる。目より大きい数のポイントに駒がなければ、いちばん高いポイントの駒を出せる
- 勝ちの点：シングル1点、ギャモン2点（負けた側が1個もベアオフしていない）、バックギャモン3点（さらにバーか勝った側のインナーボードに駒がある）。キューブの値を掛ける
- ダブリングキューブ：ダイスを振る前にダブルを提案できる。受けると点が2倍になり、次にダブルできるのは受けた人。降りると今の点で負け
- マッチ：決めた点数を先に取った人の勝ち。どちらかが初めてマッチの1点前になった次のゲームはダブルできない（クロフォード・ルール）

### 決めたこと

- 設定は「CPU の強さ（やさしい・ふつう）」「マッチ（1・3・5・7点先取）」「キューブ（あり・なし）」。既定は「ふつう・3点先取・キューブあり」にした。ボードゲームアリーナの既定の値は、公開の資料で確かめられなかった
- 1点先取ではキューブに意味がないので、キューブは使わない（設定も選べなくする）
- ジャコビー・ルール、ビーバー、自動のダブル、投了（点数を決めて降りる）は入れていない
- 今のキューブで勝てばマッチに届く人には、ダブルのボタンを出さない（ダブルしても得にならないため）
- ダブルできないときは、ダイスを自動で振る。動かせる手がないときは、自動で相手の番になる

### 画面の操作

- 動かせる駒の上の輪が光る。駒を押すと、行き先のポイントが明るくなり、駒が着く位置に使う目の数が出る（「6+3」は、同じ駒で2つの目を続けて使う行き先）。バーの駒のように動かせる場所が1か所だけなら、最初から選んである
- 動かすたびに盤に反映し、使った目のダイスは薄くなる。「取り消し」でその番の動きを1つずつ戻し、目を使い切ったら「決定」で番を終える
- 相手の手は、駒が1個ずつ滑って見せる。打たれた駒はバーへ動く。相手の最後の手で着いた駒は、点線の輪で示す
- 各人の欄に、ピップ数（ベアオフまでに要る目の合計）とマッチの点を出す
- 遊び方を開いている間は、CPU が止まる。途中でホームに戻っても、「続きから」で再開できる（番の途中の動きは、その番の初めに戻る）

## CPU

動かしたあとの局面の値打ちで手を選ぶ（先読みはしない。強すぎないように）。

- 値打ち＝ピップ数の差＋作ったポイント（インナーボード・バーポイント・相手陣のアンカー。相手の駒がまだ後ろにいるときだけ数える）＋プライム − ブロットが相手の次の目（36通り）で打たれる見込み×打たれたときの損 − 積みすぎ − バーの駒。相手の駒がインナーボードに集まるほど、自分の後ろの駒を早く戻したいと見る
- すれ違ったあと（競走）は、ピップ数の差とベアオフの数だけで見る
- ダブル：値打ちから勝つ見込みを見積もり、ふつうは 68% 以上で提案し（勝ちすぎの見込みなら、ギャモンを狙って続ける）、25% 以上なら受ける。クロフォードのあとに負けている側は、すぐダブルする
- やさしい：打たれる見込みを軽く見て、評価の揺れが大きく、4回に1回は3番目までの手から選ぶ。ダブルの判断も粗い
- ゲームの乱数は使わない（記録から再現できる）。1手の考える時間は数ミリ秒

CPU 同士の結果（`scripts/cpu-match.mjs`。先手・後手を入れ替えて対戦）：

| 対戦 | 試合 | 結果 |
|---|---|---|
| ふつう 対 やさしい（1点勝負） | 400 | ふつう 294勝・やさしい 106勝 |
| ふつう 対 やさしい（3点先取・キューブあり） | 200 | ふつう 134勝・やさしい 66勝 |
| ふつう 対 やさしい（5点先取・キューブあり） | 200 | ふつう 132勝・やさしい 68勝 |
| ふつう 対 やさしい（7点先取・キューブなし） | 100 | ふつう 90勝・やさしい 10勝 |
| やさしい 対 でたらめ（1点勝負） | 200 | やさしい 199勝・でたらめ 1勝 |
| ふつう 対 ふつう（1点勝負） | 400 | 197勝・203勝 |

どの試合も最後まで進んだ（進まなくなった試合・長引いた試合はなかった）。ふつう同士の1点勝負の勝ちの種類は、シングル 66%・ギャモン 29%・バックギャモン 6%。

```bash
# 試合数・強さ（easy・normal・random）を2つ・何点先取・キューブ（on・off）
node scripts/cpu-match.mjs 200 normal,easy 1
node scripts/cpu-match.mjs 100 normal,easy 5 on
```

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/rules.js` | ルールの中身（盤・1歩の動かし方・通る手の一覧・番の途中で次に動かせる1歩・ベアオフ・勝ちの種類） |
| `public/js/game.js` | 進行と記録（ダイス・キューブ・マッチ・クロフォード）。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる。番の動きは `play`（歩の並び）でまとめて送る |
| `public/js/game-view.js` | 見る人ごとのビュー（隠す情報はない） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |

### オンライン対戦を入れるとき

ルールとビューは、netplay-kit の「ゲームの定義」の形（`server/src/game-definition.js`）で用意してある。CPU の強さ・何点先取か・キューブを部屋の設定に持つ。ダイスはシードから決まるので、記録の再現でも同じ目が出る。netplay-kit の `sync.mjs` で部屋の処理を写し、この定義を `createHandler` と `startDevServer` に渡す。画面は、ローカル対戦と同じ `getView()` / `send()` の形のオンライン用のコントローラーを足す。盤はビューの `seat` を下にして描くので、そのまま使える。ゲームの間（`between`）は、どちらの人が「次のゲーム」を送ってもよい。
