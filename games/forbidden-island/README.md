# 禁断の島

沈みゆく島から4つの宝を持ち帰る協力ボードゲーム「禁断の島（Forbidden Island）」を、ブラウザで遊べるようにしたもの。2〜4人の協力ゲームで、仲間を CPU に任せるか、1台で全員を操作する。オンラインでも遊べる。スマホの縦持ち向け。ホーム画面に追加すればオフラインでも遊べる。

絵・島の場所の名前・画面はすべて自作。

## 遊び方

- 全員が仲間。宝（大地の石・風の像・炎の水晶・海の聖杯）を4つ手に入れ、全員で「愚者の発着場」に集まって「ヘリで脱出」を使えば勝ち
- 手番の流れ：アクションを3回まで → 宝のカードを2枚引く → 水位の数だけ浸水のカードをめくる
  - アクション：移動（上下左右）・補強（自分の場所かとなりの浸水を戻す）・宝のカードを渡す（同じ場所の仲間へ）・宝を手に入れる（神殿で同じ宝のカードを4枚捨てる）
  - 水位上昇のカードを引くと、水位が上がり、浸水のカードの捨て札を切って山の上に戻す（同じ場所がまためくられやすくなる）
  - 浸水した場所がもう一度めくられると沈む。そこにいた駒は、となりへ泳いで逃げる
- 手札は5枚まで。特別なカード（ヘリで脱出・土のう）は、誰の手番でもいつでも使える（アクションを使わない）
- 負け：発着場が沈む・まだ手に入れていない宝の神殿が2つとも沈む・泳いで逃げる先がない・水位が頂点（10）に達する
- 役割（6種から人数分をランダムに配る）

| 役割 | 特技 |
|---|---|
| パイロット | 手番に1回、1アクションで島のどこへでも飛べる |
| 技師 | 1アクションで2か所を補強できる |
| 探検家 | 斜めにも移動・補強できる（泳ぐときも斜めへ） |
| ダイバー | 浸水や沈んだ場所を続けて抜けて移動できる（泳ぐときはいちばん近い場所へ） |
| 航海士 | 1アクションで、ほかの人を2マスまで動かせる |
| 伝令 | 島のどこにいる仲間にも、宝のカードを渡せる |

- 難易度は始まりの水位：見習い 1・標準 2・熟練 3・伝説 4
- 画面：島の光っている場所を押すと移動。下のボタンで補強・渡す・獲得・特技・終える。手札の「ヘリ」「土のう」を押すと使える。電球のボタンはおすすめの手（ヒント）、矢印は待った（1手戻す）

### 決めたこと（原作のルールで書かれていない点や、画面のために決めた点）

- 「宝のカードを引く」「浸水のカードをめくる」は、手番の人が押して進める（特別なカードを使う間を作るため）。画面では少し待って自動で押す
- 航海士がほかの駒を動かすときは、上下左右に2マスまで（動かされる人の役割の移動は使わない）
- 泳いで逃げる先が1つだけなら、その場で動かす。2つ以上なら、その人が選ぶ（手番の人から順に）
- 泳いで逃げる途中は、特別なカードを使えない
- 初めの手札で水位上昇を引いたら、配り直さずに山へ戻して切り直す（原作どおり）

## CPU

`public/js/cpu-player.js`。仲間の CPU は、自分の残りのアクションをビーム探索（幅40）で並べて試し、評価が一番高い並びの先頭を打つ。

- 評価：手に入れた宝、浸水した場所の危険（発着場・最後の神殿ほど重く、次にめくられそうなほど重い）、宝のカードの集まり具合（1人に集めるほど高い）、4枚そろった人と神殿の距離、特別なカード、宝が4つそろったあとの発着場までの距離など
- めくられる見込みは、見てよい情報だけで出す：浸水のカードの捨て札、水位上昇で山の上に戻した束（どの場所が入っているかは公開されている）、山の枚数、宝のカードの捨て札。山の並びはのぞかない
- 特別なカード：脱出できれば脱出する。大事な場所が浸水していれば土のうを使う。宝が4つそろえば、ヘリで仲間を発着場へ運ぶ
- ゲームの乱数は使わない。同じ状態なら同じ手を打つので、CPU の試合も記録から再現できる
- 強さは1つ。難易度は始まりの水位で変わる

測った結果（`npm run cpu-match`、CPU だけの試合）：

| 難易度 | 2人 | 3人 | 4人 |
|---|---|---|---|
| 見習い（各100試合） | 56% | 74% | 67% |
| 標準（各100試合） | 33% | 55% | 49% |
| 熟練（各20試合） | 10% | 15% | 40% |
| 伝説（各20試合） | 0% | 20% | 5% |

負け方は、終盤に島が小さくなって発着場が沈むものがいちばん多い。2人は手札の枠（5枚×2人）が小さく、宝のカードを捨てやすいので、いちばん難しい。

発着場の近くに駒を残す評価や、土のうを発着場と最後の神殿だけに取っておく方針も試したが、2人戦の勝率は上がらなかった（誤差の範囲）ので入れていない。

## 開発

```bash
python3 -m http.server 8000 --directory public   # http://localhost:8000/ を開く
npm test                                          # Vitest（ルール・記録からの再現・ヒント・CPU・オンライン・PWA）
npm run cpu-match                                 # node scripts/cpu-match.mjs [試合数] [人数 2・3・4・all] [難易度 novice・normal・elite・legendary・all] [最初のシード]
```

| ファイル | 内容 |
|---|---|
| `public/js/game.js` | ルールと状態（DOM に依存しない）。操作は `applyCommand(seat, command)` に通し、`Game.replay` で記録から作り直せる |
| `public/js/data.js` | 島の場所・宝・役割・カード・水位 |
| `public/js/game-view.js` | ビュー（山は枚数だけ。協力ゲームなので手札は全員に見せる） |
| `public/js/cpu-player.js` | CPU とヒント |
| `public/js/game-controller.js` | ローカルのコントローラー（CPU の進行・待った・途中経過の保存） |
| `public/js/ui.js`・`board.js`・`help.js` | 画面・島の描画・遊び方 |
| `public/js/sound/bgm.js` | BGM（engine.js・effects.js は packages/sound の写し） |
| `server/src/game-definition.js` | オンライン対戦のゲームの定義 |
| `scripts/cpu-match.mjs` | CPU だけの試合で勝率を測る |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人の協力で、足りない席は CPU で埋める。対戦中に部屋を出た人の席は CPU が引き継ぐ（記録からの再現のあとも CPU のまま）。オンラインではヒントと待ったはない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online` を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）。ロビーで難易度を選べる
- 接続先は `public/js/online-config.js`
- 部屋には参加者・シード・操作の記録だけを保存し、`Game.replay` で作り直す。ビューにシードや乱数は入れない
- 特別なカードは誰の手番でも使えるので、操作を待っている人以外からも受け付ける（使えるかは Game が判定する）
- 勝てば全員の画面で勝ちの音、負ければ負けの音が鳴る
