# バーグルブロス

泥棒の仲間でビルに忍び込み、見張りをかわして金庫を開け、屋上から逃げる協力ボードゲーム「バーグルブロス（Burgle Bros）」を、ブラウザで遊べるようにしたもの。1〜4人の協力ゲームで、仲間を CPU に任せるか、1台で全員を操作する。オンラインでも遊べる。スマホの縦持ち向け。ホーム画面に追加すればオフラインでも遊べる。

絵・部屋や道具の名前・曲・画面はすべて自作。

## 遊び方

- 全員が仲間。各階の金庫を開け、全員が最上階の階段から屋上へ逃げれば勝ち。隠密の印（1人3つ）を使い切った人がもう一度見つかったら、全員の負け
- 建物は 1〜3階建て（階が多いほど難しい）。各階は 4×4 の裏向きの部屋で、壁で区切られている。入るかのぞくとめくれる
- 手番はアクション4つ：移動・のぞく・金庫にダイスを足す（2）・金庫のダイスを振る・ハック・階段・得意
- 金庫：金庫と同じ行と列の6部屋の数字を出してから、ダイスを振る。出た目の数字の部屋に印が付き、6部屋そろうと開く。開けた人はお宝と道具を手に入れ、その階の見張りが速くなる
- 見張り：手番の終わりに、手番の人がいる階の見張りが速さの数だけ動く。警報があれば近い警報へ、なければ巡回の山の行き先へ。山が尽きると切り直して速くなる。見張りと同じ部屋になると見つかる
- 部屋（17種）：指紋認証・レーザー・動体センサー・熱センサー（警報）、暗証番号の扉・かんぬき扉（入りにくい）、監視カメラ・ロビー・吹き抜け（見つかりやすい）、端末（ハック）、研究室（道具）、洗面所（隠れ札）、隠し扉・通気ダクト・吊り通路・階段・金庫
- 泥棒（6人から人数分を配る）：金庫破り（1個多く振る）・ハッカー（警報を鳴らさない）・ホーク（壁ごしにのぞく、最初ののぞきがただ）・軽業師（見張りの部屋に入っても平気）・仕掛け屋（となりの警報を鳴らして見張りをおびき寄せる）・見張り役（巡回の山の上を見て下へ回す）
- 道具（8種）：設計図・ローラースケート・透明スーツ・煙幕・バール・聴診器・ウイルス・ダイナマイト
- 画面：盤の光る部屋を押すと移動。上の「1F・2F・3F」で見る階を切り替える。点線の部屋は、この手番の終わりに見張りが必ず通る部屋。◎は見張りの行き先。電球のボタンはおすすめの手（ヒント）

### 決めたこと（原作から変えた点・画面のために決めた点）

- 建物の階数（1〜3階建て）を難しさにした。1階建ては、1階の階段がそのまま屋上への出口
- 壁の配置は毎回ランダム（どの部屋も出口が2つ以上あり、行き止まりを作らない）。各階 6 枚
- 金庫を開けたときに速くなるのは、その階の見張りだけにした。警報があっても見張りの速さは変えない（警報は行き先を変えるだけ）
- イベントのカード、お宝の不利な効果、一部の泥棒と道具は入れていない（数が多く、短い手番で遊ぶスマホ向けに絞った）。お宝は飾り
- 泥棒の得意は、短く使えるように簡単にした（ハッカーは警報を鳴らさない、ホークは壁ごしにのぞけて最初ののぞきがただ、など）
- レーザーの部屋は、アクションが残っていれば自動で1つ余分に使って避ける（残っていなければハック、それもなければ警報）
- 道具は手番の人だけが、自分の手番に使える
- 待ったはない（めくった部屋やダイスの目を見たあとに戻すと有利になるため）

## CPU

`public/js/cpu-player.js`。ビュー（めくった部屋・見張りの場所と行き先・巡回の捨て札）だけを見て手を選ぶ。めくっていない部屋や山の並びはのぞかない。

- 手番の残りのアクションでできる並び（移動・のぞく・ダイス・金庫・ハック・階段）をすべて試し、「進み具合 − 手番の終わりの部屋で見つかる確率 × 重み − 目標までの道のり」がいちばん大きい並びの、最初の1手を打つ。1手ごとに選び直すので、のぞいて分かったことはすぐ反映する
- 見つかる確率：見張りの次の動き（自分の手番の終わりと、自分の次の手番までに同じ階の仲間の手番で動くぶん）を、巡回の捨て札からわかる残りのカードで枝分かれさせて出す（`rules.js` の `guardRisk`）。計画の中で警報を鳴らすなら、その警報へ向かう見張りで計算し直す
- 階の仕事：金庫を探す → 行と列の部屋をのぞいて数字を出す → ダイスを3〜4個足して振る → 階段を探して上へ。金庫を仲間に任せられる人は、先に上の階へ上がって階を分ける（各階の見張りが動く回数が減る）
- 隠密が少ないほど慎重になる。逆に、長引くほど急ぐ（安全を取り続けて進まないのを防ぐ）
- ゲームの乱数は使わない。同じ状態なら同じ手を打つので、CPU の試合も記録から再現できる
- 強さは1つ。難しさは建物の階数で変わる

測った結果（`npm run cpu-match`、CPU だけの試合、各100試合）：

| 建物 | 1人 | 2人 | 3人 | 4人 |
|---|---|---|---|---|
| 1階建て | 98% | 88% | 59% | 34% |
| 2階建て | 84% | 41% | 7% | 1% |
| 3階建て | 45% | 5% | 0% | 0% |

進まなくなった試合は 0（1200試合）。

人数が多いほど勝ちにくい。見張りは同じ階の泥棒の手番ごとに動くので、同じ階に4人いると、自分の次の手番までに見張りが4回動く（原作どおりのルール）。

## 開発

```bash
python3 -m http.server 8000 --directory public   # http://localhost:8000/ を開く
npm test                                          # Vitest（ルール・記録からの再現・ヒント・CPU・オンライン・PWA）
npm run cpu-match                                 # node scripts/cpu-match.mjs [試合数] [人数 1・2・3・4・all] [階数 1・2・3・all] [最初のシード]
```

| ファイル | 内容 |
|---|---|
| `public/js/game.js` | ルールと状態（DOM に依存しない）。操作は `applyCommand(seat, command)` に通し、`Game.replay` で記録から作り直せる |
| `public/js/rules.js` | 盤の判定（動ける先・のぞける先・見張りの道と先読み）。Game とビューのどちらにも使える |
| `public/js/data.js` | 部屋・泥棒・道具・お宝・階数 |
| `public/js/game-view.js` | ビュー（めくっていない部屋は中身なし、山は枚数だけ。協力ゲームなので道具は全員に見せる） |
| `public/js/cpu-player.js` | CPU とヒント |
| `public/js/game-controller.js` | ローカルのコントローラー（CPU の進行・途中経過の保存） |
| `public/js/ui.js`・`board.js`・`help.js` | 画面・盤の描画・遊び方 |
| `public/js/sound/bgm.js` | BGM「真夜中の忍び足」（engine.js・effects.js は packages/sound の写し） |
| `server/src/game-definition.js` | オンライン対戦のゲームの定義 |
| `scripts/cpu-match.mjs` | CPU だけの試合で勝率を測る |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人の協力で、足りない席は CPU で埋める。ロビーで建物の階数を選べる。対戦中に部屋を出た人の席は CPU が引き継ぐ（記録からの再現のあとも CPU のまま）。オンラインではヒントはない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online` を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`（`DEPLOYED_SERVER_URL` はデプロイ後に書く。空のあいだは公開したページで「オンラインで遊ぶ」を出さない）
- 部屋には参加者・シード・操作の記録だけを保存し、`Game.replay` で作り直す。ビューにシードや乱数、めくっていない部屋、山の並びは入れない
- 勝てば全員の画面で勝ちの音、負ければ負けの音が鳴る
