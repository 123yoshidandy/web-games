# スターレルム

宇宙を舞台にしたデッキ構築カードゲーム「スターレルム（Star Realms、Robert Dougherty・Darwin Kastle、White Wizard Games 2014）」の基本セット（2人用）を、ブラウザで CPU と遊べるようにしたもの。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

カードの絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。公式の日本語版が見つからなかったので、カード名は自分で訳した（下の表）。効果の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本セット）

- 各自、スカウト8枚（交易+1）とバイパー2枚（戦闘+1）のデッキと、権威50で始める。相手の権威を0以下にした人の勝ち
- 交易デッキ80枚（4勢力20枚ずつ）を混ぜ、5枚を表にして交易の列に並べる。エクスプローラー（費用2・交易+2・廃棄で戦闘+2）10枚は、いつでも獲得できる
- 先手は手札3枚、後手は5枚で始める（どちらが先手かは無作為）
- 手番：手札を出して効果を使い、交易で交易の列やエクスプローラーを獲得し（捨て札へ）、戦闘で相手の基地や権威を攻撃する。順番は自由
- 手番の終わりに、出した艦と残りの手札を捨て札にして5枚引く。山札がなくなったら、捨て札を混ぜて山札にする
- **同盟**：同じ勢力のカードがほかに場（この手番に出した艦か、自分の基地）にあれば、同盟の効果も使える。カードごとに1手番1回
- **廃棄**：場のカードをゲームから取り除いて、廃棄の効果を使う。廃棄したエクスプローラーは山に戻る
- **基地**：場に残り、毎手番の始めに効果を使う。耐久以上の戦闘で壊され、持ち主の捨て札に行く。**前哨**がある間は、相手はほかの基地も権威も攻撃できない（前哨を全部壊してから）

### 資料と、資料で分からない点の決め方

カードの枚数・費用・効果・耐久・前哨かどうかは、オープンソースの3つの実装（tonywok/realms・icesphere/star-realms-simulator・josschne/starrealms）が完全に一致したものを使った。細かい扱いは、公式の FAQ（https://www.starrealms.com/faq/）と、rulespal の要約・FAQ に合わせた。

- 艦隊司令部は、公式の訂正のあとの文「このあと出す艦すべてに戦闘+1」。艦隊司令部より前に出した艦には付かない
- ブロブの星は、この手番に出したブロブのカード（基地と、ブロブの星そのものを含む）を数える。ブロブの艦を写したステルスニードルも数える
- ステルスニードルは、写した艦の効果を全部（同盟・廃棄も）得て、その勢力にもなる
- メックの星は、同盟の判定ですべての勢力として数える
- 大使館ヨットの「基地が2つ以上」は、この手番に出した基地も数える
- リサイクルステーションは、先に0〜2枚を捨ててから、同じ枚数を引く
- 前の手番から残っている基地も、同盟の相手に数える

自分で決めた点：

- **相手に捨てさせる効果**は、相手の次の手番の始めに、基地の効果より先に、相手が選んで捨てる（デジタル版と同じ扱い）。手札より多くは捨てない。重ねて受けたら、その数だけ捨てる
- **同盟の効果**は、条件を満たした時点で自動で使う。本来は任意だが、使って損になる効果がないため。選ぶ形の効果（基地の破壊・交易の列の廃棄など）は「選ばない」もできる。貨物船・中央局の「次に獲得する艦を山札の上に置く」も自動で、そのあと最初に獲得した艦に付く
- **基地の効果**は、手番の始めに自動で使う。「どちらか」を選ぶ基地は、選ぶ画面を出す
- **権威への攻撃**は、その時点の戦闘を全部使う（分けて使う意味がないため）。基地への攻撃は、耐久の分だけ戦闘を使う
- 交易の列から獲得したら、その場所にすぐ交易デッキから補充する（列の場所は保つ）。交易デッキが尽きたら、列は減っていく
- ブロブ空母の同盟（ただで獲得）は、交易の列の艦だけ選べる（基地は選べない）。獲得したら山札の上へ
- 権威が0以下になった時点で、手番の途中でも勝敗が決まる。権威の上限はない
- 山札と捨て札の両方が尽きたら、それ以上は引かない
- 拡張（Colony Wars など）、ガンビット、3人以上の遊び方は入れていない

### 画面の操作

- 上の欄は相手（名前・権威・手札・山札・捨て札の枚数）、その下は相手の基地と、相手の手番に出した艦。中ほどが交易の列（いちばん右はエクスプローラーの山）、その下が自分の基地とこの手番に出した艦、金色の欄が自分（権威・山札・捨て札と、この手番の交易と戦闘）、いちばん下が手札
- 手札は押すと出る。「全部出す」で残りを順に出す（選ぶ効果が出たら、そこで止まる）
- 交易の列は、交易が足りるもの（金色に光る）を押すと獲得する
- 戦闘があれば、「攻撃」で相手の権威を攻撃する。相手の基地は、壊せるもの（金色に光る）を押すと攻撃する
- 廃棄できるカード（赤い点線）は、押して「廃棄して使う」
- どのカードも長押しで説明が見られる。捨て札の枚数を押すと、捨て札の中身が見られる
- カードの面：左上が費用、右上の盾が耐久（塗りつぶしは前哨）。下の段が効果で、金の丸が交易、赤が戦闘、緑が権威、青が引く枚数、1文字は特別な効果（長押しで文が見られる）。勢力の印の段が同盟、ごみ箱の段が廃棄の効果
- 効果で選ぶものはダイアログで出る。外側を押して閉じると盤面が見られ、「選ぶ」で開き直せる
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（自分の手札、全員の場・捨て札・権威、交易の列）だけを見て決め、相手の手札や山札の並び・交易デッキの並びはのぞかない。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう
  - 手札は全部出す。廃棄の効果のあるカードは後に出す（スカウトから交易を得てから廃棄するため）
  - 獲得：カードの値（費用に、引く効果・前哨・廃棄の効果・持っている同じ勢力の数を上乗せ）が一番高いものから、交易が続く限り獲得する
  - 攻撃：とどめを刺せるなら権威へ。前哨は先に壊す。ほかの基地は、耐久4以上で壊せれば壊し、残りで権威を攻撃する
  - 選ぶもの：権威が少なければ権威を、交易が足りそうなら交易を選ぶ。廃棄はスカウトとバイパーを捨て札から先に。エクスプローラーの廃棄は、とどめのときと後半に使う
- やさしい：手札を順に全部出し、獲得できるものからでたらめに獲得し、前哨から攻撃する。廃棄の効果は使わない

```bash
# 試合数と、席0・席1の強さ（easy・normal）
node scripts/cpu-match.mjs 200 normal,easy
```

| 対戦 | 試合数 | 勝率 | 平均の手番 |
|---|---|---|---|
| ふつう（席0）対 やさしい | 200 | ふつう 100% | 23.9 |
| やさしい（席0）対 ふつう | 200 | ふつう 100% | 23.5 |
| ふつう 対 ふつう | 400 | 席0 51.7%・席1 48.3%（先手 55.3%） | 26.7 |
| やさしい 対 やさしい | 200 | 席0 42.0%・席1 58.0%（先手 57.5%） | 32.0 |

どの組み合わせでも、止まった試合はない。やさしいは、ルールを覚える相手としてかなり弱めにしてある。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/cards.js` | カードのデータ（勢力・費用・枚数・種類・耐久・効果） |
| `public/js/card-text.js` | 効果の文と、カードの面の印 |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（相手の手札、山札と交易デッキの並び、シードを隠す） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率 |

テスト（`test/`）：

- `game.test.js`：準備（枚数・権威・手札）、出す・獲得・エクスプローラー、手番の終わり、同盟（前の手番からの基地・1手番1回・メックの星）、基地と前哨の攻撃、勝ち、選ぶ効果（どちらか・捨てさせる・廃棄・交易の列・基地の破壊・ステルスニードル・艦隊司令部・ブロブの星・リサイクルステーション・機械基地・頭脳の星・大使館ヨット・貨物船・ブロブ空母）、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（途中からも）、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず再現できること、CPU どうしの試合が強さとシードを変えても止まらないこと、交易カードの大半が実際に獲得されること
- `game-definition.test.js`：オンライン対戦の定義と、ビューで手札・山札と交易デッキの並び・シードが漏れないこと
- `pwa.test.js`・`offline.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン、ネットワークが切れてもキャッシュから開けること

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で、相手がいなければ CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'star-realms' })`。web-games の1つのスタックから `?game=star-realms` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
