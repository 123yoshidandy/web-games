# ハーツ

ハートとスペードのクイーンを取らないようにするトランプのゲーム「ハーツ（Hearts）」を、ブラウザで CPU 3人と遊べるようにしたもの。スマホの縦持ち向け（横にすると2列に組み替える）。ホーム画面に置くと、オフラインでも遊べる。

トランプの絵（スートの記号を含む）とアイコンは、すべて SVG で自作している。

## 遊び方

- 4人。52枚を13枚ずつ配る
- 配ったら3枚を選んで渡す。ラウンドごとに、左 → 右 → 向かい → 渡さない、をくり返す
- クラブの2を持つ人が、それを出して始める。時計回りに1枚ずつ出す
- 最初に出されたスートを持っていれば、それを出す（マスト・フォロー）。なければ何を出してもよい
- 最初のスートの一番高い札（A が最強）を出した人が4枚を取り、次を始める
- 最初のトリックでは、クラブがなくても、ハートとスペードのクイーンは出せない
- ハートが一度出されるまで（ハートが割れるまで）、ハートで始められない
- 取ったハートは1枚1点、スペードのクイーンは13点の失点
- ハート13枚とスペードのクイーンを1人で全部取ったら（シュート・ザ・ムーン）、その人は0点、ほかの全員が26点
- だれかの失点の合計が100点に達したら終わり。失点が一番少ない人の勝ち

### ボードゲームアリーナの既定の選択肢に合わせたこと

- 渡し方：左 → 右 → 向かい → 渡さない
- ダイヤのジャック（−10点）：使わない（既定で無効）
- 失点の札の制限：最初のトリックでは出せず、ハートが割れるまでハートで始められない
- シュート・ザ・ムーン：本人は0点、ほかの全員に26点（「本人から26点を引く」形ではない）
- 点の数え方：ボードゲームアリーナは「100点から失点を引き、だれかが0点になったら終わり、多い人の勝ち」と数える。このアプリは同じことを「失点を足し、だれかが100点に達したら終わり、少ない人の勝ち」と数える

### ルールに書かれていないので決めたこと

- 最初のトリックで、手札が失点の札だけなら、それを出してよい（出せる札がなくならないように）
- 手札がハートだけなら、割れる前でもハートで始めてよい
- スペードのクイーンでは、ハートは割れない
- 失点が一番少ない人が複数いたら、その全員を勝ちとする

### 画面

- 手札の13枚は2段に並べる。札を押して選び、もう一度押すか「出す」で出す。出せない札は暗くし、押すと理由を出す
- 渡すときは3枚を押して選び、「渡す」で渡す。もらった札には青い印を付ける
- 場のトリックは、出した人の向きに置く。4枚がそろったら取る札を光らせ、取った人へ集める
- 各席に、失点の合計と、このラウンドで取ったハートの数・クイーンを出す
- 途中でホームに戻っても、「続きから」で再開できる

## CPU

自分から見える情報だけ（ほかの人の手札や、ほかの人が選んだ渡す札は見ない）で選ぶ。

- 渡す：守りの薄いスペードのクイーンと A・K、高いハート、短いスートの高い札（早く切らすため）
- 始める：クイーンを持っていなければ、低いスペードでクイーンをあぶり出す。それ以外は一番低い札
- ついていけるとき：今の勝ち札より下の一番高い札で逃げる。逃げられないときは、最後で失点がなければ一番高い札、それ以外は一番低い札
- ついていけないとき：クイーン → スペードの A・K → 高いハート → 高い札、の順に捨てる
- シュート・ザ・ムーンは狙わず、防ぎもしない

| 強さ | 中身 |
|---|---|
| やさしい | 半分くらいでたらめに出し、渡す札の選び方も大まか |
| ふつう | 上の決め方に、ときどきの誤り（1割）を混ぜる |

CPU 同士の対戦（各 1000 試合。渡す先の有利・不利が出ないよう、席を回して数える）：

| 対戦 | 勝率 | 公平なら |
|---|---|---|
| ふつう1 対 やさしい3 | ふつう 59.6% | 25% |
| 比較用の誤りのない CPU 1 対 ふつう3 | 比較用 32.5% | 25% |
| やさしい1 対 でたらめ3 | やさしい 85.5% | 25% |

```bash
# 試合数・4人の強さ（easy・normal・strong は誤りのない比較用・random はでたらめ）
node scripts/cpu-match.mjs 1000 normal,easy,easy,easy
```

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/game.js` | ルール。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる。イベントには、その時点の全員に見せてよい状態を付ける |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー（ほかの人の手札と渡す札は伏せる） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js` | 画面。届いたイベントを順に再生して見せる |
| `public/js/art.js`・`animator.js` | 絵と動き |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'hearts' })`。web-games の1つのスタックから `?game=hearts` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
