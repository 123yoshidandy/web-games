# キャリコ

パッチを縫い付けて自分のキルトを仕上げ、猫とボタンを集めるタイル配置ゲーム「キャリコ（Calico、Kevin Russ、Flatout Games／AEG 2020）」の基本ゲームを、ブラウザで遊べるようにしたもの。1〜4人（あなた＋CPU、1人用もある）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

パッチ・猫・ボタン・アイコンの絵は、すべて SVG で自作している（公式の画像は使っていない）。パッチは6色の上に白い模様を重ね、模様は色に頼らなくても形で見分けられる（しま：斜めの線、シダ：葉、水玉：点、花：5枚の花びら、四つ葉：結び目、つる：渦）。猫は10匹とも、毛の色と柄を変えた丸い顔。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 部品：パッチ108枚（6色×6模様×3枚）、キルトの盤4枚（7×7の六角。外周24マスは縁のパッチが印刷済みで、盤ごとに違う。内側の25マスのうち3マスが目標タイルの置き場、残り22マスにパッチを置く）、目標タイル6種、猫10匹（両面の札5枚）、ボタン（6色と虹）
- 準備：パッチを袋に入れ、各自2枚を手札に、3枚を市場に出す
- 猫：3匹を選び、6つの模様をでたらめに2つずつ割り当てる（猫の好きな模様）
- 手番
  1. 手札の2枚から1枚を、自分のキルトの空きマスに置く（となりにパッチがなくてよい）
  2. ボタンか猫の条件を満たしたら、その場で取る
  3. 市場の3枚から1枚を手札に取り、袋から補う
- 全員のキルトが埋まったら終わり（各自22手番）
- 得点
  - **ボタン**：同じ色が3枚以上つながると、そのまとまりにボタン1つ（3点）。まとまりを広げても、ボタンのあるまとまりにつなげても増えない。同じ色の2つ目は、前のまとまりに接しない別のまとまりで。6色のボタンがそろうと**虹のボタン**（3点）
  - **猫**：猫の好きな模様（2つのうちどちらか1つ）のまとまりが、猫ごとの枚数か形になると、そのまとまりに猫が来る（猫の点）。まとまりが条件より大きくてもよい。1つのまとまりに猫は1匹だけで、同じ猫の2匹目は、前のまとまりに接しない別のまとまりで
  - **目標タイル**：まわりの6枚の色か模様の数の並びが合えば低い点（青）、色と模様の両方で合えば高い点（金）だけ（足さない）
  - 縁に印刷されたパッチ（欠けたものも）も、ボタンと猫のまとまりに数える
- 同点なら、猫が多い人の勝ち。それも同じなら、ボタンが多い人の勝ち。それも同じなら勝ちを分ける
- **1人用**：市場から取ったあと、袋からいちばん遠い（右端の）残りのパッチを捨て、残りを右へ寄せて、袋の側（左）から補う

### 目標タイル

| タイル | 合う並び | 色か模様 | 両方 |
|---|---|---|---|
| ≠ | 6つすべて違う | 10 | 15 |
| AAAA-BB | 4つと2つ | 7 | 14 |
| AAA-BBB | 3つと3つ | 7 | 13 |
| AAA-BB-C | 3つ・2つ・1つ | 7 | 11 |
| AA-BB-CC | 2つ・2つ・2つ | 7 | 11 |
| AA-BB-C-D | 2つ・2つ・1つ・1つ | 5 | 7 |

点は、タイルに印刷された値（下の「食い違う点」を参照）。

### 猫

札の・の数（難しさ）ごとに、ふつうの準備で1匹ずつ選ぶ。札は両面で、表裏は同じ点の2匹。

| ・ | 猫 | 点 | 条件 |
|---|---|---|---|
| 1 | ミリー／キャリー | 3 | 3枚以上つながる／三角の3枚 |
| 1 | ティビット／ルミ | 5 | 4枚以上つながる／3枚がまっすぐ |
| 2 | ココナッツ／テコロテ | 7 | 5枚以上つながる／4枚がまっすぐ |
| 2 | シーラ／アーモンド | 9 | 6枚以上つながる／3枚の列の上に2枚（台形の5枚） |
| 3 | グウェン／レオ | 11 | 7枚以上つながる／5枚がまっすぐ |

形の条件は、どの向きに回してもよい。まっすぐは、六角の3本の軸のどれでもよい。

### 資料と照らし合わせ

ルールは、英語の公式ルールブックの2つの版を基にした。

- 2020年版：[lot.ahml.info の PDF](https://lot.ahml.info/Calico.pdf)。文字を取り出せる版
- AEG の2025年版：[alderac.com の PDF](https://www.alderac.com/wp-content/uploads/2025/04/Calico_BaseGame_Rulebook_Optimized.pdf)。ページが画像の版

2つの版の違いは、得点例の AAA-BBB の点だけだった。次の資料と照らし合わせた。

- 作者の BoardGameGeek での回答：[rulespal.com の FAQ](https://rulespal.com/calico/faq) にまとめられたもの（BGG のスレッドそのものは読めなかった）
- 有志の実装
  - [JanSakowski/Calico-board-game](https://github.com/JanSakowski/Calico-board-game)（Java）
  - [Dancis-S/Calico-Boardgame](https://github.com/Dancis-S/Calico-Boardgame)（Python）
- ルールの要約：[officialgamerules.org](https://officialgamerules.org/game-rules/calico/)、[Happy Piranha](https://happypiranha.com/blogs/board-game-rules/how-to-play-calico-board-game-rules-instructions)
- BGA（Board Game Arena）のルールのページは見つからなかった（404）

**猫**

- 10匹の点・条件・・の数を、ルールブック9ページの絵と、JanSakowski の `Cat.java` と照らし合わせた。食い違いはなかった
- 形の猫も同じだった。キャリーは三角の3枚、アーモンドは「真ん中の1枚と、そのとなりの4つ続き」（＝3枚の列の上に2枚）。JanSakowski の `Board.java` も同じ形

**準備**

- ルールブック5ページで確かめた
  - 猫：・の数ごとに札を1枚、表裏もでたらめ
  - 目標タイル：6枚から4枚を引いて3枚を選ぶ
  - はじめての準備：≠・AA-BB-CC・AAA-BBB の置き場と、ミリー・ティビット・ココナッツ

**1人用**：ルールブック（2020年版）8ページで確かめた。市場から取ったあと、袋からいちばん遠い1枚を捨て、残りをずらして補う

**猫とボタンのまとまり**：1つのまとまりに来る猫は1匹だけ。同じ猫の2匹目は、接していない別のまとまりで来る（作者の回答 [BGG](https://boardgamegeek.com/thread/2339290/article/33684631)）。接していれば同じまとまりになるので、判定は「置いたパッチのまとまりに、もう猫がいるか」で見ている

**盤の形と縁**

- 目標の置き場は、行と列で (2,3)・(3,4)・(4,2)。ルールブック4ページの写真と Dancis-S で一致した
- 縁のパッチ（24マス×4枚）は、Dancis-S のデータを使った
  - 青と紫の盤は、ルールブック4ページの写真と24マスすべて一致した
  - **緑と黄の盤は、写真がなく確かめられていない**
  - どの盤も、6色が4回ずつ出る。模様は1つが5回・1つが3回で、そろっていない（青と紫は写真どおり）

### 食い違う点の決め方

- **目標タイルの点**
  - 2020年版のルールブックの表は AAA-BBB 8/13、AAAA-BB 8/14、AA-BB-C-D 5/8（JanSakowski も同じ）
  - 作者は「タイルに印刷された値が正しく、ルールブックの 8 は直し漏れで 7」と答えている（rulespal.com）
  - Dancis-S の実装は 7/13・7/14・5/7。2025年版のルールブックも、得点例が AAA-BBB 7点に直っている
  - **作者の回答と Dancis-S に合わせて、7/13・7/14・5/7 にした**。両方の点（13・14・7）は、タイルの印刷を読んで確かめたわけではない
- **同点**：ルールブック（両方の版）は「猫が多い人、次にボタンが多い人、それでも同じなら分ける」。BGG にあるユーザー作の早見表は「ボタンが多い人」と書いていて、officialgamerules.org・Happy Piranha の順番も食い違っている。**ルールブックに合わせた**

### 資料で分からない点の決め方

- **虹のボタン**：1人1つにした。ルールブックは「6色そろえば取ってよい」とだけ書く。部品は4個（4人分）で、Dancis-S は何度も取れる作り
- **同点のボタンの数**：虹のボタンも数に入れる
- **最後の手番**：22枚目を置いた手番でも、市場から1枚取る。資料に書いておらず、取ったパッチは使わないので結果は変わらない
- **ボタンと猫**：同じパッチを使ってよい。色と模様は別々に見る。禁止する決まりは資料にない
- **形の猫のまとまり**：形の外に同じ模様が付いていてもよい（rulespal.com。公式には確かめられていない）
- **最初の人**：シードから決める。ルールブックは「いちばん最近、猫をなでた人」
- **入れていないもの**：2人用の任意の遊び方（色と模様の組み合わせごとに1枚、36枚を抜く）。ファミリーの遊び方（目標タイルを伏せ、点にしない）。1人用のシナリオ。いずれもルールブックでは任意の遊び方

### 準備（タイトル画面で選ぶ）

- **はじめて**：猫はミリー・ティビット・ココナッツ。目標タイルは全員 ≠・AA-BB-CC・AAA-BBB（ルールブックのはじめての準備）
- **ふつう**：猫は難しさ（札の・の数 1・2・3）ごとに1匹ずつでたらめに。目標タイルは各自に4枚が配られ、3枚を選んで置く（全員が同時に選び、選び終わるまでほかの人の目標は見えない）

### 画面の操作

- 手札のパッチを押して選び、キルトの空きマスを押すと下書きが出る。もう一度押すか、右下の決定のボタンで縫い付ける。下書きで来るボタンと猫が、下に出る
- 縫い付けたら、光る市場のパッチを押して手札に取る
- 上の名前を押すと、その人のキルトが見られる。名前の下は、今の点（目標はまわりが埋まって合ったものだけ）・猫・ボタン（虹を含む）の数
- 猫の欄を押すと、猫の条件と好きな模様、ボタンの決まりが見られる
- 右上のボタンで、記録と遊び方が見られる。操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（全員のキルト・ボタン・猫・市場・猫の好きな模様と、自分の手札）だけを見て決め、袋の順とほかの人の手札はのぞかない（`chooseCommand(view, level, rand)`）。CPU の迷いにはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

**ふつう**：キルトの値（今の点＋見込み）がいちばん上がる手を選ぶ。

- 今の点：ボタン・虹のボタン・猫
- ボタンの見込み：まだボタンのない3枚未満の色のまとまりで、まわりに空きがあるもの。枚数が多いほど高く、終盤ほど薄める
- 猫の見込み：まだ猫のいない、猫の好きな模様のまとまりで、条件の枚数に届く空きがあるもの
- 目標の見込み：色と模様のそれぞれで、まだ合わせられるなら、埋まった割合から見込みを出す
- 置く：置いたあとの値に、手札に残す1枚の次の手番の伸びを足す。取る：市場の3枚それぞれについて、手札の1枚と合わせた2枚の「どちらを先に置くか」まで見て比べる
- 目標タイルは、点と合わせやすさを掛けた値の高い3枚を選ぶ

**やさしい**：半分はすぐ取れるボタンと猫だけを見て置き、半分はでたらめに置く。市場からはでたらめに取る。

```bash
# 試合数・人数・席ごとの強さ（easy・normal）・準備（standard・beginner）
node scripts/cpu-match.mjs 100 2 easy,normal
```

勝率と点の平均（最初の人は試合ごとに入れ替える）。

| 対戦 | 準備 | 試合数 | ふつうの勝率 | 点の平均（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | ふつう | 100 | 100% | 56.6／21.8 |
| 2人（やさしい・ふつう） | はじめて | 60 | 100% | 57.9／23.7 |
| 3人（やさしい2・ふつう） | ふつう | 30 | 100% | 56.1／約21 |
| 4人（やさしい3・ふつう） | ふつう | 30 | 100% | 57.6／約21 |

1人用（30試合ずつ、ふつうの準備）：ふつう 平均 56.8点、やさしい 平均 21.4点。

ふつうは、やさしいに負けたことがない。ふつうは点の取りやすいボタンを多く集め、点の高い形の猫（アーモンド・レオ）はほとんど取らない。

## 開発

```bash
npm install
npm test                       # ルール・得点・記録からの再現・ランダムな操作・CPU どうしの試合・コントローラー・オンラインの定義・PWA・オフライン
python3 -m http.server 8000    # http://localhost:8000/ を開く（public/ へ移動する）
node scripts/cpu-match.mjs 100 2 easy,normal   # CPU どうしの勝率
```

- 素の HTML・CSS・JavaScript（ES Modules）。ビルドはない。テストは Vitest
- `public/js/game.js`：ルールと進行（DOM に依存しない）。操作はすべて `applyCommand` を通し、記録（`commands`）とシードから `Game.replay` で同じ状態を作り直せる。断る操作は状態を変えない
- `public/js/scoring.js`：まとまり・ボタン・猫・目標タイルの判定と点。`data.js`：部品のデータ（パッチ・盤の縁・目標・猫）。`board.js`：盤の形と六角の座標
- `public/js/game-view.js`：プレイヤーから見てよい情報（ほかの人の手札と袋は枚数だけ。目標を選ぶ間は、ほかの人の目標を入れない。シードは入れない）
- `public/js/cpu-player.js`：CPU。`game-controller.js`：ローカル対戦（CPU を間を置いて進め、途中経過を保存する）
- `public/js/ui.js`・`art.js`：画面と絵
- `server/src/game-definition.js`：オンライン対戦の部品 netplay-kit の「ゲームの定義」の形（2〜4人）。今はオンライン対戦を入れていない。入れるときは、netplay-kit の `sync.mjs` で部屋の処理を写し、この定義を渡す。ビュー（`sanitize`）で袋の順と手札を隠す
- `scripts/cpu-match.mjs`：CPU どうしを多数回対戦させ、勝率と点の平均を出す（`node scripts/cpu-match.mjs 試合数 人数 席ごとの強さ 準備`）
- `public/sw.js`・`manifest.webmanifest`：PWA。自分のファイルはネットワークを先に、Google Fonts はキャッシュを先に使う
