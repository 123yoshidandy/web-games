# コリドール

壁で相手の道をふさぎながら、向かいの辺を目指すボードゲーム「コリドール（Quoridor）」を、ブラウザで CPU と遊べるようにしたもの。2人（あなたと CPU）か4人（あなたと CPU 3人）。スマホの縦持ち向け。ホーム画面に置くと、オフラインでも遊べる。

絵（盤・駒・壁・アイコン）は、すべて SVG で自作している。

## 遊び方

- 盤は 9×9。2人は下と上の辺の中央から、4人は4辺の中央から始める。壁は2人なら10枚、4人なら5枚ずつ
- 最初の手番はランダム。4人は 下→左→上→右（時計回り）の順
- 手番には、駒を1マス動かすか、壁を1枚置く
- 駒：上下左右に1マス。壁は越えられない
  - 隣の駒と向かい合ったら、飛び越せる
  - 飛び越す先が壁・盤の端・別の駒なら、隣の駒の左右（斜め）へ進める（斜めの先に壁や駒があれば、その向きへは進めない）
  - 4人でも、2つ以上の駒を続けて飛び越せない
- 壁：2マス分の長さで、マスの間の溝に置く
  - ほかの壁と重ねられない。十字に交差させられない
  - だれかのゴールへの道を完全にふさぐ壁は置けない（駒は道をふさがないものとして調べる）
- 向かいの辺のどこかのマスに着いた人の勝ち（4人でも、最初に着いた人の勝ちで終わる）

ルールは、ボードゲームアリーナの遊び方のページと、公式のルールで確かめた。

### 決めたこと

- 飛び越す先に別の駒がいるとき（4人）は、壁や盤の端と同じに扱い、斜めへ進めるようにした（「2つ以上は飛び越せない」の扱いを、資料で確かめきれなかった）
- 動かす手も置ける壁もないときは、パスする（公式のルールには書かれていない。4人で囲まれたときだけ起きうる）
- 同じ局面の繰り返しによる引き分けはない（公式のルールにない）。CPU は前に出た局面へ戻る手を避ける

### 画面の操作

- 自分の番には、駒の動ける先のマスに点が出る。押すとそこへ動く
- 盤のほかの場所か「壁」を押すと、壁を置いたときの姿が出る。指でずらすと位置が、同じ場所をもう一度押すか向きのボタンで向きが変わる。「置く」で置き、「×」でやめる
  - 置けない場所は赤く出し、理由（重なる・交差する・〇〇のゴールへの道がふさがる・壁が残っていない）を出す
  - 置けるときは、誰のゴールまでの歩数がいくつからいくつに変わるかを出す
  - 「壁」で最初に出る位置は、次の手番の相手の歩数が延び、自分の歩数は延びない場所
- 各人の欄に、残りの壁とゴールまでの最短の歩数（あと◯歩）を出す。ゴールの辺は、盤の外側に同じ色の帯で示す
- 盤は、自分の辺が下に来るように描く（オンライン対戦で、どの席でも同じ見え方になるように）
- 最後の手は、駒なら元のマスを点線の輪で、壁なら置いた人の色の縁で示す
- 遊び方を開いている間は、CPU が止まる。途中でホームに戻っても、「続きから」で再開できる

## CPU

局面の値打ちは「相手（4人では一番ゴールに近い相手）の最短の歩数 − 自分の最短の歩数 ＋ 残りの壁の差 × 壁の値打ち」。候補の手は、駒の動ける先と、相手の最短の道を切る壁だけにしている。

- やさしい：自分の1手だけを読む。壁を高く値踏みして（使い惜しむ）、評価の揺れが大きく、ときどき3番目までの手を選ぶ
- ふつう：次の手番の人の応手まで2手を読む（応手は、その人にとって一番良い手とみなす）
- どちらも、すぐ勝てる手は見逃さない。1手の考える時間は 0.8 秒で打ち切る（実際は 50ms 以内）

CPU 同士の結果（`scripts/cpu-match.mjs`。席を回して対戦）：

| 対戦 | 試合 | 結果 |
|---|---|---|
| ふつう 対 やさしい（2人） | 200 | ふつう 187勝・やさしい 13勝 |
| ふつう 対 ふつう（2人） | 200 | 86勝・114勝（最初の手番の人の勝ち 103） |
| ふつう2・やさしい2（4人） | 100 | ふつう 96勝・やさしい 4勝 |
| やさしい 対 でたらめ（2人） | 20 | やさしい 20勝 |

どの対戦でも、終わらない試合・進まなくなった試合はなかった。1手の考える時間は最長 45ms。

```bash
# 試合数・強さ（easy・normal・random）を2つ（2人）か4つ（4人）
node scripts/cpu-match.mjs 100 normal,easy
node scripts/cpu-match.mjs 40 normal,easy,easy,easy
```
上の帯の電球（ヒント）を押すと、ふつうの CPU が揺れなしで選ぶ手を示す（駒なら行き先のマスを光らせ、壁なら置く画面にその壁を出しておく）。上の帯の一覧のボタンで、最近の手の履歴を見られる。

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人か4人で、足りない席は CPU で埋められる。CPU の強さを部屋の設定に持つ。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'quoridor' })`。web-games の1つのスタックから `?game=quoridor` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/rules.js` | ルールの中身（駒の動ける先・壁の判定・最短の道・手を当てる）。CPU の先読みでも使う |
| `public/js/game.js` | 進行と記録。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる |
| `public/js/game-view.js` | 見る人ごとのビュー（手番の人には駒の動ける先を付ける） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |
| `server/src/handler.js`・`public/js/online-config.js`・`public/js/netplay/` | オンライン対戦のサーバーの入口・接続先・netplay-kit の写し |
