# テント

木のとなりにテントを張り、行と列の数字に合わせる論理パズル（Tents・Tents and Trees）。問題はその場で作り、どの問題も答えが1つに決まる。

## 遊び方

- 木のとなり（上下左右）にテントを張る。木とテントは1つずつ組になり、どの木にも、となりに自分のテントが1つある
- テントどうしは、ななめも含めて、となり合わない。盤面の外の数字は、その行・列にあるテントの数
- マスを押すと、テント → 芝生（テントを置かない印）→ 空、の順に変わる。なぞると芝生をまとめて付けられる
- 大きさ：やさしい 6×6・ふつう 9×9・むずかしい 12×12。やさしいは基本の理屈だけで解ける。ふつうは1マス置いてみて矛盾を見る手が要ることがある
- **フリープレイ**：難しさを選んで、1問ずつ解く。時間は計るが、ヒントの加算はない
- **今日のパズル**：日付で決まる3問（やさしい・ふつう・むずかしい）。誰が開いても同じ問題になる。合計の時間（ヒントは1回15秒の加算）を、日ごとに記録する
- **タイムアタック**：難しさと問題の数（3・5）を選び、続けて解いた合計の時間を競う。設定ごとに自己ベストを記録する。CPU のライバルを付けると、ライバルの進み具合が並んで出る
- **オンライン**：同じ問題の組を全員で解く早解きレース。合計の時間（ヒント15秒・まちがった盤面30秒の加算）の短い順に順位が付く
- ヒント（電球）は、まちがった印があれば消すマスを、なければ次に理屈で決まるマス（行・列の残りの数・張れる場所が1つしかない木・置くと矛盾するマス）を、理由と一緒に光らせる。待った（1手戻す）と、最初からやり直すこともできる
- **記録**：タイトル画面の「記録」に、フリーの解いた数と最短（ヒントなし）、タイムアタックの自己ベスト、今日のパズルを解いた日数と連続、オンラインの対戦の数と1位の数が出る（端末に保存）。ログインしていれば、共通の利用者ごとの記録（netplay-kit の user-stats）にも送る

## CPU

- CPU は、実際にヒントを当て続けて問題を解き、その手数から解き終わる時間を決める（`js/cpu-player.js`）
  - 時間 = (4秒 + 手数 × 10秒) × 強さの倍率（やさしい 1.8・ふつう 1・つよい 0.55）× ばらつき（0.8〜1.2倍）
  - 1手 10 秒は、ふつうの問題（9×9）を CPU（ふつう）が 2 分ほどで解くように決めた（`npm run cpu-match`：ふつう 1:57・むずかしい 4:58）。テントのヒントは行・列1本分をまとめて決めることが多く、1手が大きい
  - ばらつきは、渡された乱数（オンラインはサーバーの乱数、タイムアタックは組のシードから作った乱数）で決める
- タイムアタックのライバルと、オンラインの CPU（ロビーで足す。強さはロビーの設定）に使う。オンラインで部屋を出た人の席も、その時点から CPU が解く
- `npm run cpu-match` で、難しさごとに、ヒントで最後まで解けること・強さごとの時間・強さどうしの勝率を確かめる

## オンライン対戦

- netplay-kit の共通のロビー（公開の部屋）から遊ぶ。2〜4人（CPU を足せる）。ロビーで難しさ・問題の数・CPU の強さを選ぶ
- サーバーが問題の組を作り、問題（木の位置と行・列の数）だけを配る。シードはビューにも保存にも入れない（問題は見えてよいので、端末で答えを計算されるのは割り切る）
- 端末で解けたら、その盤面を送る。サーバーは種類の `check` で確かめ、解いた時間をサーバーの時刻で記録する（始まる前の 3.5 秒のカウントダウン中に送られたものは 0 秒として数える）
- 人（退出していない人）が全員解き終わるか、30分たったら終わる
- 定義は `server/src/game-definition.js`（中身は puzzle-kit の `public/js/race-definition.js`）

## 開発

このゲームは、パズルのゲームの共通部品 `packages/puzzle-kit` の写し（画面・遊びのロジック・オンラインの定義）に、このゲームの種類を載せたもの。共通の部分は `packages/puzzle-kit` で直して同期する（写しを直接直さない）。手順は `packages/puzzle-kit/README.md`。

```bash
npm test -w games/tents          # 種類の共通の検査・ロジック・記録の再現・オンライン・PWA・記録
npm run cpu-match -w games/tents # CPU の強さと、ヒントで解けるかの確かめ
npm run sw -w games/tents        # sw.js の先読みの一覧を作り直す
node packages/puzzle-kit/scripts/sync.mjs tents   # web-games の直下で。puzzle-kit を同期する（check で確かめる）
npm run dev:online               # web-games の直下で。手元のオンライン対戦のサーバー（ws://localhost:8787）
```

画面は `public/` を静的に配れば動く（`python3 -m http.server` など。8080 は避ける）。`?play&difficulty=hard&seed=3` で、その問題のフリープレイがすぐ始まる。

| ファイル | 中身 |
|---|---|
| `public/js/game.js` | このゲームの設定（名前・種類・曲・保存の名前の頭） |
| `public/js/puzzles/tents/` | 種類のロジック（`logic.js`）・画面（`render.js`）・入口（`index.js`） |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/sound/bgm.js` | BGM「たき火」 |
| `public/css/theme.css` | このゲームの色 |
| `public/js/main.js` ほか | puzzle-kit の写し（`puzzle-kit.lock.json` に一覧） |

記録：1人用の遊びは、操作（テント・芝生・ヒント・待った・最初から）を、遊び始めてからの時間（止めていた間は数えない）と一緒に記録する。`replay(setup, commands)` で同じ局面になり、「続きから」もこれで戻す。

## 決めたこと

- 種類のロジックは、パズル集（`games/puzzle-collection`）の `tents` をそのまま移した。直したのは CPU の速さ（1手 4 秒 → 10 秒）だけ
- 差し色は、森とキャンプ場に合わせた苔色にした
- 問題は前もって作って並べておかず、その場で作る
- 今日のパズルは、やさしい・ふつう・むずかしいを1問ずつにした（1種類のゲームなので、難しさで変化を付ける）
- ご褒美や集める要素は入れない
