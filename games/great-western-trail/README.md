# グレート・ウエスタン・トレイル

牛を連れて道を進み、カンザスシティから鉄道で西の都市へ届けるボードゲーム「グレート・ウエスタン・トレイル（Great Western Trail、初版）」を、ブラウザで CPU と遊べるようにしたもの。2〜4人（あなた＋CPU 1〜3人）。スマホの縦持ち向けで、PC の広い画面では道と鉄道を左、市場と選択肢を右に並べる。ホーム画面に置くと、オフラインでも遊べる。

絵（道・鉄道・アイコン）は、すべて SVG で自作している。

## 遊び方

手番は「進む → 止まった場所を使う → 手札を補充」の3つ。

- **進む**：牧場主を歩数の上限まで進める。建物・災害・ティーピーのあるマスだけを1歩と数え、空いたマスは数えない。カンザスシティは通り越せない。手の印（緑・黒）のある場所を通るか止まると通行料（ほかの人の建物なら持ち主へ、災害とティーピーは銀行へ。払えなければ払えるだけ）
- **使う**：中立の建物（A〜G）か自分の建物なら、そのアクションを好きな順に1回ずつ。使わないなら、補助アクションを1つ。ほかの人の建物・災害・ティーピーでは補助アクションを1つだけ
- **カンザスシティ**：先読みの3列から1枚ずつ選んで場に出し（労働者は求人市場へ、災害は道へ、ティーピーは交易の場所へ）、手札の違う品種の繁殖値の合計＋証明書の収入を得て、その値までの都市へ配達する。ボードの円盤を都市に置き、外した円盤の能力（補助アクション・手札の上限・歩数・証明書の上限）が使えるようになる。機関車が都市より手前なら、間の × の数だけ運賃
- **終わり**：カンザスシティで求人市場の最後のマスが埋まったら、ほかの人が1回ずつ手番をして終わり。$5ごとに1点・建物・都市・駅・災害・牛・目標カード・駅長・5〜6人目の労働者・歩数の円盤・求人市場のトークンの合計で競う

ルールは初版の英語のルールブック（2016）に合わせた。個人の建物は Aの面（1a〜10a）だけを使う。

### 推定の数値（ルールブックと照合できていない）

ルールブックのアイコンでしか示されていない次の数値は、オープンソースの実装（boardgamefiesta の初版）に合わせた推定。ルールブックの文とは照合できていない（食い違う出典も見つかっていない）。

- 災害の手の色と得点（種類ごとに、緑の手 4・4・3・2点、黒の手 3・2点）
- 技師の列の即時アクション（2人目：ジャージーで証明書+1、3人目：ジャージーで$2、4人目：$2安く雇う、5人目：ジャージーで証明書+2、6人目：ジャージーで$4）。カウボーイは4人目で災害を無料で除く・6人目で交易、職人は4・6人目で職人1人$1で建てる
- 駅の費用と得点、繁殖値4を3人で$6・繁殖値5を4人で$6 で買う買い方、4人のときの歩数（4 → 6 → 7）
- 中立の建物Fで災害を取り除く費用（$7）、エルパソ以降の都市の値（12・14・16・18）、求人市場の段ごとの雇用費（$6・6・7・5・7・9・6・8・10・6・5・4）

### 決めたこと・割り切ったこと

- 中立の建物は、初めて遊ぶときの置き方（A〜G をその文字のマス）で固定。最初の手番はランダム
- 同じ行き先へ通行料の違う道のりがあるときは、一番安い道のり（同じなら、ほかの人に払う額が少ないほう）を自動で選ぶ。わざと高い道を通ることはできない
- 「同じ品種2枚を捨てる」「ジャージーを捨てる」など、捨てるカードが決まっているときは自動で選ぶ（得点の低いものから）
- 「〜歩進んで、そこをもう一度使う」（建物3・4・10）で進むと、元の建物の残りのアクションは使えない
- 駅長にできるのは、2人目以降の労働者だけ（最初からいる1人目は出せない）
- 置く円盤がないときに駅の円盤を使う特例は、最初に見つかった駅の円盤を使う
- 牛を買うアクションでは、買う・カウボーイ1人で市場に2枚足す、を好きな順に繰り返せる（「買い終える」で終わる）
- 終わったときに山札に残っている目標カードは、得点が一番高くなる組み合わせで自動で数える
- 道の盤の形（マスの並びと分かれ道）は初版の盤に合わせたが、絵の位置は画面に合わせて描き直している

### 画面

- 上の人の欄に、お金と見えている得点。押すと、その人のボード（労働者・円盤・目標カード・牛の群れ・得点の内訳）を見られる
- タブで「道・鉄道・市場・ボード」を切り替える。選ぶものに合わせて、タブは自動で切り替わる
- 道は2本指・ホイール・ボタンで拡大できる。選べる場所は光り、タップでも選べる。進む番は、自分のあたりを拡大する
- 鉄道は0〜39のマスを蛇行で並べ、都市の紋章は都市の値と同じ番号のマスの下に置いた（× は運賃の目印）
- 途中でホームに戻っても、「続きから」で再開できる

## CPU

盤面の良さを「終わりの得点の見込み」（今の得点＋お金・労働者・機関車・牛の群れの繁殖値の見込み・証明書・外した円盤などの、残りの長さに応じた価値）で点数にし、点数が一番上がる手を選ぶ。進む手は、行ける場所ごとに手番の残りを貪欲に進めて比べる。自分の山札や各山の並びは見ない（試すときは、状態から作った別の乱数で混ぜ直す）。

| 強さ | 中身 |
|---|---|
| ふつう | 選択の先を読まず、移動先の点数に揺れを混ぜる |
| つよい | 選択の先にまた選択があれば、1段先まで読む。揺れなし |

CPU 同士の対戦：

| 対戦 | 試合 | 勝率 | 得点の平均 |
|---|---|---|---|
| 2人：つよい 対 ふつう | 30 | つよい 93.3% | 50.3 対 33.7 |
| 4人：つよい1 対 ふつう3 | 10 | つよい 50.0%（公平なら 25%） | 42.5 対 約31 |
| 2人：ふつう 対 でたらめ | 16 | ふつう 100% | 53.7 対 −19.7 |

```bash
# 試合数・人数・席ごとの強さ（normal・strong・random はでたらめ）
node scripts/cpu-match.mjs 30 2 strong,normal
```

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest。モノレポの直下で）
npm test -w games/great-western-trail
```

| ファイル | 役割 |
|---|---|
| `public/js/data.js` | 部品のデータ（牛・建物・道・駅・都市・目標カード・円盤） |
| `public/js/rules.js` | ルール。状態を JSON で持ち、選ぶものは列（queue）に積んで `choose` で答える |
| `public/js/game.js` | 操作の入口。写しの状態で試し、通ったときだけ差し替えて記録する。`Game.replay` で再現できる |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー（ほかの人の手札・山の並びは伏せる） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js` | 画面。選べる手は、ビューの状態にルールの関数を当てて求める |
| `public/js/board-view.js`・`rail-view.js` | 道（拡大・移動つき）と鉄道の SVG |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |

### オンライン対戦を入れるとき

ルールとビューは、netplay-kit の「ゲームの定義」の形（`server/src/game-definition.js`）で用意してある。netplay-kit の `sync.mjs` で部屋の処理を写し、この定義を `createHandler` と `startDevServer` に渡す。画面は、ローカル対戦と同じ `getView()` / `send()` の形のオンライン用のコントローラーを足す。
