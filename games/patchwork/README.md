# パッチワーク

パッチを買ってキルトに縫いつけ、ボタンを集める2人用のボードゲーム「パッチワーク」を、ブラウザで CPU と遊べるようにしたもの。あなた＋CPU 1人。スマホの縦・横、PC で遊べ、ホーム画面に追加すればオフラインでも遊べる。

布の色・模様、ボタン、時間の盤の絵と画面はすべて自作。

## 遊ぶ

```bash
python3 -m http.server 8000 --directory public
# http://localhost:8000/ を開く
```

ビルドは要らない（素の HTML / CSS / ES Modules）。

## テスト

```bash
npm install
npm test             # Vitest
npm run bench:cpu    # CPU の強さを測る（node tools/cpu-bench.mjs [試合数] [名前で絞り込み]）
```

## 実装したルール

- パッチは 33 枚（`public/js/patches.js`。形・ボタンの値段・時間・ボタンの収入）。混ぜて環に並べ、2×1 のパッチを中立の駒の真後ろに置く
- 9×9 のキルト。最初のボタンは5つ
- 時間の盤はスタート（0）からゴール（53）。時間の駒が後ろにいる人が手番。同じマスなら、あとから来た人（上に乗った人）が先に動く。最初の手番はランダム
- 手番の操作
  - 買う：中立の駒の先の3枚から1枚を選び、ボタンを払ってキルトに置く（回転・裏返しできる）。中立の駒は買ったパッチの場所へ進み、時間の駒はパッチの時間だけ進む
  - 進む：相手の1マス先まで進み、進んだマスの数だけボタンをもらう
- 収入のマス（5, 11, 17, 23, 29, 35, 41, 47, 53）を通る（止まる）と、キルトのパッチに付いたボタンの数だけもらう。パッチは置いてから時間を進めるので、買ったばかりのパッチのボタンも数える
- 革のパッチのマス（20, 26, 32, 44, 50）を最初に通った（止まった）人が 1×1 の革のパッチをもらい、すぐキルトに置く
- 7×7 の正方形を最初に埋めた人に +7
- ゴールを越える分は進まない（進むときのボタンも、実際に進んだマスの分だけ）
- 2人ともゴールに着いたら終わり。得点 = ボタン − 空きマス×2 ＋ 7×7 のボーナス。同点なら先にゴールした人の勝ち

### データの出典

パッチの形・値段・時間・収入と、時間の盤の収入のマス・革のパッチのマス・ゴールは、公開されている2つの実装を突き合わせて使った。

- [danzel/PatchworkSim](https://github.com/danzel/PatchworkSim)（`PieceDefinition.cs`・`SimulationState.cs`）
- [CACppuccino/PatchworkGame](https://github.com/CACppuccino/PatchworkGame)（`PatchworkGame.java`）

33 枚すべてで、値段・時間・収入・形（回転と裏返しを同じものとして比べた）が一致し、マスの合計も 166 で同じだった。時間の盤の値も両方で一致した。

### 解釈したところ

- 革のパッチを置く場所がもうないときは、もらえない（捨てる）
- 革のパッチは、そのマスにちょうど止まったときももらえる（「通った（止まった）」と扱う）

## CPU

`public/js/cpu-player.js`。

- 買う：パッチの価値 = 面積×2 − ボタンの値段 + 収入×残りの収入マスの数 − 時間 で見積もり、置き場所の良さを少し足して、いちばん高いものが「進む」（価値 0）より良ければ買う
- 置く：キルトの縁やほかのパッチに接するほど良く、孤立した空きマスを作るほど悪い
- 革のパッチ：まわりの空きが少ないマス（穴）を先に埋める
- 強すぎないように、パッチや置き場所の見落としと、見積もりのぶれを入れている

| 強さ | 見落とす確率 | 見積もりのぶれ |
|---|---|---|
| やさしい | 35% | ±3点 |
| ふつう | 15% | ±1.2点 |

CPU の判断には、ゲームの乱数を使わない（状態から作った別の乱数を使う）。

測った結果（`npm run bench:cpu`、各 200 試合。strong は見落としもぶれもない同じ CPU、simple は「面積 − 値段」が一番大きいパッチを左上から詰めて置く素朴な打ち方）：

| 組み合わせ | 結果 |
|---|---|
| ふつう 同士 | 平均 16.4点、空き 10マス、約41手 |
| やさしい 同士 | 平均 9.2点、空き 14マス |
| ふつう 対 strong | ふつうの勝率 40% |
| やさしい 対 ふつう | やさしいの勝率 25% |
| ふつう 対 simple | ふつうの勝率 89% |
| やさしい 対 simple | やさしいの勝率 72% |

## ファイル

| ファイル | 内容 |
|---|---|
| `public/js/patches.js` | パッチ33枚のデータ |

| `public/sw.js` | Service Worker（オフライン） |
| `tools/cpu-bench.mjs` | CPU の強さを測る |

### オンライン対戦を入れるとき

netplay-kit の「サーバーがゲームを進める型」にそのまま差し込める形にしてある。

- `create`：`new Game(players, { seed })`
- `persist` / `restore`：`{ players, options: { seed }, commands }` と `Game.replay`
- `view`：`createGameView(game, seat)`
- 操作：`advance`・`buy`・`leather` の3種類。断る操作は状態を変えない
- CPU：`runCpuStep(game)`
