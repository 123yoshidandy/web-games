# ボーナンザ

豆を畑に植えて育て、取引しながら売って金を集めるカードゲーム「ボーナンザ（Bohnanza、Uwe Rosenberg、Amigo 1997）」の基本ゲーム（拡張なし）を、ブラウザで CPU と遊べるようにしたもの。3〜5人（あなた＋CPU 2〜4人）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 手札5枚で始める。**手札の並びは変えられない**。植えるのはいつも一番前から、引いたカードは一番後ろに入る
- 畑は2つ。1つの畑には1種類だけ。同じ種類の畑があればそこに、なければ空いた畑に植える。植える畑がなければ、どれかの畑を売って空ける
- 手番
  1. **植える**：手札の一番前を植える。続けてもう1枚植えてもよい（3枚目は植えられない）
  2. **表にして取引**：山から2枚を表にする。手番の人は、表の2枚と手札（どの位置からでも）を出して、ほかの人と交換したり、あげたりできる。ほかの人は手番の人とだけ、手札から取引できる。もらった豆は手札に入れず、取っておく
  3. **もらった豆を植える**：取引でもらった豆と、手番の人の残った表の豆は、全員が全部植える
  4. **引く**：手番の人が山から3枚を、1枚ずつ手札の後ろへ
- **売る**：いつでも（手番でなくても）、畑の豆を全部売れる。売値の表の金額だけ豆を金にし、残りは捨て札に。1枚だけの畑は、ほかに2枚以上の畑があれば売れない
- **3つ目の畑**：いつでも3金で買える（1回だけ）。払った金は捨て札に戻る
- 山がなくなったら捨て札を切り直す。山が3回なくなったら終わり。表の2枚の途中でなくなったら、その手番の3（植える）まで続ける。3枚引く途中でなくなったら、すぐに終わり
- 終わりに、手札は置いて畑の豆を売る。金の多い人の勝ち。同点なら、手札の多い人

### 人数ごとの違い

| 人数 | 抜く豆 | 畑 | 終わり |
|---|---|---|---|
| 3人 | カカオ | 最初から3つ（買えない） | 山が2回なくなったら |
| 4〜5人 | コーヒー | 2つ（3つ目は3金） | 山が3回なくなったら |

ルールブックには、2人用（「豆の決闘」：取引のかわりに、表の3枚を相手に残す。山が1回なくなったら終わり）と、6〜7人（カカオとガーデンを抜く、配る枚数が席で3〜6枚、引くのは4枚、3つ目の畑は2金）の決まりもある。手番の形が違う（2人）か、画面に収まらない（6〜7人）ため、入れていない。

### 資料と、資料で分からない点の決め方

ルールは、Rio Grande Games の英語版ルールブック（2000年、2〜7人）を読んで合わせた。豆の枚数はルールブックの一覧、売値の表は Wikipedia（英語版）の表と RPGnet の紹介記事の表で照らし合わせ、一致した（ルールブックの本文には、くさい豆の表の例だけがある）。

食い違いと、決めたこと：

- Lookout の fan 版の資料は「104枚」と書き、ultraboardgames は「コーヒー・ワックス・カカオは7人までの遊び方だけで使う」と書く。どちらも別の版（拡張や、遊ぶ人数の範囲が違う版）の決まりと考え、2000年のルールブックどおり154枚・人数ごとに1種類を抜く形にした
- ガーデンの1金・4金と、カカオの1金はない（Wikipedia の表どおり）

ルールブックに書かれていない、または読み方が分かれる点：

- 提案は1件ずつ。提案された人が受けるか断るまで、ほかの提案はできない
- ほかの人の手札から欲しいものは「豆の種類と枚数」で求める。受ける人が、手札のどの位置のカードを渡すかを選ぶ（画面では、手放して損の少ない位置を初めから選んでおく）
- 1つの手番に1人が出せる提案は8件まで（終わらない交渉を防ぐ）。手番でない人は「取引しない」と言ったら、その手番はもう提案しない。手番の人は、いつでも取引を終えられる（CPU の手番では、人がまだ提案できるあいだは終えない）
- 畑に同じ種類の豆があれば、そこに植える（ほかの空いた畑には植えられない）
- 1枚だけの畑の売り方：空いた畑は数えない（ほかの畑がすべて1枚以下なら売れる）
- 最初の手番の人はランダム（配るのは、その人から順に5枚ずつ）
- 同点で手札の枚数も同じなら、その全員の勝ち
- 豆の名前は、画面のために自分で付けた短い名前（日本語版の名前は確かめていない）

### 画面の操作

- 光っている畑を押して植える。手番の初めは手札の一番前（金色の枠）、もらった豆は「植える」の欄で選んだもの
- 畑の「売る」でその畑を売る（売ったときの金額を出してある）。「畑を買う」で3つ目の畑
- 「表をめくる」で山から2枚を表に
- 取引は「提案」から：相手（手番のとき）、出すカード（表・手札）、もらうもの（手番の人の表のカード、相手の手札から欲しい豆の種類）を選んで送る。手番のときは「取引おわり」、手番でないときは「取引しない」で抜ける
- CPU からの提案は、ダイアログで「もらう」「渡す」を見て「受ける／断る」。閉じても、下の「答える」で開き直せる
- 上の人の欄は、金・手札の枚数・畑。押すと、その人の畑と植える前の豆が見られる
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は、その席のビュー（`createGameView`）だけを受け取って決める（`chooseCommand(view, level)`）。ほかの人の手札と山の並びは見えない。ゲームの乱数も使わない（`public/js/cpu-player.js`）。

- ふつう：豆1枚の価値を「それを植えることになったら、自分の畑にとってどうか」で見る
  - 同じ種類の畑があれば良い（次の金額に届くならもっと良い）。空いた畑があれば少し良い。どちらもなければ、畑を売らされるので悪い
  - 手札は、前の2枚ほど重く見る（次の手番に植えるため）。前のほうのいらないカードを手放せる取引は得
  - 提案は、もらう豆の価値から渡す豆の価値を引き、得なら受ける。渡す位置は、失う価値の小さい位置
  - 手番では、いらない表の豆と、前のほうのいらない手札を、その豆の畑を持っている人（なければ空いた畑がある人）に回す。まず自分の畑の豆との交換を求め、断られたらあげる
  - 手番でないときは、表に自分の畑の豆があれば、いらない手札をつけて求める
  - 売れる金額が上限に届いた畑は売る。3つ目の畑は、山が1回目のうちに3金あれば買う
- やさしい：受ける・断るに大きな迷いを足し、自分から交換は求めない（いらない表の豆をあげるだけ）。3つ目の畑は、植える畑がないとき以外は買わない

CPU どうしでもよく取引する（ふつう4人で、1試合に提案約190件・成立約80件）。

```bash
# 試合数・強さの並び（easy・normal）。席の並びは試合ごとに1つずつずらす
node scripts/cpu-match.mjs 1000 easy,normal,easy
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 平均の金（ふつう／やさしい） |
|---|---|---|---|---|
| 3人（やさしい・ふつう・やさしい） | 1000 | 92.6% | 4.0%・3.4% | 23.3／14.2 |
| 4人（ふつう・やさしい・ふつう・やさしい） | 1000 | 47.4%・46.1% | 3.1%・3.4% | 18.2／10.2 |
| 5人（やさしい3・ふつう2） | 1000 | 47.3%・46.0% | 1.8%・2.5%・2.4% | 13.5／6.5 |
| 3人（ふつう3人） | 1000 | 32.4%・33.7%・33.9% | — | 23.7 |
| 4人（ふつう4人） | 1000 | 26.8%・25.8%・24.5%・22.9% | — | 17.8 |
| 5人（ふつう5人） | 1000 | 21.4%・18.8%・22.6%・18.4%・18.9% | — | 13.2 |
| 3人（やさしい3人） | 1000 | — | 32.4%・33.8%・33.9% | 8.0 |

同点で複数が勝った試合は、勝ちを等分して数えた。どの組み合わせでも、止まった試合はない。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

### オンライン対戦を入れるとき

netplay-kit の `scripts/sync.mjs` で部屋の処理を写し、`server/src/game-definition.js` を `createHandler` と `startDevServer` に渡す。部屋には参加者・シード・操作の記録だけを保存し、操作のたびに記録から再現する。取引の段階では、手番の人と、まだ「取引しない」と言っていない人が同時に操作を待つ（`game.actors()`）。売る（`harvest`）と畑を買う（`buyField`）は、待っている人でなくても送れる。端末から届いた操作は `sanitize` で種類ごとの項目だけを取り出してから `applyCommand` に渡す。
