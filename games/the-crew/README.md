# ザ・クルー

協力型のトリックテイキングのカードゲーム「ザ・クルー（The Crew: The Quest for Planet Nine）」（第1作の基本ゲーム）を、ブラウザで CPU の仲間と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人。2人のときは JARVIS が加わる）。航海日誌の50のミッションを順に進め、進み具合（クリアまでの挑戦の回数）を保存する。スマホの縦・横、PC で遊べ、ホーム画面に追加すればオフラインでも遊べる。

カードの絵、アイコン、画面はすべて自作。

## 遊ぶ

```bash
python3 -m http.server 8000 --directory public
# http://localhost:8000/ を開く
```

ビルドは要らない（素の HTML / CSS / ES Modules）。

## テスト

```bash
npm install
npm test             # Vitest
npm run bench:cpu -- --players 4 --games 20 --missions 1-50   # CPU だけでミッションごとの成功の割合を測る
```

## 実装したルール

### カードとトリック

- 4色（桃・黄・青・緑）の1〜9と、ロケット（切り札）の1〜4。色は記号（輪のある惑星・星・ひし形・三角）でも見分けられる
- ロケットの4を持つ人が指揮官。指揮官が最初のトリックを始める（課題のないミッションでも）
- 出された色を持っていれば、その色を出す（出せないカードは暗くなる）。ロケットがあれば一番大きいロケット、なければ出された色で一番大きいカードが勝つ
- 人数ごとの配り方：3人は 14・13・13 枚（最後に1枚残り、13トリック）、4人は10枚、5人は8枚

### 課題と順番のトークン

- 課題のカードを、指揮官から時計回りに1枚ずつ選ぶ。課題のカードを持ち主がトリックで取れば達成、ほかの人が取ったらその場で失敗。すべて達成したら成功
- 順番のトークン：数字（1〜5）はその番目に、矢印（›・››・›››・››››）はこの順に、Ω は最後に果たす。同じトリックで続きの番号の課題を果たすのはよい
- 指揮官の決定（20・27・37）：課題は裏のまま、指揮官が全員に「すべて受け持てるか」を聞き、指揮官以外の1人を選ぶ。選ばれた人がすべての課題を受け持つ
- 指揮官の配分（24・32・36・43）：課題を1枚ずつめくって全員に聞き、指揮官が配る（自分でもよい）。最後に2枚以上の差がつく配り方はできない。トークンは課題と一緒に配る
- 5人のとき、ミッション25以降は、最初のトリックの前に課題を1枚ほかの人へ渡せる

### 通信

- ミッションごとに1回、トリックの前に（課題を配ったあと）、手札の色のカードを1枚見せる。その色で一番上・唯一・一番下のどれか（通信のトークンの位置）を伝える。ロケットと、それ以外のカードは通信できない
- 不感地帯：カードは見せるが、位置は伝わらない
- 通信の妨害：決まったトリックの前から通信できる
- ミッション11：指揮官が選んだ1人は通信できない

### 遭難信号

- 最初のトリックの前で、だれも通信していないときだけ。全員がロケット以外の1枚を、同じ向きの隣の人へ渡す
- 使ったら、航海日誌の挑戦の回数が1回増える

### 特別な条件のミッション

| 9・26 | 色の1のカードで、トリックを1つ（26は2つ）取る |
| 12 | 1トリック目のあと、全員が右の人の手札から1枚を引く（課題4・Ω） |

### 2人（JARVIS）

ロケットの4を除いた39枚から、JARVIS に裏7枚・その上に表7枚を置き、残りにロケットの4を混ぜて2人に13枚ずつ配る。指揮官が JARVIS の課題を選び、JARVIS の番には JARVIS の表のカードから出す。表のカードを出したら、トリックのあとに下のカードを表にする。

### 解釈したところ

- 「左の人」は次の席（時計回り）とした（ミッション46、遭難信号の向き）
- ミッション5・33・41で、指揮官は自分を選んでもよいとした（ルールブックの「自分は選べない」は指揮官の決定の記述にだけある）
- 2人のとき、遭難信号で JARVIS はカードを渡さない。JARVIS は問いかけに答えない
- 5人の課題の受け渡しは、人の席の人が決める（CPU だけのときは渡さない）
- ミッション12の引くカードは、ゲームの乱数で決める
- 1回の挑戦が1つのゲーム。失敗したら「もう一度挑む」で配り直す。航海日誌の挑戦の回数は、終わった挑戦の数（遭難信号は1回足す）

## CPU

見えている情報（自分の手札・場・通信・出されたカード・JARVIS の表のカード）だけで考える。ほかの人の手札はのぞかない。

- 課題を選ぶ：その色の大きいカードやロケットを持っていて、自分で取れそうな課題を選ぶ
- 通信：ほかの人の課題のカードを持っているとき、自分の課題の色で課題より大きい一番上のカードを持っているときに伝える
- 読む：通信（一番上なら大きいカードはない、唯一ならその色はそれだけ、一番下なら小さいカードはない）と、色を出せなかったこと（その色がない）から、見えないカードの配り方を何通りか想像する
- 出す：想像したそれぞれの配り方で、出せるカードごとに、全員が「課題のカードを持ち主に取らせる」よう協力したとして最後まで進め、成功しやすいカードを選ぶ（強さ「ふつう」は12通り）

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜5人で、足りない席は CPU で埋められる（2人のときは JARVIS が加わる）。部屋はミッション1から始め、ミッションを選ぶのと航海日誌はローカル対戦だけ。ほかの人の手札はビューに入れない。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'the-crew' })`。web-games の1つのスタックから `?game=the-crew` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `tests/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

- ミッション：同 英語版の航海日誌（Log Book）。課題の数は PDF の文字と、ページの画像の2通りで、順番のトークンはページの画像と、画像の個数の2通りで読み取って突き合わせた。航海日誌とは別の出典（ほかの言語版・ファンの一覧）は、確かな形で手に入らなかった
