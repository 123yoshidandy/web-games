# キング・オブ・トーキョー

巨大モンスターになってダイスを振り、東京を奪い合うゲーム（第2版の基本ゲーム。パワーカード 66 枚）。ブラウザで、CPU を相手に 2〜6 人で遊べる（人間 1 人＋CPU 1〜5 人）。スマホの縦・横の画面と PC に対応し、ホーム画面に追加するとオフラインでも遊べる（PWA）。

モンスターの絵・ダイス・アイコンは自作。カードの名前は日本語の訳（自分で付けたもの）。

## 遊ぶ

ビルドは要らない。リポジトリのルートで HTTP サーバーを立てて開く。

```bash
python3 -m http.server 8080
# http://localhost:8080/public/ を開く（ルートを開くと public/ へ移る）
```

## ルール

- 体力 10・勝利点 0 で始める。先に 20 勝利点を集めるか、最後の 1 体まで生き残ったら勝ち。手番は無作為に決めた人から
- 手番：ダイス 6 個を振り、残したいダイスを選んで、残りを 2 回まで振り直す。出目を決めたら効果を解決する
  - 1・2・3：同じ数字 3 つでその数の勝利点、4 つめから 1 つにつき +1
  - エネルギー：1 つにつき 1 エネルギー
  - ハート：1 つにつき体力 +1（上限 10）。東京にいる間は回復できない
  - 攻撃：東京にいれば東京の外の全員に、外にいれば東京のモンスターに、1 つにつき 1 ダメージ
- 東京：空いていれば入る（+1 勝利点）。東京で番を始めると +2 勝利点。東京で攻撃されたら、明け渡すか残るかを選び、明け渡すと攻撃した人が入る
- 5〜6 人のときは東京湾もあり、2 体まで東京に入れる。生き残りが 4 体以下になったら東京湾は使わない
- カードの購入：番の終わりに、場の 3 枚をエネルギーで買える。2 エネルギーで場の 3 枚を捨てて入れ替えられる（何度でも）
- パワーカード：持続（買ったあと効果が続く）48 枚と、使い捨て（買ったときに効果を使う）18 枚。毒・縮小のトークン、ものまね・煙幕・バッテリーモンスターなどのカウンターも扱う

### 決めたこと（説明書だけでは決まらない点）

- カードの構成は第2版の基本ゲーム。第1版から入れ替わった 7 枚（異星の生まれ・メディアの人気者・バッテリーモンスター・雑食・エナジードリンク・空からの襲撃・火炎放射器）は第2版のものにした。公開されている 2 つの資料（BGA の実装と、第1版のカード一覧）で、共通の 57 種の費用・種類が一致することを確かめた
- ハートで回復するときは、毒・縮小のトークンを先に消す
- 急速回復は、体力が 0 になるときに 2 エネルギーがあれば自動で使う（いつでも自分で使うこともできる）
- 癒しの光線：相手は回復した体力 1 につき 2 エネルギーを払う。払えるエネルギーまでしか回復しない
- 東京を明け渡すかは、ダメージを受ける前に決める（ジェットなどのため）
- 火炎の息は、攻撃の目がなくても両隣に 1 ダメージ。明け渡しの判断は出ない
- ものまねは、カウンターを使うカード（ものまね・煙幕・バッテリーモンスター）はまねできない
- 寄生触手で買ったカードのカウンター（煙幕の残りなど）は引き継がない
- 判官びいき（下位を助ける）は、同点の最下位も含む
- 最後の 1 体が同時に倒れたときは引き分けではなく、勝利点の多い人（同点なら手番の人）の勝ち

## 操作

- ダイスを押すと「残す」になり（黄緑に光る）、もう一度押すと外れる。「振り直す」で残していないダイスを振り直し、「決定」で出目を決める
- 目を変えるカード（群れの間引き・どんでん返し・伸縮自在）を持っていれば、ダイスの上にボタンが出る。カードを選び、ダイスを押し、目を選ぶ
- 場のカードを押して選び、「買う」。「流す」で場の 3 枚を入れ替え、「終える」で番を終える
- 東京を明け渡すか、翼・念力探査・ものまねなどの判断は、大きなボタンのダイアログで出る（ほかの人の番でも出る）
- モンスターの欄を押すと、そのモンスターのカードの効果が見られる。自分のカードは下の列から見られる
- 途中で閉じても、タイトルの「続きから」で再開できる（操作の記録を保存して再現する）

## CPU

自分のビューだけで判断する（ほかの人の判断の中身や山札の並びは見ない）。ダイスは、勝利点の組、体力の残り、東京にいるかで、残す目を評価して選ぶ。カードは、効果ごとの値打ちの表と残りのエネルギーで買うかを決める。東京は体力が一定以下になったら明け渡す。ゆらぎを入れて、強すぎないようにしている。

- ふつう（既定）・やさしい の 2 段階
- 強さの測定：`npm run sim -- <試合数> <強さの並び>`（例：`npm run sim -- 400 normal,easy`）。`strong`（ゆらぎなし）と `random` は測定用

自分の番の操作の欄（とダイアログ）の「ヒント」を押すと、ゆらぎのない CPU が選ぶ手を、選んだ状態にして光らせる（残すダイス・買うカード・明け渡すかなどの答え）。CPU と同じく、自分のビューだけで決める。

## ファイルの構成

| ファイル | 内容 |
|---|---|
| `public/js/cards.js` | パワーカード 66 枚のデータ（費用・種類・効果の文）、モンスター |
| `public/js/game.js` | ゲーム本体。手順を積んで進め、判断が要るところで止まる。`applyCommand` と `Game.replay` |
| `public/js/game-view.js` | ビュー（判断の中身は、決める人にだけ渡す） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | ローカル対戦のコントローラー（`getView()` / `send()`） |
| `public/js/art.js` | モンスター・ダイス・アイコンの絵と、記録の文 |
| `public/js/main.js` | 画面の進行 |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形） |

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜6人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

CPU の強さ（やさしい・ふつう）はロビーで決める。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'king-of-tokyo' })`。web-games の1つのスタックから `?game=king-of-tokyo` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
