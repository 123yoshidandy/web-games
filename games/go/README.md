# 囲碁

9路・13路・19路の碁盤で、日本ルールで打つ囲碁。ブラウザで遊べる（スマホの縦持ち向け、PC でも遊べる）。

- CPU と対局（やさしい・ふつう・つよい・とてもつよい。黒・白を選べる）
- 2人で1台を使って対局
- 置き碁（9路は2〜5子、13路・19路は2〜9子）、コミの変更（なし・半目・5目半・6目半・7目半）
- 待った（1手戻す）、続きから、投了、棋譜の保存（SGF）
- ホーム画面に追加すると、オフラインでも遊べる（PWA）

絵（盤・石・アイコン）はすべて自作の SVG。

## ルール（日本ルール）

- 黒と白が交互に、線の交点に1つずつ打つ。黒が先。置き碁では黒の石を星に置き、白から打つ
- 取り：縦横でつながった相手の石（連）のダメ（隣の空き）をすべてふさぐと、取り上げる。取った石はアゲハマ
- 自殺手の禁止：打った石の連のダメがなくなる手は、相手の石を取れないかぎり打てない
- コウ：1子を取り返すと直前の形に戻る点には、すぐには打てない（ほかに1手打つかパスをすれば打てる）
- パスはいつでもできる。2人が続けてパスしたら終局
- 終局後、死に石を決める。CPU が見込みで決め、人が連ごとに直す。2人が確定したら数える。どちらかが「対局再開」で打ち続けられる
- 点＝地（一方の色の石だけに囲まれた空き。死に石の点を含む）＋アゲハマ（取った石と相手の死に石）。白にはコミを足す。同じなら持碁

### 割り切った点

- **コウは「直前の形に戻る手」だけを禁じる**（日本ルールのコウ）。三コウなどの同形反復は禁じない。終わらないのを防ぐため、CPU は手数が盤の点の数の 2.5 倍を超えたらパスする
- **セキの中の地も数える。** 日本ルールではセキの眼は地にならないが、判定していない。一方の色だけに囲まれた空きは、すべて地になる
- **死に石は連ごとに指定する**（つながっていない石は、1つずつ押す）
- **CPU は死に石の指定に、そのまま同意する。** 2人で1台のときは、「確定」で2人分をまとめて確定する
- **待ったは、人の最後の着手（打つ・パス）まで戻す。** CPU 戦では、そのあとの CPU の手と死に石の指定もまとめて戻す
- 時間の決まり（持ち時間・秒読み）は入れていない

## 操作

- 交点を押すと打つ。マウスでは、打つ前に薄い石で位置を示す
- **仮置き：** 盤が小さく表示されるとき（指で押す端末で交点の間が 30px 未満。スマホの13路・19路）は、押すと仮に置き、赤い十字の線で行と列を示し、下に座標（Q16 など）を出す。指を動かすと仮の石も動く。同じ点をもう一度押すか「ここに打つ」で打つ
- 打てない点（コウ・自殺手）を押すと、わけを短く知らせる。コウで今は打てない点には赤い四角が付く
- 直前の手に赤い輪。上に手数、対局者の欄にアゲハマとコミ、盤の下に直前の手の座標
- 上のバー：ホーム／待った・棋譜の保存（SGF）・投了・遊び方
- 終局後：石を押すと死に石（×）と生き石が切り替わる。地を小さな四角で示し、盤の下に今の点を出す

## CPU

`public/js/engine.js` のモンテカルロ木探索（MCTS）。終局まで乱数で打ち進める「プレイアウト」を何度も行い、勝つ割合の高い手を選ぶ。

- **速い盤：** 縁つきの盤。連ごとに疑似ダメの数・番号の和・2乗の和を持ち、アタリとその点を、連をたどらずに求める
- **プレイアウト：** 直前の手でアタリになった石の取りと逃げを優先し、ほかは自分の眼をつぶさない手を乱数で選ぶ。終わったら石と眼を数え（エリア）、打った石の数の差を引いて日本式の差に合わせる
- **木：** UCT に RAVE（AMAF）を足す。序盤の1線・2線を低く、取り・逃げを高く、自分からアタリになる手を低く見込む（事前の値）
- 勝ち負けに点差を少し混ぜる（大差のときに手が緩まないように）
- **パス：** 相手がパスしたあと、今終わっても勝っているならパスする。中盤を過ぎたら、探索でパスが一番良いときもパスする
- **投了：** つよい・とてもつよいだけ。中盤を過ぎて、勝つ見込みが 5% を切ったら
- 打ち切りはプレイアウトの回数で決める。時間（12秒）は安全弁だけ。乱数は盤から作るシードを使うので、同じ局面なら同じ手になる
- ブラウザでは Web Worker（`cpu-worker.js`）で考え、画面を止めない

| 強さ | 9路 | 13路 | 19路 |
|---|---|---|---|
| やさしい | 300 | 300 | 300 |
| ふつう | 2,000 | 1,500 | 1,500 |
| つよい | 7,000 | 5,000 | 4,000 |
| とてもつよい | 20,000 | 12,000 | 8,000 |

（1手あたりのプレイアウトの回数）

### 死に石の見込み

終局の局面から、両方の色に交互に先に打たせて 400 回プレイアウトし、点ごとの持ち主の割合を数える。連の石が平均して相手のものになる連を死に石とする。ただし、眼（縦横がすべて同じ色の空き）を2つ以上持つ連は生きとする（乱数のプレイアウトは、生きた石も取られることがあるため）。シードは盤から作るので、記録を再現しても同じ結果になる。

### 勝率と時間

`node scripts/cpu-match.mjs <試合数> <強さA> <強さB> <盤>` で測った（開発用の Mac。最初の2手は乱数でばらし、試合ごとに席を入れ替える）。

| 対戦 | 盤 | 試合数 | 勝率 | 1手の平均（最長） |
|---|---|---|---|---|
| ふつう 対 やさしい | 9路 | 10 | 100% | 35ms（62ms）／5ms |
| つよい 対 ふつう | 9路 | 10 | 70% | 122ms（176ms）／34ms |
| とてもつよい 対 つよい | 9路 | 10 | 70%（10局中9局が投了） | 388ms（469ms）／133ms |
| ふつう 対 やさしい | 13路 | 2 | 100% | 56ms／12ms |
| ふつう 対 やさしい | 19路 | 2 | 100% | 123ms／25ms |

どの組み合わせでも、止まった対局はない。19路のとてもつよいは、ブラウザ（PC）で1手約 0.7 秒。スマホでは数倍（2〜3秒）かかる見込み。

## 開発

素の HTML / CSS / JavaScript（ES Modules）。ビルドはない。

```bash
npm test                                          # Vitest
python3 -m http.server 8080 --directory public    # http://localhost:8080/
node scripts/cpu-match.mjs 20 strong normal 9     # CPU どうしの勝率
```

### ファイル

| ファイル | 役割 |
|---|---|
| `public/js/rules.js` | 盤・取り・自殺手・コウ・地の計算・置き石の位置（DOM に依存しない） |
| `public/js/game.js` | 進行（手番・パス・終局・死に石・確定・投了）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現する。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（盤・アゲハマ・コウ・地の持ち主と点） |
| `public/js/engine.js` | CPU の読み（速い盤・プレイアウト・MCTS・持ち主の見込み） |
| `public/js/cpu-player.js` | CPU の強さと、ビューから手を決める処理（パス・投了・確定） |
| `public/js/cpu-worker.js` | CPU の読みを Web Worker で行う |
| `public/js/game-controller.js` | ローカルの対局（CPU 戦・2人で1台）。待った、保存と続きから、CPU を間を置いて打たせる |
| `public/js/sgf.js` | 棋譜の書き出し（SGF） |
| `public/js/ui.js`・`art.js` | 画面と絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（自分のファイルはネットワークを先に、字体はキャッシュを先に使う） |
| `server/src/game-definition.js` | オンライン対戦の「ゲームの定義」（netplay-kit の形） |
| `scripts/cpu-match.mjs` | CPU どうしの対局と勝率・1手の時間 |

### テスト

- `rules.test.js`：座標、連とダメ、取り（隅・辺・複数の連を同時に）、自殺手（取れるなら打てる）、コウ（すぐ取り返せない・2子取りや大石の取りはコウでない）、日本式の地の計算（ダメ・死に石・コミ・持碁）、置き石の位置
- `game.test.js`：置き碁、断る操作のわけ、コウの解消（コウ立て・パス）、パス2回で終局、死に石の見込み・指定・確定・対局再開、投了、乱数の対局と記録からの再現、でたらめな操作で状態が変わらない
- `engine.test.js`：速い盤が rules.js と一致する、同じシードで同じ手、アタリの取りと逃げ、コウの点を選ばない、回数での打ち切り、持ち主の見込み
- `cpu-player.test.js`：対局が最後まで終わる、ふつうがやさしいに勝ち越す、パスの判断、確定、手数の安全弁
- `game-controller.test.js`：CPU が人の番で止まる、白を選ぶと CPU から、待った、2人で1台の確定、終局、投了、続きから
- `sgf.test.js`・`game-definition.test.js`・`pwa.test.js`・`offline.test.js`

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で（片方を CPU にもできる）、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

盤の大きさ（9路・13路・19路。既定は9路）はロビーで決める。コミ・置き石は既定の値。部屋の CPU は「ふつう」。死に石は2人とも確定したら終わる。待ったと棋譜の保存は、ローカルの対局だけ。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'go' })`。web-games の1つのスタックから `?game=go` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
