# 宝石の煌き デュエル

宝石とパールを集めてカードを買う2人用のボードゲーム「宝石の煌き デュエル（Splendor Duel）」を、ブラウザで CPU と遊べるようにしたもの。スマホの縦持ち向け（横向きでも遊べる）。ホーム画面に置くと、オフラインでも遊べる。

絵（トークン・カード・王族のカード・アイコン）は、すべて SVG で自作している。

## 遊び方

- 2人（あなた＋CPU）。CPU の強さは「やさしい」「ふつう」から選ぶ
- 手番の終わりに、次のどれかに達したら勝ち
  - 20点
  - 王冠10個
  - 同じ色のカードで10点（色なしのカードは、写した色に数える）
- 手番には、してもしなくてもよい行動（この順）のあと、必ず行う行動を1つ行う
  - 特権を使う：巻物1枚につき、盤の宝石かパールを1個取る（黄金は取れない）
  - 盤を補充する：袋のトークンを、中央かららせんの順に空いたマスへ置く。相手が特権を1枚得る
  - 必ず行う行動（どれか1つ）
    - トークンを取る：縦・横・斜めにすき間なく並んだ1〜3個（黄金は取れない）。同じ色を3個かパールを2個取ったら、相手が特権を1枚得る
    - 予約する：盤の黄金を1個取り、場のカードか山札の一番上（伏せたまま）を手元に置く（3枚まで）
    - 買う：場か予約したカード。ボーナスの分だけ安くなる（パールは安くならない）。黄金はどの色の代わりにもなる
  - 必ず行う行動ができないときは、先に盤を補充する
- カードの能力：もう一度（もう1手番）・同じ色を取る（盤からカードの色を1個）・特権（1枚得る）・盗む（相手の宝石かパールを1個）・色なし（持っているボーナスの色を写す。ボーナスのカードがないと買えない）
- 特権を得るとき、巻物が残っていなければ相手から取る
- 王冠が3個と6個になったとき、王族のカード（3点、または2点＋能力）を1枚取る
- 手番の終わりに、トークンが10個を超えていたら、超えた分を選んで袋に返す
- 準備：25個のトークン（宝石5色×4・パール2・黄金3）を盤に置き、カードは1段目5枚・2段目4枚・3段目3枚を表にする。後手の人が特権を1枚持って始める

### ルールブックに書かれていないので決めたこと

- 盤のらせんは、中央から上へ出て時計回りに回る順にした（盤に印刷されたらせんの向きは、確かめられなかった）
- 「もう一度」が同じ手番に重なったら（カードと王族のカード）、その数だけ続けて手番を行う
- 能力は「色を写す → カードの能力 → 王族のカードを取り、その能力」の順に行う
- 必須の行動ができず、袋も空で補充もできないときは、何もせずに手番を終える（パス）。2人が続けてパスしたら、点の多い人の勝ち（同じなら引き分け）
- 選べるものが1つしかない能力（盤にその色が1個だけ、写せる色が1色だけ、など）は自動で選ぶ。予約のときに盤の黄金が1個だけなら、それを取る
- 最初の手番の人は、ランダムに決める

### 画面の操作

- 盤のトークンを押すと、続けて取れるマスだけが光る。続けて押して「取る」。1個だけ選んだときは「特権で」取ることもできる
- カード・山札を押して「買う」「予約」。金色に光っているカードは、今買えるカード。盤に黄金が2個以上あるときは、予約のあとに取る黄金を盤から選ぶ
- 「補充」は、ピラミッドの右の袋の下にある
- 能力で色を写す・相手から盗む・王族のカードを取るときは、選ぶシートが出る。「盤を見る」で閉じても、操作の欄の「選ぶ」で出し直せる。同じ色を取るときは、盤の取れるマスが光る
- 相手の欄や自分の点の行を押すと、色ごとのボーナスと点・予約・王族のカードが見られる
- 途中でホームに戻っても、「続きから」で再開できる

## カードのデータの出典

カード67枚と王族のカード4枚は、公開されている次の3つの実装を照らし合わせて作った（`public/js/cards.js`）。

- [dylanguo1129/splendor-duel-ai](https://github.com/dylanguo1129/splendor-duel-ai) の `data/cards.json`
- [CGYGameDevelopment/Splendor-Duel](https://github.com/CGYGameDevelopment/Splendor-Duel) の `jewel-cards.csv`・`royal-cards.csv`
- [ErronZrz/splendor-duel](https://github.com/ErronZrz/splendor-duel) の `backend/internal/game/cards.go`

食い違ったのは次の2点で、多数に従った。

- 2段目の「1点・ボーナス2つ」の5枚：ボーナス2つ（cards.json・csv。cards.go はボーナスの数を持たない）
- 1段目の「王冠1・色なし」のカードのコスト：白4・パール1（cards.json・cards.go。csv だけ黒1が多い）

## CPU

自分から見える情報だけ（山札の並びや、相手が伏せて予約したカードは見ない）で、「ねらうカードを決め、不足分のトークンが多く入る連なりを取り、買えるようになったら買う」方針で打つ。特権は、使えば今すぐ買えるときだけ使う。相手があと1手で勝てる場のカードに気づけば、予約して止める。

強すぎないように、場のカードの見落とし・評価の揺れ・いちばん良い連なりの見逃し・買い控え・相手の勝ち筋の見逃しを混ぜている（目の前の勝ちは見逃さない）。「やさしい」は「ふつう」より誤りが多い。

CPU 同士の対戦で、勝率と試合の長さを測れる（strong は見落としのない比較用で、画面では選べない）。

```bash
# 試合数・席0の強さ・席1の強さ
node scripts/cpu-match.mjs 400 easy normal
```

400〜500試合で測った結果：やさしい 対 ふつう は 32%：68%、ふつう 対 つよい（比較用）は 37%：63%。どの組み合わせでも、試合は必ず終わる（1人あたり約35手番）。

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/cards.js` | カード67枚と王族のカード4枚のデータ |
| `public/js/game.js` | ルール。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js`・`art.js`・`animator.js` | 画面・絵・動き |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |
| `scripts/cpu-match.mjs` | CPU 同士の対戦 |

### オンライン対戦を入れるとき

ルールとビューは、netplay-kit の「ゲームの定義」の形（`server/src/game-definition.js`）で用意してある。netplay-kit の `sync.mjs` で部屋の処理を写し、この定義を `createHandler` と `startDevServer` に渡す。画面は、ローカル対戦と同じ `getView()` / `send()` の形のオンライン用のコントローラーを足す。
