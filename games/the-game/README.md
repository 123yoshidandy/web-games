# ザ・ゲーム

2〜99 の98枚を、仲間と協力して4つの山に出し切る協力カードゲーム「The Game」（Steffen Benndorf）をもとにしたブラウザゲーム。1〜5人で遊べ、足りない席は CPU の仲間が埋める。スマホの縦持ち向け。

## 遊び方

- 山は4つ。上り（1から）の2つには一番上より大きいカードを、下り（100から）の2つには小さいカードを出す
- ちょうど10違うカードは逆向きにも出せる（上りの 47 に 37、下りの 52 に 62）。山が戻る「10戻し」
- 自分の番には2枚以上（山札がなくなったら1枚以上）出し、「番を終える」で手札が元の枚数になるまで引く
- 手札の枚数：1人 8枚・2人 7枚・3〜5人 6枚
- 番の人が決まった枚数を出せなくなったら終わり。残ったカード（山札と全員の手札）が少ないほど良い。0枚なら出し切り、10枚以下ならすばらしい結果
- 数字は伝えられない。代わりに、山ごとに合図を置ける（原作で許されている「この山には出さないで」「この山に大事なカードがある」のような言い方の代わり）。合図は番でなくても置ける
  - 手のひら：この山には出さないで
  - 星：この山に大事なカードがある
- 操作：手札を選び、出したい山を押す。山には進む数（+3・10戻し）が出る。山の下の「合図」で自分の合図を置く
- ヒント（電球）：おすすめのカードと山、または「番を終える」を光らせる（`suggest()`、つよい CPU と同じ考え）
- 待った（矢印）：今の番に出したカードを1枚ずつ戻せる。番を終えて引いたあとは戻せない
- 途中経過は自動で保存し、タイトルの「続きから」で再開できる

### 結果と音

| 結果 | 条件 | 効果音 |
|---|---|---|
| 全部出し切った | 残り0枚 | `win` |
| すばらしい | 残り10枚以下 | `notify` |
| ここまで | 残り11枚以上 | `lose` |

ほかの効果音：カードを選ぶ `select`・出す `place`・10戻し `gain`・番を終えて引く `draw`・選び直し／待った／合図を外す `cancel`・出せない山 `error`・仲間がカードを出した `notify`・自分の番になった `turn`・始まり `shuffle`。

## CPU

CPU は仲間で、強さは3段階（タイトルの「仲間」、オンラインはロビーの「CPU」）。手の良さは「山がどれだけ進むか（飛ばした数）」で測り、10戻しは -10 として最優先する。CPU は自分の手札しか見ない（ほかの人の手札・山札の並びをのぞかない）。

| 強さ | 決まった枚数の選び方 | 続けて出す | 合図 |
|---|---|---|---|
| やさしい | 1枚ずつ、その場で一番近いカード | 10戻しだけ | 出さない・読まない |
| ふつう | 手札の2枚の組み合わせ（大きい方を出してから10戻すなど）まで | 飛ばす数 3 以下 | 出す・読む |
| つよい | 3枚先までの組み合わせと、残りの手札の出しやすさ | 飛ばす数 5 以下 | 出す・読む |

- 合図を出す：自分の番でないとき、手札に近いカード（10戻しか、飛ばす数 2〜3 以下）がある山に「出さないで」、少し近い（6〜7 以下）山に「大事」を、近い順に2つまで置く。人が出している最中にも置き直す
- 合図を読む：仲間の合図がある山に大きく飛ばして出すときは、飛ばす数に応じた重みを足して避ける
- 1人のときは仲間がいないので、続けて出す基準を飛ばす数 1 以下に下げる

CPU だけで遊ばせたときの残りの枚数（`npm run cpu-match -w games/the-game -- 300 3 all`、3人・300試合）：

| 強さ | 平均 | 中央 | 出し切り | 10枚以下 |
|---|---|---|---|---|
| やさしい | 17.4 | 15 | 2.3% | 39.3% |
| ふつう | 8.8 | 6 | 7.3% | 73.3% |
| つよい | 5.7 | 3 | 19.7% | 85.7% |

## 開発

```bash
npm test -w games/the-game                         # ルール・再現・CPU・ヒント・オンライン・PWA のテスト
npm run cpu-match -w games/the-game -- 300 3 all   # CPU だけで遊ばせ、残りの枚数の分布を出す（試合数・人数・強さ）
node packages/sound/scripts/sync.mjs the-game      # 音のエンジンの同期（web-games の直下で）
```

- `public/js/game.js`：ルールと状態。操作は `applyCommand(seat, command)`（`play`・`end`・`signal`）だけで、受け付けた操作を記録し、`Game.replay` で同じ局面を作り直せる。乱数はシード付き（`random.js`）
- `public/js/cpu.js`：CPU とヒント（`suggest`）。ゲームの乱数は使わず、状態だけから手を決める
- `public/js/game-view.js`：見る人ごとのビュー。ほかの人の手札・山札の並び・シードは入れない
- `public/js/game-controller.js`：ローカル対戦（保存・続きから・待った・CPU の間合い）
- `public/js/main.js`：画面と入力。`window.__app` で状態を見られる
- `scripts/cpu-match.mjs`：CPU だけの試合を回し、止まらないことと残りの分布を確かめる

## オンライン対戦

- `server/src/game-definition.js`（netplay-kit のゲームの定義）と `server/src/handler.js`（`keyPrefix: 'the-game'`）。部屋には参加者・シード・操作の記録だけを保存する
- 2〜5人。ロビーで CPU を足せ、CPU の強さを選べる。部屋はすべて公開で、部屋番号は出さない（共通のロビー）
- 対戦中に部屋を出た人の席は CPU が引き継ぐ（`isCPU` を保存するので、部屋を読み直しても CPU のまま）
- オンラインでは、ヒントと待ったを出さない
- 接続先は `public/js/online-config.js`。デプロイ前なので `DEPLOYED_SERVER_URL` は空（公開ページでは「オンラインで遊ぶ」を出さない）。手元では web-games の直下で `npm run dev:online`

## 決めたこと

- 最初の番は席0（人）から。原作では、手札を見て話し合って決める
- 原作の「言葉での合図」は、山ごとの2種類の合図にした。数字や「すごく近い」のような程度は伝えられない
- 待ったは、今の番に出したカードだけ戻せる（引いたカードを見てから戻すと、山札の並びを知ってしまうため）
