# チケット・トゥ・ライド

北米の都市を線路でつなぎ、目的地を達成して点を競うゲーム「チケット・トゥ・ライド（Ticket to Ride、Days of Wonder 2004）」の基本ゲーム（北米の地図）を、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち向けで、地図は拡大やスクロールなしで全体が収まる。ホーム画面に置くと、オフラインでも遊べる。

地図・列車カード・アイコンの絵は、すべて SVG で自作している（公式の画像は使っていない）。都市の位置は、実際の地形をもとに自分で決めた。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 列車カード110枚（赤・橙・黄・緑・青・桃・白・黒が12枚ずつと、機関車14枚）。はじめに4枚ずつ配り、5枚を表にする
- 目的地カード30枚。はじめに3枚ずつ配り、2枚以上を残す（全員が同時に選ぶ）。戻した目的地は山の下へ
- 列車は1人45両
- 手番では、次の3つから1つ
  - カードを2枚引く：表の5枚か山から。表の機関車を取るなら、それ1枚で終わり。2枚目に表の機関車は取れない（山から引いた機関車はよい）。表に機関車が3枚以上並んだら、5枚とも捨てて並べ直す
  - 路線を1本引く：長さの数だけ、路線と同じ色のカードを払う。灰色の路線はどの色でも1色にそろえる。機関車はどの色にもなる
  - 目的地を3枚引き、1枚以上を残す（山が3枚未満なら、あるだけ引く）
- 複線の2本を、1人で両方は引けない。2〜3人のときは、片方が引かれたら、もう片方は使えない
- 山がなくなったら、捨て札を切り直す。山も捨て札もなければ、カードは引けない（路線か目的地を選ぶ）
- 誰かの列車が手番の終わりに2両以下になったら、その人を含めて全員が1回ずつ手番をして終わる
- 得点
  - 路線：長さ 1・2・3・4・5・6 で 1・2・4・7・10・15点（引いたときに入る）
  - 目的地：2都市が自分の線路でつながれば足し、つながらなければ引く
  - 一番長く続いた線路（同じ路線は2度通らない。都市は何度通ってもよい）の人に10点。同じ長さなら全員
- 同点なら、達成した目的地の多い人。それも同じなら、一番長い線路の10点を取った人

### 地図と目的地

- 都市36・路線100本（2都市の組で78。うち複線22組）。8色の路線は長さの合計がどれも27両、灰色は93両。全部で309両
- 目的地30枚（点の合計 349）。一覧は `public/js/map.js`

### 資料と、資料で分からない点の決め方

ルールは公式のルールブック（Days of Wonder、2015年の英語版 PDF `tt_rules_2015_en.pdf`）を読んで合わせた。地図と目的地は、公開されている3つの実装のデータと照らし合わせた。

- 路線の組（78）は、fraziern/ttr-graph（`archive/all_routes.json`）と一致した
- 路線の長さと複線は、rtealwitter/Ticket-to-Ride（`graph/edge_lengths.csv`・`graph/is_double.csv`）と全部一致した
- 路線の色は、willdzeng/ticket_to_ride（`game/board.py`）と照らした。この実装は路線が93本しかなく、長さの誤りもある（ロサンゼルス–フェニックスを黒2、デンバー–フェニックスを白4、チャールストン–ローリーを1 としている）。色は、長さの誤りのない路線ではすべて一致した。8色の路線の長さがどれも27両になる（盤の色の釣り合い）ことも確かめた
- 目的地30枚と点は、willdzeng/ticket_to_ride（`game/cards.py`）と全部一致した
- さらに、thoun/tickettoride（Board Game Arena の版の実装。`modules/maps/usa`）と Rob217/TicketToRideAnalysis（`data/USA`）のデータとも照らし、路線100本の都市・長さ・色・複線と、目的地30枚の点が、すべて一致した

自分で決めた点：

- 引けるカードも、払える路線も、目的地の山もない手番は、見送れる
- 表に機関車が3枚以上並び続けるとき（山と捨て札の残りで直せないとき）は、そのまま並べる
- 引いた目的地が残す枚数（はじめは2枚、途中は1枚）に満たないときは、その全部を残す
- 目的地の点は、終わるまで本人にしか見えない（ほかの人の画面では、路線の点だけが見える）
- 同点がさらに続くときは、全員の勝ち

### 画面の操作

- 地図の路線を押すと、押した位置に一番近い、まだ引かれていない路線を選ぶ。下に払い方（色と機関車の枚数）が出るので、選んで「引く」
- 表のカードと山（右端）は、押すとすぐ引く
- 目的地は、下の「目的地を引く」で引く（押し間違いで手番を使わないよう、地図とは離してある）
- 地図の黄色い輪は、まだつないでいない目的地の都市、緑の輪はつないだ目的地の都市。右下のボタンで、自分の目的地の一覧を見られる
- 上の帯は、各人の残りの列車と路線の点（4人以上のときは名前を省く）。押すと記録が見られる
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分のビュー（自分の手札と目的地、全員の路線、表のカード）だけを見て判断し、ほかの人の手札・目的地や山の並びはのぞかない（`public/js/cpu-player.js`）。

- 目的地ごとに、今引ける路線での一番短い道（自分の路線は0両、ほかの人の路線は通れない）を求め、点の高い目的地から順に、前の道を0両と見て重ねる。その道の路線が「引きたい路線」
- 引きたい路線を払えるなら長いものから引き、払えなければ足りない色のカードを表から取る（合う色がなければ山から）
- 目的地を選ぶときは、目的地の点と道の路線の点から、かかる手番（カード集めと、引く手番）を差し引いて比べる。終わりまでの手番を超える計画は低く見る
- 目的地を全部つないだら、まだ早い時期（列車28両以上・終わりまで24手番以上）なら新しい目的地を引く。そうでなければ、長い路線を狙って点を稼ぐ
- 終わりが近い（最後の1周、自分の列車が8両以下、ほかの人の列車が5両以下）ときは、払える一番長い路線を引いて列車を使い切りにいく
- やさしいは、目的地を最少の枚数だけ残し、カードは山から引くことが多く、途中で目的地を引かず、長い路線を狙ってカードを集めることもしない

```bash
# 試合数・人数・強さ（normal・easy・mixed）。mixed は席ごとに強さを交互に変えて比べる
node scripts/cpu-match.mjs 200 2 mixed
```

| 対戦（各200試合） | ふつう | やさしい |
|---|---|---|
| 2人：平均点 | 98.3点 | 92.0点 |
| 2人：勝ち数 | 122勝（61%） | 78勝 |
| 4人（ふつう2・やさしい2）：平均点 | 92.6点 | 84.9点 |
| 4人：勝った試合 | 133試合（66.5%） | 67試合 |

ふつうの内訳の平均（2人）は、路線 70.7・目的地 +25.6 −3.8・最長 5.8。目的地は平均2.4枚持ち、2.2枚を達成する。CPU は目的地を控えめに持つので、目的地を多くつなげる人なら勝てる強さ。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/map.js` | 都市・路線・目的地のデータと、カードの枚数・路線の点 |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。つながりと一番長い線路の計算 |
| `public/js/game-view.js` | 席ごとのビュー（ほかの人の手札・目的地と、山の並びを隠す） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js`・`help.js` | 画面・絵（地図・カード）・遊び方 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と平均点・勝ち数 |

### オンライン対戦を入れるとき

netplay-kit の `scripts/sync.mjs` で部屋の処理を写し、`server/src/game-definition.js` を `createHandler` と `startDevServer` に渡す。部屋には参加者・シード・操作の記録だけを保存し、操作のたびに記録から再現する。手番制だが、はじめの目的地は全員が同時に選ぶので、操作を待っている人は `game.actors()` で見る。手札と目的地は、席ごとのビュー（`createGameView`）で本人の分だけにする（見ている人には誰の分も見せない）。
