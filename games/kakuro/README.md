# カックロ

黒いマスに書かれた和になるように、白いマスへ 1〜9 の数字を入れる論理パズル（クロスサム）。どの問題も答えが1つに決まり、理屈だけで解ける。

## 遊び方

- 白いマスに 1〜9 の数字を入れる。黒いマスの斜線の右上の数字は、右へ続く白いマスの和。左下の数字は、下へ続く白いマスの和
- 和を作る続きの中では、同じ数字を2回使えない。たとえば 2マスで和が 3 なら 1 と 2、3マスで和が 24 なら 7・8・9 だけ
- 白いマスを押して選び、下の数字のボタンで入れる（キーボードの数字・矢印でもよい）。同じ数字をもう一度押すと消える。「消す」で選んだマスを消す
- 「メモ」にすると、候補の数字を小さく書いておける。数字を書くと、同じ続きのメモからその数字が消える
- 選んだマスのよこ・たての続きが薄く色付き、その和の数字が明るくなる。和が合った続きの和は薄くなる。同じ続きに同じ数字がある・和が合わない・和を超えた続きの数字は赤くなる
- 大きさ：やさしい 6×6・ふつう 8×8・むずかしい 9×9（どれも上の1行と左の1列は和の黒いマス）
- **フリープレイ**：難しさを選んで、1問ずつ解く。時間は計るが、ヒントの加算はない
- **今日のパズル**：日付で決まる3問（やさしい・ふつう・むずかしい）。誰が開いても同じ問題になる。合計の時間（ヒントは1回15秒の加算）を、日ごとに記録する
- **タイムアタック**：難しさと問題の数（3・5）を選び、続けて解いた合計の時間を競う。設定ごとに自己ベストを記録する。CPU のライバルを付けると、ライバルの進み具合が並んで出る
- **オンライン**：同じ問題の組を全員で解く早解きレース。合計の時間（ヒント15秒・まちがった盤面30秒の加算）の短い順に順位が付く
- ヒント（電球）は、和の組み合わせから1つに決まるマスを光らせて選び、その理由を出す（よこ・たての和の組み合わせから、そのマスに入る数字が1つだけ・その続きに必ず入る数字を入れられるマスが1つだけ）。まちがった数字があれば、先にそれを消すよう示す。待った（1手戻す）と、最初からやり直すこともできる
- **記録**：タイトル画面の「記録」に、フリーの解いた数と最短（ヒントなし）、タイムアタックの自己ベスト、今日のパズルを解いた日数と連続、オンラインの対戦の数と1位の数が出る（端末に保存）。ログインしていれば、共通の利用者ごとの記録（netplay-kit の user-stats）にも送る

## CPU

- CPU は、実際にヒントを当て続けて問題を解き、その手数から解き終わる時間を決める（`js/cpu-player.js`）
  - 時間 = (4秒 + 手数 × 秒数) × 強さの倍率（やさしい 1.8・ふつう 1・つよい 0.55）× ばらつき（0.8〜1.2倍）。1手は数字1つで、秒数は種類の `cpuSecondsPerStep`
  - ばらつきは、渡された乱数（オンラインはサーバーの乱数、タイムアタックは組のシードから作った乱数）で決める
- タイムアタックのライバルと、オンラインの CPU（ロビーで足す。強さはロビーの設定）に使う。オンラインで部屋を出た人の席も、その時点から CPU が解く
- `npm run cpu-match` で、難しさごとに、ヒントで最後まで解けること・強さごとの時間・強さどうしの勝率を確かめる

## オンライン対戦

- netplay-kit の共通のロビー（公開の部屋）から遊ぶ。2〜4人（CPU を足せる）。ロビーで難しさ・問題の数・CPU の強さを選ぶ
- サーバーが問題の組を作り、問題（和）だけを配る。シードはビューにも保存にも入れない（問題は見えてよいので、端末で答えを計算されるのは割り切る）
- 端末で解けたら、その盤面を送る。サーバーは種類の `check` で確かめ、解いた時間をサーバーの時刻で記録する（始まる前の 3.5 秒のカウントダウン中に送られたものは 0 秒として数える）
- 人（退出していない人）が全員解き終わるか、30分たったら終わる
- 定義は `server/src/game-definition.js`（中身は puzzle-kit の `public/js/race-definition.js`）

## 開発

このゲームは、パズルのゲームの共通部品 `packages/puzzle-kit` の写し（画面・遊びのロジック・オンラインの定義）に、このゲームの種類を載せたもの。共通の部分は `packages/puzzle-kit` で直して同期する（写しを直接直さない）。手順は `packages/puzzle-kit/README.md`。

```bash
npm test -w games/kakuro          # 種類の共通の検査・ロジック・記録の再現・オンライン・PWA・記録
npm run cpu-match -w games/kakuro # CPU の強さと、ヒントで解けるかの確かめ
npm run sw -w games/kakuro        # sw.js の先読みの一覧を作り直す
node scripts/build-pool.mjs 120   # games/kakuro で。問題の組（pool.js）を作り直す（1分半ほど）。直したら npm run sw も
node packages/puzzle-kit/scripts/sync.mjs kakuro   # web-games の直下で。puzzle-kit を同期する（check で確かめる）
npm run dev:online                # web-games の直下で。手元のオンライン対戦のサーバー（ws://localhost:8787）
```

画面は `public/` を静的に配れば動く（`python3 -m http.server` など。8080 は避ける）。`?play&difficulty=hard&seed=3` で、その問題のフリープレイがすぐ始まる。

| ファイル | 中身 |
|---|---|
| `public/js/game.js` | このゲームの設定（名前・種類・曲・保存の名前の頭） |
| `public/js/puzzles/kakuro/` | 種類のロジック（`logic.js`）・問題の組（`pool.js`）・画面（`render.js`）・入口（`index.js`） |
| `scripts/build-pool.mjs` | 問題の組を作り、1問ずつ解が1つであることを確かめて `pool.js` に書く |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/sound/bgm.js` | BGM「和の小道」 |
| `public/css/theme.css` | このゲームの色 |
| `public/js/main.js` ほか | puzzle-kit の写し（`puzzle-kit.lock.json` に一覧） |

記録：1人用の遊びは、操作（入力・ヒント・待った・最初から）を、遊び始めてからの時間（止めていた間は数えない）と一緒に記録する。`replay(setup, commands)` で同じ局面になり、「続きから」もこれで戻す。

## 決めたこと

- **問題は前もって作った組から選ぶ**。解が1つのカックロをその場で作ると、9×9 では1秒を超えることがあり、作れないこともあった（パズル集の版では、むずかしいの多くが作れなかった）。そこで `scripts/build-pool.mjs` が難しさごとに 120 問を作り、1問ずつ、打ち切りなしで解を数えて1つと確かめ、`pool.js` に並べた。遊ぶときは、シードで1問を選び、半分の確率でたてとよこを入れかえる（入れかえても解は1つのまま）。難しさごとに 240 通りになる
- 問題の作り方：形（外の1行・1列は黒、中は点対称に黒を置き、1マスの続きはなくし、長すぎる続きは切る）を作って数字を埋め、和を書く。理屈（和の組み合わせで候補をしぼる・一つに決まるマスを探す）でしぼったあとの候補の数の合計が 0 になるまで、数字を1つずつ変えていく（焼きなまし）。理屈だけで解ける問題だけを入れるので、ヒントも理屈で出せる
- 続きの長さの上限は、やさしい 4・ふつう 5・むずかしい 6 マス。黒いマスが片寄って固まらないように、中のどの行・列にも白いマスを、やさしい 2・ふつう 3・むずかしい 4 つ以上置く。白いマスは、やさしい 15〜18・ふつう 23〜37・むずかしい 38〜50
- 今日のパズルは、やさしい・ふつう・むずかしいを1問ずつにした（1種類のゲームなので、難しさで変化を付ける）
- ご褒美や集める要素は入れない
