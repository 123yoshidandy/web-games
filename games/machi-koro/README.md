# 街コロ

サイコロを振って施設からコインを集め、ランドマーク4つの完成を競うゲーム「街コロ（Machi Koro、菅沼正夫、グランディング 2012）」の基本ゲーム（拡張なし）を、ブラウザで CPU と遊べるようにしたもの。2〜4人（あなた＋CPU 1〜3人）。スマホの縦持ち向けで、市場の15種と自分の街が、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

施設とランドマークの絵、アイコンは、すべて SVG で自作している（公式の画像は使っていない）。カードの名前は日本語版の名前のまま。効果の文は自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- はじめは各自、麦畑とパン屋を1つずつと、3コイン。ランドマーク4つは工事中
- 市場には15種の施設を全部並べる（紫は4枚ずつ、ほかは6枚ずつ。合わせて84枚）
- 手番
  1. サイコロを振る。駅があれば1個か2個を選べる（2個なら合計）。電波塔があれば、1回だけ振り直せる
  2. 出た目の施設が働く
  3. 施設を1つ建てるか、ランドマークを1つ完成させる（建てなくてもよい）
- 施設の色
  - 青：誰の番でも、銀行から
  - 緑：自分の番だけ、銀行から
  - 赤：ほかの人が出したら、その人から受け取る
  - 紫：自分の番だけ、ほかの人から。同じ種類は1人1つまで
- 同じ目で色の違う施設が働くときは、赤 → 緑と青 → 紫の順。赤が何人もいるときは、振った人から反時計回り（手番と逆の順）に払う。払えない分は免除
- 遊園地があって、2個でゾロ目を出したら、この番のあとにもう1回自分の番
- ランドマーク4つを最初に完成させた人の勝ち（完成させた時点で終わる）

### 資料と、資料で分からない点の決め方

ルールは、公式のルールブック（IDW Games の英語版。構成・準備・手番・解決の順・払えないとき・紫の制限・ランドマーク）と、日本語版のカードを紹介した記事（カード名・費用・出目・効果）を照らし合わせて決めた。

- 英語版のルールブックの構成（施設72枚・大施設12枚・最初の施設8枚・ランドマーク16枚）から、紫以外は6枚ずつ、紫は4枚ずつとした
- スタジアム・テレビ局・ビジネスセンターの費用（6・7・8）は、ルールブックの文にはなく（カードの絵にだけ書かれている）、日本語の紹介記事と英語のカードの一覧で一致したものを使った。まとめサイトの中には3つとも6としているものがあったが、採らなかった
- 解決の順（赤 → 緑と青 → 紫）、赤の支払いが反時計回りなこと、払えない分は免除で受け取る側にも補いがないことは、ルールブックの例（コイン0の人がカフェに払わずに済み、そのあとパン屋で受け取る／3コインしかない人がカフェ2つと3つの持ち主に払う）をそのままテストにした

自分で決めた点：

- 銀行のコインは尽きない（ルールブックでもコインの数で止める決まりはない）
- 電波塔の振り直しは、最初と同じ個数で振り、振り直した目に従う
- 遊園地は、振った時点で完成していれば働く。ゾロ目を出した番に遊園地を完成させても、もう1回はない
- 1人が紫を複数持つときは、スタジアム → テレビ局 → ビジネスセンターの順に働く。スタジアムは、振った人から反時計回りの順に集める
- テレビ局は、ほかの人が1人だけ（2人で遊ぶとき）なら、自動でその人から取る。コインのない人も選べる
- ビジネスセンターの交換は任意（日本語のカードの「交換できる」から）。紫どうしは交換できず、最初の麦畑とパン屋は交換できる
- 「紫は1人1枚まで」は、同じ種類を1人1つまで、と読んだ（ルールブックの「同じ種類の大施設は2つ目を建てられない」。3種を1つずつ持つことはできる）
- 市場は、基本ゲームの決まりどおり15種を全部並べる（のちの版の「10種だけ並べる」市場は入れていない）

### 画面の操作

- 自分の番の振る前は、下のボタンで振る（駅があれば「1個」と「2個」）。電波塔があれば、振ったあとに「振り直す」か「このまま」
- 建てる段階では、建てられるカードとランドマークが金色に光る。押すと説明が出るので「建てる」。建てないときは「建てない」
- テレビ局とビジネスセンターが働いたら、選ぶ画面が開く（閉じても下のボタンで開き直せる）
- 上の帯は、ほかの人のコインとランドマーク（4つの印）。押すとその人の街が見られる。今の番の人は金色の枠
- サイコロの横は、最後の出来事。押すと記録が見られる。コインの出入りは「+3」「−1」で浮かび、自分の施設のうち働いたものは白く光る
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。街コロには隠す情報がないので、CPU はゲームの状態をそのまま見て決める。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう：出目の確率から、1周（全員が1回ずつ振る）あたりに入るコインの見込みを計算する。自分の番の青と緑と紫、ほかの人の番の青と赤、自分が振ったときに払う赤を数える。そのうえで「（残りのランドマークの費用 − 手持ち）÷ 1周の見込み」（勝つまでにかかる周の数）が一番小さくなる手を選ぶ。施設は費用で残りが増えるが見込みが上がり、ランドマークは残りが減らずに見込みが上がる（駅で2個を選べる、モール、遊園地、電波塔）。サイコロの個数、振り直し、ビジネスセンターの交換も同じ見込みで決め、テレビ局はコインの一番多い人から取る
- やさしい：ランドマークが建てられれば一番安いものを建て、そうでなければ買える施設から安いものほど選びやすく選ぶ（4回に1回は見送る）。2個で振るかは、持っている施設の出目の多い側で決め、何も入らなかったときだけ振り直す。交換はしない

```bash
# 試合数・人数・席ごとの強さ（easy・normal）。最初の番は試合ごとに入れ替える
node scripts/cpu-match.mjs 1000 2 easy,normal
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 手番の数の平均 |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 1000 | 96.0% | 4.0% | 31.7 |
| 2人（ふつう・やさしい） | 1000 | 97.4% | 2.6% | 31.3 |
| 3人（やさしい・ふつう・やさしい） | 500 | 42.4% | 27.2%・30.4% | 56.4 |
| 4人（やさしい・ふつう・やさしい・ふつう） | 500 | 29.6%・28.6% | 20.8%・21.0% | 67.2 |
| 2人（ふつう・ふつう） | 1000 | 52.6%・47.4% | — | 28.8 |

2人なら、ふつうはやさしいにほぼ負けない。3〜4人では、サイコロの運とほかの人の赤の施設の影響が大きく、差は縮む（同じ強さなら 33%・25% が五分）。どの組み合わせでも、止まった試合はない。

自分の番に操作の欄の電球（ヒント）を押すと、ふつうの CPU が選ぶ手を光らせる（振るサイコロの数・振り直すか・建てる施設・建てない。テレビ局とビジネスセンターは、相手や取り替えを選んでおく）。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/cards.js` | 施設とランドマークのデータ（費用・出目・効果・枚数） |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（全員の盤面と、その席の番でできること） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率 |

テスト（`test/`）：

- `game.test.js`：準備、振る（駅・電波塔）、色ごとの働き、赤の反時計回りと払えないとき（ルールブックの例）、ショッピングモール、工場と市場、紫（スタジアム・テレビ局・ビジネスセンターとその順）、建てる（売り切れ・紫の2つ目・コイン不足）、遊園地、勝ち、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（JSON を通しても、途中からでも）、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、場面ごとの判断
- `game-definition.test.js`：オンライン対戦の定義（受け付け・断る・保存と再現・CPU・抜けた人）とビュー
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'machi-koro' })`。web-games の1つのスタックから `?game=machi-koro` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
