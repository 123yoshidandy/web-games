# フォーセール

競りで物件を買い、それを売って小切手に換えるカードゲーム「フォーセール（For Sale）」を、ブラウザで CPU と遊べるようにしたもの。3〜6人（あなた＋CPU 2〜5人）。スマホの縦持ち向け（横にすると2列に組み替える）。ホーム画面に置くと、オフラインでも遊べる。

絵（物件の建物・小切手・コイン・アイコン）は、すべて SVG で自作している。

## 遊び方

金額の単位は千ドル（コイン1枚が $1,000）。

- 物件は1〜30、小切手は 0 と 2〜15 が2枚ずつ
- 3〜4人はコイン18枚、5〜6人は14枚で始める。3人なら物件と小切手を6枚ずつ、4人なら2枚ずつ、伏せて除く
- 前半（競り）：人数分の物件を並べる。手番の人は「上げる」か「降りる」
  - 上げる：今の最高額より多いコインを出す（それまでに出した分を含めた合計で言う）
  - 降りる：残っている中で一番安い物件を取り、出したコインの半分（切り捨て）が戻る
  - 最後に残った人は、一番高い物件を取り、出したコインを全部払う。その人が次の競りを始める
- 後半（売り）：人数分の小切手を並べ、全員が同時に物件を1枚出す。高い物件から順に、高い小切手をもらう
- 小切手の合計＋残りのコインが一番多い人の勝ち

### 版によって違うところ（ボードゲームアリーナに合わせた）

- コインと除く枚数は、最初の版とボードゲームアリーナの値にした。IELLO 版（2020年）のルールブックでは、3人28枚・4人21枚・5人16枚・6人14枚で、除くのは4人のときの2枚ずつだけ
- 同点なら、残りのコインが多い人の勝ち。それでも同点なら、競りで手に入れた一番高い物件の人の勝ち（ボードゲームアリーナの決まり。IELLO 版は、コインでも決まらなければ勝ちを分け合う）

### ルールブックに書かれていないので決めたこと

- 物件・コイン・もらった小切手は、全員に見せる。どれも公開の場で動くので、覚えていれば分かる情報のため。後半に出す物件だけは、全員がそろうまで伏せる
- コインが足りず上げられないときは、少し間を置いて自動で降りる
- 終わったら、除かれていた物件と小切手を見せる

### 画面

- 競りでは、並んだ物件・最高額と入札した人・各自が出しているコインを出す。降りた人が取った物件には名前が付く
- 降りるボタンには、降りたら取る物件を出す。入札額は −／＋ で決める
- 売りでは、全員の物件を、もらう小切手の下に高い順で並べて公開してから、小切手が持ち主へ飛ぶ
- 途中でホームに戻っても、「続きから」で再開できる

## CPU

自分から見える情報だけ（山札の並び、除いたカード、後半にほかの人が先に出した物件は見ない）で選ぶ。物件の値打ちは、売りでもらえそうな小切手の額（物件の数のおよそ半分）と見る。

- 競り：一番高い物件と一番安い物件の値打ちの差に、係数を掛けた額まで上げ、超えたら降りる
- 売り：ほかの人の残りの物件から、自分の物件が何番目になりそうかを見積もる。その順位でもらえそうな小切手から、その物件を後に残したときの値打ちを引いた分が一番大きい物件を出す

| 強さ | 中身 |
|---|---|
| やさしい | 値打ちの差を大きく見て払いすぎる。売りの判断の揺れと誤りが大きい |
| ふつう | 上の見積もりに、揺れとときどきの誤りを混ぜる |

CPU 同士の対戦（各 1000 試合）：

| 対戦 | 勝率 | 公平なら |
|---|---|---|
| 3人：ふつう1 対 やさしい2 | ふつう 57.2% | 33.3% |
| 4人：ふつう1 対 やさしい3 | ふつう 44.6% | 25% |
| 5人：ふつう1 対 やさしい4 | ふつう 36.1% | 20% |
| 6人：ふつう1 対 やさしい5 | ふつう 26.9% | 16.7% |
| 4人：比較用の揺れのない CPU 1 対 ふつう3 | 比較用 29.1% | 25% |

```bash
# 試合数・人数・席ごとの強さ（easy・normal・strong は揺れのない比較用・random はでたらめ）
node scripts/cpu-match.mjs 1000 4 normal,easy,easy,easy
```

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/game.js` | ルール。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる。イベントには、その時点の全員に見せてよい状態を付ける |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js` | 画面。届いたイベントを順に再生して見せる |
| `public/js/art.js`・`animator.js` | 絵と動き |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。3〜6人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'for-sale' })`。web-games の1つのスタックから `?game=for-sale` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
