# クー

役割を名乗り、はったりを見抜いて、最後の1人を目指すカードゲーム「クー（Coup、Rikki Tahta、La Mame Games 2012）」の基本ゲーム（拡張・改革派なし）を、ブラウザで CPU と遊べるようにしたもの。2〜6人（あなた＋CPU 1〜5人）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

役割の絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方（基本ゲーム）

- 役割5種（公爵・暗殺者・大使・船長・伯爵夫人）×3枚の15枚。各自2枚を伏せて持ち（影響力）、2コイン。残りは山
- 2人のときは、最初の人だけ1コイン
- 手番では、行動を1つ。10コイン以上で手番を始めたら、クーしかできない

| 行動 | 名乗る役割 | 効果 | ブロック |
|---|---|---|---|
| 収入 | — | 1コイン | できない |
| 援助 | — | 2コイン | 公爵（だれでも） |
| クー | — | 7コインを払い、1人が影響力を1つ失う | できない |
| 税 | 公爵 | 3コイン | — |
| 暗殺 | 暗殺者 | 3コインを払い、1人が影響力を1つ失う | 伯爵夫人（対象） |
| 強奪 | 船長 | 1人から2コイン（1コインなら1） | 船長か大使（対象） |
| 交換 | 大使 | 山から2枚引き、手札と合わせて同じ枚数を残し、2枚戻す | — |

- 役割は、持っていなくても名乗れる（はったり）。名乗り（行動もブロックも）には、ほかの全員がチャレンジできる
- チャレンジ：名乗った人がその役割を持っていれば見せ、チャレンジした人が影響力を1つ失う。見せた札は山に戻して切り、1枚引き直す。持っていなければ、名乗った人が影響力を1つ失う
  - 行動へのチャレンジが通ったら、行動は失敗し、払ったコインは戻る
  - ブロックへのチャレンジが通ったら、ブロックは無効になり、行動が通る
- ブロックされた行動は失敗し、払ったコインは戻らない
- 1回の暗殺で2枚失うことがある：暗殺者へのチャレンジに負けた（チャレンジの分と暗殺の分）、伯爵夫人のはったりがばれた（ブロックの分と暗殺の分）
- 影響力を失うときは、どの札を表にするかを本人が選ぶ。2枚とも失ったら脱落。最後の1人が勝ち

### 資料と、資料で分からない点の決め方

ルールは、公式のルールブック（英語版。準備・行動・ブロック・チャレンジ・2人のとき）を読んで合わせた。

- 2人のとき：ルールブックの本則は「最初の人は1コインで始める」。セット（1種ずつ5枚）を配って1枚を選ぶ準備は「変種」と書かれているので、入れていない
- 行動へのチャレンジが通ったら払ったコインが戻り、ブロックされたら戻らないことは、ルールブックのとおり
- ルールブックでは、チャレンジされた人は持っていても見せずに負けることを選べる。この版では、持っていれば必ず見せる（見せずに負けるのが得になる場面はほぼないため）

自分で決めた点：

- **チャレンジとブロックは、順に聞く。** 行動を名乗ったら、まず本人以外の全員にチャレンジするかを聞く。全員が通したら、ブロックできる人に聞く。ブロックされたら、ブロックした人以外の全員に、ブロックへのチャレンジを聞く。答えは届いた順に処理し、最初のチャレンジ（援助のブロックは最初のブロック）が通る
- CPU との対戦では、人が答え待ちに入っているあいだ、CPU は答えない。人が答えてから CPU が答える（CPU が先にチャレンジして、人の答える機会がなくならないように）。オンライン対戦の定義（`server/src/game-definition.js`）では、まだ届いた順のまま
- **聞く相手はルールだけで決め、手札で変えない。** 援助のブロックは本人以外の全員、暗殺と強奪のブロックは対象の人。札を持っていない人にも聞く（持っている人にだけ聞くと、だれに聞いているかで手札が分かってしまうため）
- 対象が途中で脱落したら（暗殺者へのチャレンジに負けて最後の札を失った、など）、その行動は何も起きない。暗殺のコインは払ったまま
- 銀行のコインは尽きない（ルールブックの50枚で足りなくなることは、ふつうない）
- 交換で手札が1枚なら、3枚から1枚を残す

### 画面の操作

- 自分の番は、下の7つのボタンから行動を選ぶ。役割の行動は、その役割の色。払えない行動は押せない。暗殺・強奪・クーは、押したあとに上の相手の欄を押して選ぶ（もう一度押すとやめる）
- 名乗りに答える番になると、ボタンが「チャレンジ／通す」や「〇〇でブロック／通す」に変わる
- 影響力を失うときは、赤く光る自分の札を押して選ぶ。交換は、残す札を選ぶ画面が開く
- 相手の欄：コイン、伏せた札（裏）と失った札（色と頭の1文字）、名乗った役割。今の番の人は金色の枠、答えを考えている人には「…」
- 真ん中に今の行動とブロック、右上のボタンで記録が見られる。チャレンジの結果は下に短く出る
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（自分の手札、全員のコインと失った札、名乗りの履歴）だけを見て決め、ほかの人の手札や山はのぞかない。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

**相手が役割を持つ見込み**（嘘を見抜く）

- 役割ごとに、見えている枚数（自分の手札と、全員の失った札）を数える。3枚とも見えている役割を名乗ったら、確実な嘘
- そうでなければ、見えていない札（ほかの人の手札と山）から、その人の手札の枚数だけ引いて当たる確率を出す
- 前にも同じ役割を名乗っていて、名乗った役割の種類が手札の枚数以下なら、見込みを上げる。手札の枚数より多くの種類を名乗っていれば（どれかは嘘）、見込みを下げる。嘘がばれたことがあれば下げる

**ふつう**

- 行動：7コイン以上ならクー（札とコインの多い相手）。暗殺者を持っていて3コインあれば、伯爵夫人を持っていなさそうな相手を暗殺。公爵があれば税、船長があれば強奪。持っていなくても、税（手札2枚なら4割、1枚なら2割）と強奪のはったりをする。だれかが公爵らしければ援助をやめて収入
- 強奪は、船長か大使を持っていそうな相手と、最近ブロックしてきた相手からはしない（ブロックし合って試合が止まるのを防ぐ）
- チャレンジ：確実な嘘には必ず。そうでなければ、見込みが低いときだけ。自分が損をする名乗り（自分への暗殺・強奪、自分の行動へのブロック）には厳しく、最後の1枚を狙う暗殺で伯爵夫人がないときは、見込みが5割を切ればチャレンジする。手札が1枚のときは慎重にする
- ブロック：持っている役割でブロックする。持っていなくても、最後の1枚への暗殺は9割で伯爵夫人のはったり、2枚なら3割。強奪と援助にも、ときどきはったりでブロックする
- 失う札・交換：価値（公爵 > 暗殺者 > 船長 > 伯爵夫人 > 大使）の低いものから手放す。同じ役割の2枚目は低く見る

**やさしい**：はったりはほとんどしない（税で6%）。チャレンジは、確実な嘘のときに7割と、ほかはまれに当てずっぽう。ブロックは持っている役割だけ（最後の1枚への暗殺だけ、5割で伯爵夫人のはったり）。

```bash
# 試合数・人数・席ごとの強さ（easy・normal）。最初の番は試合ごとに入れ替える
node scripts/cpu-match.mjs 1000 2 easy,normal
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 手番の数の平均 |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 3000 | 68.8% | 31.2% | 12.1 |
| 2人（ふつう・やさしい） | 3000 | 66.2% | 33.8% | 12.1 |
| 3人（やさしい・ふつう・やさしい） | 1000 | 47.7% | 25.5%・26.8% | 22.0 |
| 4人（やさしい・ふつう・やさしい・ふつう） | 1000 | 29.7%・32.8% | 18.0%・19.5% | 30.2 |
| 6人（やさしいとふつうを交互） | 1000 | 17.9%・21.2%・23.6% | 12.1%・12.4%・12.8% | 44.6 |
| 2人（ふつう・ふつう） | 3000 | 48.6%・51.4% | — | 9.1 |

チャレンジの当たり（2人・1000試合）：ふつうどうしは 1182回のうち 722回（61%）で嘘を見抜いた。やさしい対ふつうでは 515回のうち 181回。どの組み合わせでも、止まった試合はない。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/roles.js` | 役割と行動のデータ |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（ほかの人の手札、山、交換で引いた札、引き直した札を隠す） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `server/src/handler.js` | オンライン対戦のサーバーの入口（AWS Lambda） |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/netplay/` | netplay-kit のクライアントとロビーの画面の写し（同期で置く。手で直さない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率・チャレンジの数 |

テスト（`test/`）：

- `game.test.js`：準備（2人のとき）、各行動、10コインでクー、チャレンジ（嘘と本当、コインの返し、引き直し）、ブロックとそのチャレンジ、暗殺で2枚失う流れ、聞く相手が手札で変わらないこと、失う札の選び方、勝ち、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず札が15枚のままで再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数（2〜6）・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、確実な嘘へのチャレンジ、名乗りの履歴による見込み、場面ごとの判断
- `game-definition.test.js`：オンライン対戦の定義と、ビューで手札・山・交換で引いた札・引き直した札・シードが漏れないこと
- `game-controller.test.js`：CPU との対戦で、人が答え待ちのあいだ CPU が答えないこと
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜6人で、足りない席は CPU で埋められる。ほかの人の伏せ札と山札の並びはビューに入れない。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'coup' })`。web-games の1つのスタックから `?game=coup` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
