# ツォロ

タイルを置いて自分の道をのばし、最後まで盤に残った人が勝つボードゲーム「ツォロ（Tsuro: The Game of the Path、Tom McMurchie、WizKids／Calliope Games 2004）」の基本ゲームを、ブラウザで CPU と遊べるようにしたもの。2〜8人（あなた＋CPU 1〜7人）。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

盤・タイル・駒・アイコンの絵は、すべて SVG で自作している（墨と金。公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方

### 準備

- 6×6 の盤、道のタイル35枚、竜のタイル1枚、駒8つ（色ごと）
- 山をよく混ぜ、各自に3枚ずつ配る。最初の人から時計回りに、盤の縁の印（48か所）の空いているところに駒を置く。タイルを置くのは、全員が駒を置いてから

### 手番

1. **置く**：手札から1枚を、自分の駒の前のマスに置く。どの向きでもよい
2. **進む**：自分の駒と、そのタイルに面しているほかの駒が、道の終わりまで進む（置いてあるタイルの道もたどる）
3. **引く**：山から1枚引く。手札が3枚に満たない人がいれば、手番の人から時計回りに1枚ずつ、全員が3枚になるか山がなくなるまで引く

自分の道を盤の縁につなぐ置き方（自分から脱落する置き方）は、ほかに置き方がないときしかできない。

### 脱落

- 盤の外に出た駒は脱落
- 2つの駒が出会ったら（道がつながってぶつかったら）両方とも脱落
- 脱落した人の手札は山に入れて混ぜる

### 竜のタイル（3人以上のとき）

- 山が空で引けなかった人は、竜のタイルを取る（その手番はもう引かない）
- あとでタイルが山に戻ったら、手番の人ではなく竜のタイルを持つ人から引き始め、引いたら竜のタイルを手放す
- 竜のタイルを持つ人が脱落したら、時計回りで次の、手札が3枚に満たない人に渡す

### 終わり

- 盤に残った駒が1つになったら、その人の勝ち
- 残りの全員が同じ手で脱落したら、その人たちの引き分け
- タイルがすべて置かれたときに2人以上残っていれば、残った人たちの引き分け

### 資料と、資料で分からない点の決め方

読み比べた資料：

- [A] Calliope Games 版の英語のルールブック（© 2009 Compound Fun。FAQ と上級ルールを含む）：https://gamers-hq.de/media/pdf/8f/1b/5c/Tsuro_Rules_web.pdf
- [B] ルールの解説のサイト：https://rulespal.com/tsuro/rulebook 、https://groupgames101.com/tsuro-rules
- [C] Wikipedia：https://en.wikipedia.org/wiki/Tsuro

確かめたこと：

- 人数（2〜8人）、盤（6×6）、道のタイル35枚と竜のタイル、手札3枚、縁の印に駒を置く、手番の3つの段階、自分から縁につなぐ置き方の禁止と例外、盤の外・衝突での脱落、手札を山に戻す、引く順と竜のタイル、勝ち・引き分けは、[A] の本文と FAQ に従った
- **35枚の道の組み合わせ**：1枚のタイルは、縁の8つの端点を2つずつ4組に分けたもの。分け方は 7×5×3×1 = 105 通りあり、90度ずつ回して重なるものを1つにまとめると、ちょうど35通りになる。[A] の「各タイルは異なる（Each tile is unique）」と35枚に一致する。ゲームのタイルは、この35通りをプログラムで作っている（`public/js/tiles.js`）。内訳は、どの向きでも同じ形が5枚、半回転で同じ形が10枚、4つの向きがすべて違う形が20枚（テストで確かめている）

資料の食い違いと、資料に書かれていない点は、次のように決めた：

- **竜のタイルを持つ人が脱落したとき**：[B] の一部は「脇に置く（だれも持たない）」、[A] の FAQ は「時計回りで次の、手札が3枚に満たない人に渡す」。公式の [A] に従った。手札が3枚に満たない人がいなければ、だれも持たない（書かれていない）
- **ほかの駒とぶつかる置き方**：[A] が禁じているのは「自分の道を盤の縁につなぐ」置き方で、衝突には触れていない。衝突する道は、相手の来た道をたどって盤の縁につながっていて、自分が脱落する点も同じなので、これも「自分から脱落する置き方」として、ほかに置き方があればできないことにした
- **最初の人**：[A] は「最年長の人」。ここではシードで決める
- **手番に手札がない人**：山が空のまま手札を使い切った人の番は、置かずに飛ばす（書かれていない）
- **引く順**：[A] の「手札が3枚に満たない人が、時計回りに1枚ずつ」を、全員が3枚になるか山がなくなるまで何周でも回す、と読んだ。初めのうちは、手番の人だけが引くことになる（[A] の書き方と一致する）
- **脱落した人の手札**：山に入れたあと、山全体を混ぜる
- **手番の人が脱落したとき**：その人は引かない。引く順は、竜のタイルを持つ人がいなければ、手番の人の次から
- **終わったときの手札**：ほかの人の手札は、終わっても見せない
- [A] の上級ルール（脱落させたときの手札の交換、山を回す遊び方）は入れていない

### 画面の操作

- **駒を置く**：盤の縁の近くをタップすると、一番近い空いた印に仮の駒が出る。「置く」で決める
- **タイルを選ぶ**：手札のタイルをタップ。駒の前のマスに、置いたときの形と、動く駒の行き先（点線）が出る
- **回す**：選んだタイルをもう一度タップするか、盤の光るマスか、回すボタンをタップ。手札の絵も、その向きで描く。新しい手番では、各タイルを脱落しない向きから始める
- **決める**：「置く」。自分が脱落する向きには ✕ が付き、ほかに置き方があるうちは押せない
- 上のバー：ホーム・手番・山の残り・記録・遊び方。名前の札に、手札の枚数と竜のタイル（竜）が出る
- 置いたタイルで動いた駒は、道に沿って進み、通った道をその人の色でなぞる。脱落した駒には ✕
- 途中で閉じても、「続きから」で再開できる（操作の記録から作り直す）

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（盤・駒・通った道・自分の手札・山の枚数）だけを見て決め、山の並びやほかの人の手札はのぞかない。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）。迷いは、ビューに見えている手数・席・自分の手札から作った別の乱数で決める（`public/js/cpu-player.js`）。

**ふつう**

- 置ける手（手札3枚 × 形の違う向き）を全部試し、駒の動きをたどる
- 自分が生き残る手を選ぶ。相手を盤の外へ出す・ぶつける手を高く見る。最後の相手を出せれば、その手を選ぶ
- 数手先の道の残り：置いたあとに自分の前のマスへ「まだ見えていないタイル」（山かほかの人の手札にあるもの）が、どれかの向きで置かれたときに生き残れる割合を見る（ほかの人が同じマスに置く場合にもあたる）。さらに、残りの手札で次の手番に生き残れるか、生き残れるならその先の生き残りやすさも見る
- 相手の生き残りやすさは低いほどよい。盤の縁から遠いマスに面しているほうがよい
- どうしても脱落するなら、残りの全員を道連れにして引き分けにできる手を選ぶ
- 駒を置く：ほかの駒と同じマスに面さない、隅でない印を選ぶ
- 点の重み（`TUNING`）は、`scripts/cpu-match.mjs` で勝率を比べて決めた（重みを変えた案どうしの差は、試合数による揺れの範囲だった）

**やさしい**：置ける手から当てずっぽうに選ぶ（自分から脱落する手は、ルールで置けないので選ばない）。駒を置く印も当てずっぽう。

```bash
# 試合数・人数・席ごとの強さ（easy・normal）
node scripts/cpu-match.mjs 1000 3 normal,easy,easy
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 均等なら |
|---|---|---|---|---|
| 2人（ふつう・やさしい） | 1000 | 81.7% | 18.3% | 50% |
| 2人（ふつう・ふつう） | 1000 | 50.4%・49.5% | — | 50% |
| 3人（ふつう1・やさしい2） | 1000 | 70.9% | 15.3%・13.8% | 33% |
| 4人（ふつう1・やさしい3） | 500 | 59.7% | 13.0〜13.9% | 25% |
| 6人（ふつう1・やさしい5） | 300 | 42.6% | 8.1〜15.6% | 17% |
| 8人（ふつう1・やさしい7） | 300 | 35.0% | 7.6〜12.0% | 12.5% |
| 8人（ふつう4・やさしい4） | 300 | 15.5〜20.9% | 5.3〜8.0% | 12.5% |

引き分けは、引き分けた人数で割って勝ちに数えた。どの組み合わせでも、止まった試合はない。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/tiles.js` | 35枚のタイルの生成、盤の座標、駒の動き（道をたどる・衝突）。ゲーム・CPU・画面で共通 |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（山の並び・ほかの人の手札・シードを隠す）と、自分の番の置ける手 |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率 |

- `game-definition.test.js`：オンライン対戦の定義と、ビューに山の並び・ほかの人の手札・シードが入らないこと（sanitize）
- `game-controller.test.js`：CPU との対戦の進行、断られた操作の知らせ、保存からの再開

### オンライン対戦を入れるとき

netplay-kit の `scripts/sync.mjs` で部屋の処理を写し、`server/src/game-definition.js` を `createHandler` と `startDevServer` に渡す。部屋には参加者・シード・操作の記録だけを保存し、操作のたびに記録から再現する。操作を待っている人は `game.actors()`（ビューの `current`）で見る。隠すのはビュー（`createGameView`）の役目で、山の並びはだれにも、手札は本人以外に入れない。
