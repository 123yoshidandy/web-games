# ハイブ

虫の駒で相手の女王蜂を囲む、2人用のボードゲーム「ハイブ（Hive）」を、ブラウザで CPU と遊べるようにしたもの。あなたと CPU の2人。スマホの縦持ち向け。ホーム画面に置くと、オフラインでも遊べる。

絵（駒と虫・アイコン）は、すべて SVG で自作している。

## 遊び方（基本ゲーム）

- 駒は各自11個：女王蜂1・カブトムシ2・バッタ3・クモ2・アリ3。拡張の駒（テントウムシ・蚊・ダンゴムシ、各1）は、タイトルで選べる（既定はなし）
- 先手（白）はランダム。手番には、駒を1つ置くか、盤の自分の駒を1つ動かす。どちらもできないときはパス
- 置く：最初の1手は中央、2手目（相手の最初）はそれに接して置く。そのあとは、自分の駒に接し、相手の駒に接しない空きマスに置く（積み重なったマスは、いちばん上の駒の色）
- 女王蜂は4手目までに置く。トーナメントルール（既定でオン。切ることもできる）では、最初の手に女王蜂を置けない
- 自分の女王蜂を置くまでは、駒を動かせない
- ひとつながり：取り除くと巣が2つに分かれる駒は動かせない。動かす途中も巣に接したまま進む
- すき間：両側がふさがったすき間は、滑って通れない（カブトムシなど上を進むときは、両側の積み重なりの高さで決まる）
- 駒の動き
  - 女王蜂：1マス滑る
  - カブトムシ：1マス動く。駒の上に乗れる。乗られた駒は動けない
  - バッタ：一直線に1つ以上の駒を跳び越し、最初の空きマスへ
  - クモ：ちょうど3マス滑る（同じマスに戻らない）
  - アリ：巣のまわりを何マスでも滑る
  - テントウムシ：2マス巣の上を進み、3マス目で降りる
  - 蚊：接している駒（いちばん上の駒）の動きをまねる。巣の上にいるときはカブトムシ。蚊だけに接しているときは動けない
  - ダンゴムシ：女王蜂と同じに動くか、接している駒（積み重なっていない）を自分の上を通して、自分に接する空きマスへ動かす。直前の手番に動いた駒は動かせない。動かされた駒は、次の手番に動けない（ダンゴムシの力も使えない）。蚊はダンゴムシに接していれば、この力もまねる
- 女王蜂の6方向がすべてふさがった人の負け。両方同時なら引き分け。同じ局面が3回目になったら引き分け

ルールは、ボードゲームアリーナの遊び方のページで確かめた。

### 決めたこと

- ダンゴムシの「直前の手番に動いた駒」には、置いた駒は含めない（動かした駒だけ）
- 同じ局面の繰り返しは、3回目で引き分けにする（ボードゲームアリーナには繰り返しによる引き分けがあるが、回数を確かめられなかった）
- 選んだ駒が、ふつうの動きとダンゴムシの力の両方で同じマスへ行けるときは、画面ではふつうの動きにする

### 画面の操作

- 手持ちの駒か、盤の自分の駒を押すと、置ける場所・動かせる先が点線の六角形で出る。押すとそこに置く・動かす。駒の上に乗る先は輪で出る。ダンゴムシの力で動かす先は、別の色（青緑）で出る
- 自分のダンゴムシの隣にある相手の駒も、押して選べる
- 積み重なった駒は、下の駒を少しずらして見せ、高さの数を添える。押すと、中の駒が下から順に出る
- 盤は指でずらし、2本指・ホイール・右の＋−で拡大・縮小する（ページはズームしない）。駒や行き先が見えなくなったら、全体に合わせ直す
- 置けない駒を押すと、理由（トーナメントルール・4手目の女王蜂など）が出る
- 最後の手（動かした先と元のマス）は青で示す。手持ちの欄には、女王蜂のまわりのふさがったマスの数が出る
- 右上のボタンで、これまでの記録が見られる。遊び方と記録を開いている間は、CPU が止まる
- 途中でホームに戻っても、「続きから」で再開できる

## CPU

アルファベータ法で先を読む。「やさしい」は自分の1手だけを読み、評価の揺れが大きく、ときどき3番目までの手を選ぶ。「ふつう」は相手の応手まで2手を読む。局面の値打ちは、相手の女王蜂のふさがり具合 − 自分の女王蜂のふさがり具合（ふさがるほど急に重く）＋動ける駒の数（アリ・カブトムシは重く）＋手持ちの余裕＋相手の女王蜂への近さ。どちらも、すぐ勝てる手は見逃さない。前に出た局面へ戻る手は少し下げる。1手の考える時間は 0.8 秒で打ち切る。

```bash
# 試合数・強さ（easy・normal・random）・拡張の駒（例 LMP、なしは -）。先手・後手を入れ替えて対戦する
node scripts/cpu-match.mjs 40 normal,easy -
```

上の帯の電球（ヒント）を押すと、ふつうの CPU が揺れなしで選ぶ手を示す（動かす駒を選んでおき、行き先を金色にする。押せば動く）。盤と手持ちはすべて公開の情報。

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/rules.js` | ルールの中身（通る手・手を当てる・勝ち負け）。CPU の先読みでも使う |
| `public/js/game.js` | 進行と記録。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる |
| `public/js/game-view.js` | 見る人ごとのビュー（手番の人には通る手の一覧を付ける） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |

### オンライン対戦を入れるとき

ルールとビューは、netplay-kit の「ゲームの定義」の形（`server/src/game-definition.js`）で用意してある。netplay-kit の `sync.mjs` で部屋の処理を写し、この定義を `createHandler` と `startDevServer` に渡す。画面は、ローカル対戦と同じ `getView()` / `send()` の形のオンライン用のコントローラーを足す。
