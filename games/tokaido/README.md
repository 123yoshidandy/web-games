# 東海道

京都から江戸まで東海道を旅し、景色・土産・食事・温泉・出会いで旅の思い出（点）を集めるボードゲーム「東海道（Tokaido、Antoine Bauza、Funforge 2012）」の基本ゲーム（拡張なし）を、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち・横持ちのどちらでも、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

道・マス・札の絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。旅人の名前はカタカナ、札の名前は日本語に直したもの。

## 遊び方（基本ゲーム）

- 各人に旅人の札を2枚配り、1枚を選ぶ。旅人に書かれたお金（2〜9文）を持って、京都にランダムな順に並ぶ
- 道のいちばん後ろの旅人が、先の空いたマスへ好きなだけ進む（同じマスの2人目は後ろ）。進んだあともいちばん後ろなら、続けて進む
- 宿場は追い越せない。全員がそろうまで止まり、最後に着いた人から出発する
- 2マスは、4・5人のときだけ2人目が止まれる（2・3人のときは1人だけ）
- 止まったマスの効果を受ける。点はその場で入る

| マス | 効果 |
|---|---|
| 店 | 土産を3枚見て、好きなだけ買う（1〜3文）。買わなかった札は山の下へ。1文以上ないと止まれない |
| 農家 | 3文をもらう |
| 寺 | 1〜3文を寄付し、1文1点。1文以上ないと止まれない |
| 出会い | 出会いの札を1枚引く |
| 温泉 | 温泉の札（2点か3点）を1枚引く |
| 田・山・海 | その景色の次の1枚（田3枚・山4枚・海5枚）。点は札の番号。最初に完成させた人に3点。完成させた景色には止まれない |
| 宿場 | 最初に着いた人が、旅人の数＋1枚の食事の札を引く。着いた順に1つ買える（1〜3文、どれも6点）。同じ料理は旅の間に2度食べられない。残りは山の下へ |

- 土産：種類（小物・食べ物・着物・美術）の違うもので組を作り、組の1枚目1点・2枚目3点・3枚目5点・4枚目7点（4種類そろうと16点）
- 出会い：職人（土産の山から1枚）・案内人（その景色の次の1枚。完成していれば、ほかの景色から選ぶ）・侍（3点）・公家（3文）・巫女（場の1文を寺に寄付して1点）
- 旅の終わり（全員が江戸に着いたら）：
  - 寺の寄付の多い順に10・7・4点、ほかに寄付した人は2点。同じ額は同じ点
  - 称号（各3点、同点は全員）：食通（食事の札の値段の合計）・収集家（土産の数）・湯治客（温泉の数）・話し好き（出会いの数）
  - 点の多い人の勝ち。同点なら称号（景色の3枚を含む）の多い人。それも同じなら全員の勝ち

### 2人のとき

灰色の中立の旅人を加え、3人を京都にランダムな順に並べる。中立の旅人がいちばん後ろなら、先頭の人が動かす。中立の旅人は、寺で場の1文を寄付し（寄付の順位に入るが、点は取らない）、宿場では動かした人が食事の札を1枚ランダムに捨てる（伏せたまま山の下へ）。ほかのマスでは何もしない。最初に宿場に着いた人は4枚を引く。

## 資料と、資料で分からない点の決め方

ルールは、Funforge の英語版ルールブック（2012、TKDUS01）を読んで合わせた。札の内訳とマスの並びはルールブックの本文にないので、公開されている実装と照らし合わせた。

| 項目 | 資料 | 照らし合わせた結果 |
|---|---|---|
| 進み方・各マス・宿場・2人のとき・終わりの得点・同点・旅人の力 | ルールブック | 寄付の例（1位10点、2位で並んだ2人は7点ずつ）と土産の例（1・4・9・16・5・3・8点）をそのままテストにした。旅人の力とお金は Board Game Arena の遊び方の資料とも一致 |
| 道のマスの並び（宿場の間 13・12・13・12 マス） | foxfriends/tokaido（JavaScript）、neigebaie/tokaido（C） | 4区間すべてで種類と順番が一致 |
| 2マスの位置（24か所） | foxfriends/tokaido | 位置を持っていたのはこの1つだけ。数（24）は RaphaelIENCO/Tokaido（Java）と一致したが、座標の決め方が違い、位置は照らせなかった |
| 札の枚数（土産24・食事25・出会い14・温泉12・景色60・称号7） | ルールブックの部品の一覧 | 一致 |
| 出会いの内訳（職人2・案内人 田1 山2 海3・侍2・公家2・巫女2） | foxfriends/tokaido | 種類ごとの枚数は1つの資料にしかなかった。種類と効果はルールブック・Board Game Arena と一致 |
| 土産の名前・種類・値段、食事の名前・値段・枚数 | foxfriends/tokaido | ルールブックの「値段は1〜3文」「土産の例（箸・独楽は小物、下駄は着物、饅頭・金平糖は食べ物、重箱・漆器・浮世絵・根付・三味線は美術）」と食い違いはない |
| 温泉（2点6枚・3点6枚） | foxfriends/tokaido | ルールブックの「2点か3点、12枚」と一致 |

頼まれたマスの中の「茶屋」は、基本ゲームにはマスとしてない。食事は宿場でとる（この版の「宿場」）。

資料で決まらない点と、読み方が分かれる点は、次のように決めた。

- 寺の寄付の順位は、額の大きい順に数える。同じ額は同じ順位で、その次の額は次の順位（6・4・4・2 なら 10・7・7・4）。ルールブックは「並んだ人はその順位の点を取る」としか書いていないため
- 称号は、1枚（1文）もなければ取れない（全員が0なら、だれも取らない）
- ヒロタダの場の1文は、寺に止まるたびに必ず足す（足して損をすることがないため）。寺に止まるには、ヒロタダも自分のお金が1文以上いる
- ゼンエモンの1文で買う札は、買う中でいちばん高い1枚に自動で当てる
- サツキのただの食事は、その宿場に並んでいる札からランダムに選ぶ（ルールブックの「並んでいる食事の札から1枚をランダムに」）。もう食べた料理が出たら、ただでは食べられない
- ヒロシゲとチュウベエの力は、途中の3つの宿場だけ（ルールブックのとおり。江戸では使わない）。ヒロシゲが景色を全部完成させていたら、何も取らない。案内人で景色が全部完成していたら、何も取らない
- 山（土産・出会い・温泉・食事）が尽きたら、その札は取れない。景色の札は足りなくならない（5人がそれぞれ全部を完成させても足りる）
- 中立の旅人は、空いていればどのマスにも止まれる（お金や景色の決まりは受けない）。中立の旅人が宿場に最初に着いたら、動かした人が4枚を引いてから1枚を捨てる
- 2人のときは、中立の旅人と合わせて3人なので、2マスの2人目には止まれない
- 店で引いた土産3枚は、表にして並べるので全員に見せる。宿場の食事の札は、その宿場に着いた人にだけ見せる（ルールブックの「ほかの人に見せずに見る」から）
- ルールブックの変種（出発の順でお金を増減する、旅人の札を使わない入門、江戸から京都への逆の旅）は入れていない
- 宿場の名前は盤に書かれていないので「一の宿・二の宿・三の宿」とした

## 画面

- 道は、全員がいる区間（宿場から次の宿場まで。だれも宿場を追い越さないので、全員が必ず1つの区間にいる）だけを5列×3段の折り返しで描く。縦持ちでも横にスクロールせずに見える。道の全体は、上の細い帯（今の区間を薄く塗る）に示す
- 進めるマスは金色の輪で光る。押すとマスの効果が下に出て、もう一度押すか「進む」で進む。中立の旅人を動かすときは、灰色の輪で光る
- 小さな丸の付いたマスは2マス（2人目が止まる場所）。止まれない人数のときは、点線で薄く描く
- 旅人の枠は、名前・旅人・点・お金・景色の進み。押すと持ち物（景色・土産・食事・温泉・出会い）が開く
- 店・寺・出会い・景色・食事は、下の欄で札やボタンを選ぶ
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる
- 縦持ちは上から道・旅人・操作の欄。横持ちと PC は、道を左に、旅人と操作の欄を右に置く

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（公開された情報と、自分にだけ見える札）だけを見て決め、山の並びやほかの人の伏せた札はのぞかない（テストで、伏せた情報を入れ替えても手が変わらないことを確かめている）。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう：止まれるマスごとに「止まったら点がどれだけ増えそうか」を見積もり、飛ばすマスの数だけ割り引いて（1マス 1.1 点）、一番よいマスへ進む
  - お金は、残りの宿場の食事に要る分（1回2文）を残すように重みを変える
  - 景色は次の札の点と、完成で称号が残っていれば3点。店は土産の組の伸びと値段。寺は残りのお金に余裕があるだけ寄付する
  - 店では買い方を全部試し、増える点からお金の重みを引いたものが一番大きい買い方を選ぶ。食事は、ただで出たものか、一番安いもの
  - 旅人は、旅人ごとの勝率（旅人をランダムに配った「ふつう」どうしの3人戦 900 試合）の高い方を選ぶ。チュウベエ 45%・サツキ 42%・キンコ 41%・ウメガエ 38%・ゼンエモン 34%・ミツクニ 31%・ササヤッコ 27%・ヒロシゲ 26%・ヒロタダ 26%・ヨシヤス 24%（互角は 33%）
  - 2人のときの中立の旅人は、相手にとって一番よいマスをふさぐ
- やさしい：近いマスを好み、見積もりに大きな迷いを足す。旅人・土産・食事・景色は気まぐれに選び、寄付は1文

```bash
# 試合数・人数・席ごとの強さ（easy・normal）。席の有利を消すため、試合ごとに強さの並びをずらす
node scripts/cpu-match.mjs 1000 2 normal,easy
```

| 対戦 | 試合数 | ふつうの1席あたりの勝率 | やさしいの1席あたりの勝率 | 平均点（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（ふつう・やさしい） | 1000 | 90.0% | 10.0% | 81.3／64.7 |
| 3人（ふつう・やさしい2） | 600 | 74.7% | 12.7% | 79.6／67.2 |
| 4人（ふつう2・やさしい2） | 400 | 45.6% | 4.4% | 81.2／66.0 |
| 5人（ふつう2・やさしい3） | 400 | 43.1% | 4.6% | 70.8／59.7 |
| 2人（ふつう・ふつう） | 600 | 50.0% | — | 76.0 |
| 3人（やさしい3） | 600 | — | 33.3% | 69.5 |

同点で複数が勝った試合は、勝ちを等分して数えた。どの組み合わせでも、止まった試合はない。飛ばすマスの割り引きを 0.7・1.5 に変えた版は、今の版（1.1）との3人戦 300 試合で勝率 27.2%・30.7%（互角は 33.3%）と負け越したので、1.1 のままにした。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

### オンライン対戦を入れるとき

netplay-kit の `scripts/sync.mjs` で部屋の処理を写し、`server/src/game-definition.js` を `createHandler` と `startDevServer` に渡す。部屋には参加者・シード・操作の記録だけを保存し、操作のたびに記録から再現する。旅人を選ぶ間は全員が同時に操作し、旅の間に操作を待っている人は `game.actors()`（2人のときは、中立の旅人を動かす先頭の人を含む）。伏せた情報を隠すのはビュー（`createGameView`）の役目で、山の並び・シード・CPU の値（`cpuSalt`）は入れない。
