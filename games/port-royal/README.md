# ポートロイヤル

カードゲーム「ポートロイヤル（Port Royal、Alexander Pfister、Pegasus Spiele 2014）」の基本ゲーム（拡張なし）を、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち向けで、相手の状況・遠征・港・自分の人物と操作のボタンが、1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

カードの絵とアイコンは、すべて SVG で自作している（公式の画像は使っていない）。カードと人物の名前は自分で訳したもので、効果の文も自分で書いた。

## 遊び方（基本ゲーム）

- 120枚（船50・人物60・遠征6・税金4）。カードの裏はコインで、コインを得るときは山から裏のまま取る。払ったコインは捨て札へ。山が尽きたら捨て札を切って山にする
- はじめは各自3コイン。5人用の遠征（3種の印）は、5人のときだけ最初から場に出し、それ以外は使わない
- 手番は2つの段階
  1. 発見：山から1枚ずつ港にめくり、めくるたびに続けるか止めるかを決める（最初の1枚は必ずめくる）
     - 船：港に置く。自分の剣（船乗り・海賊）が船の剣以上なら、撃退して捨ててもよい（ドクロの船は撃退できない）。港にある船と同じ色の船を撃退しなかったら失敗：港を全部捨てて手番は終わり（道化を持つ人は、道化1人につき1コイン）
     - 遠征：港とは別の場に置く。手番の人は、自分の手番の間いつでも、条件の人物（司祭・船長・定住者。何でも屋はどれの代わりにもなる）を捨てて遠征を取り、点とコインを得る
     - 税金：12コイン以上の人は半分（切り捨て）を捨てる。そのあと、剣の最も多い人（2枚）か点の最も少ない人（2枚）が1コイン（同点はみな）
  2. 取引と雇用：港の船の色の数が 0〜3 なら1枚、4なら2枚、5なら3枚を、1枚ずつ取る
     - 船：そのコインを得る（同じ色の商人1人につき+1）。人物：費用を払って雇う
     - そのあと、ほかの人も時計回りに1枚ずつ取れる（手番の人に1コイン払う。船ならそのコインから払ってよい）。残りは捨てる
- 人物の力（重なる）

  | 人物 | 枚数 | 費用・点 | 力 |
  |---|---|---|---|
  | 商人 | 10（5色×2） | 3コイン1点×8、5コイン2点×2（黄と青） | その色の船を取ると+1コイン |
  | 船乗り | 10 | 3・1点×7、5・2点×2、7・3点×1 | 剣1 |
  | 海賊 | 3 | 5・1点、7・2点、9・3点 | 剣2 |
  | 定住者・船長・司祭 | 5ずつ | 4・1点 | 遠征の条件（家・錨・十字） |
  | 何でも屋 | 3 | 6・1点 | 遠征で、定住者・船長・司祭のどれの代わりにもなる |
  | マドモアゼル | 4 | 7・2点×2、9・3点×2 | 人物を雇う費用が1安い（0より下がらない） |
  | 道化 | 5 | 5・1点×1、7・2点×3、9・3点×1 | 手番でないときに取る番で港が空なら1コイン。誰かの発見が失敗したら1コイン |
  | 提督 | 6 | 5・1点×1、7・2点×3、9・3点×2 | 取る番に港が5枚以上なら2コイン |
  | 総督 | 4 | 8・0点 | 取引と雇用で1枚多く取れる（手番でないときは、その分も1コインずつ払う） |

- 船（剣・コイン）

  | 船 | 内訳 |
  |---|---|
  | ピナス（黄） | 剣1・1コイン×3、剣1・2×1、剣2・2×2、剣2・3×1、剣4・3×2、剣4・4×1 |
  | フリュート（青） | 剣1・1×3、剣1・2×1、剣2・2×2、剣2・3×1、剣5・3×2、剣5・4×1 |
  | スキフ（緑） | 剣1・1×3、剣1・2×1、剣3・2×2、剣3・3×1、剣5・3×2、剣5・4×1 |
  | フリゲート（赤） | 剣1・1×3、剣3・2×3、剣6・3×2、ドクロ・3×1、ドクロ・4×1 |
  | ガレオン（黒） | 剣2・1×3、剣4・2×3、剣7・3×2、ドクロ・3×1、ドクロ・4×1 |

- 遠征：司祭2（4点・2コイン）、船長2（4点・2コイン）、定住者2（4点・2コイン）、船長2と定住者（6点・3コイン）、司祭2と定住者（6点・3コイン）、5人用：司祭・船長・定住者（5点・3コイン）
- 誰かが12点以上になったら、その巡の終わり（最初の手番の人の右隣の手番のあと）で終わり。点の多い人の勝ち。同点はコインの多い人、それも同じなら同点の人がみな勝ち

### 資料と、資料で分からない点の決め方

ルールは、Pegasus Spiele の英語版の公式ルールブック（本文：https://cs.uwaterloo.ca/~dtompkin/archive/dtlib/base/Port%20Royal.pdf ）で確かめた。カードの構成（種類ごとの枚数、船の色ごとの剣の内訳）、準備、手番、税金、遠征、取引と雇用、人物の力、終わりと同点の決め方は、ルールブックのとおり。Yucata のルールの頁（https://www.yucata.de/en/Rules/PortRoyal ）とドイツ語のルールの紹介とも一致した。

カードごとの数値（船のコイン、人物の費用と点、遠征の点とコイン、税金の内訳）は、ルールブックではカードの絵にしか書かれていない。別々に作られた2つの実装の、山札を定義したコードを照らし合わせて決めた。全120枚の数値が2つの間で一致し、種類ごとの枚数・船の色ごとの剣の内訳・ルールブックの例（遠征「司祭2」で2コイン、フリュートで2コイン）とも一致している。

- JavaScript の実装：https://github.com/matthiasseemoo/portroyal の `src/game.js`（基本ゲームのカードだけを数えた）
- Java の実装：https://github.com/mpacio/portroyal_be の `portroyal_lib/src/main/java/com/matteopaciolla/portroyal/confs/BaseDeckDictionary.java`

資料で食い違った点と、どう決めたか：

- 別の実装（https://github.com/RassaLibre/PR-card-game ）は、船の剣（黄の剣3など）と遠征の枚数（5枚）がルールブックと合わないので、使わなかった
- 船のコインは、剣の数でも色でも決まらない。どの色も10枚のコインが 1・1・1・2・2・2・3・3・3・4 で、剣の弱い順に並ぶ（2つの実装で一致）
- カードの写真とは、1枚ずつは突き合わせていない（2つの実装の一致を根拠にした）

自分で決めた点：

- 取引と雇用では、取れる枚数より少なく取って終えてよい（手番の人も、取らずに終えてよい）
- 取れるものが何もない人（コインが足りない人物しか残っていない、など）の番は、自動で飛ばす
- 遠征に出す人物は、条件を満たすうち、点の低いものから自動で選ぶ（同じなら、何でも屋は最後に使う）
- 道化と提督の力は、持っている枚数だけ重なる（ルールブックの「同じ人物の力は重なる」から）
- 山も捨て札も尽きたら、それ以上のコインは得られない。手番の始めに山も捨て札もない（カードが全部コインとして持たれている）ときは、誰もめくれないので、その時点で終わり（勝ち負けはふだんどおり）
- 最初の手番の人は、ゲームごとにランダムに決める（ルールブックは「最後に港へ行った人」）

### 画面の操作

- 上の帯：ほかの人のコイン・点・剣（押すと持ち物）。手番の人は青、今操作している人は金の枠
- その下：山（残りの枚数）、捨て札の一番上、遠征（条件を満たしていれば光る。押すと説明と「遠征を果たす」）
- 港：めくったカード。上の5つの点は港にある船の色、右は取れる枚数と、次の1枚で失敗する確率（見えていないカードから数えたもの）
- 発見では「めくる」「止める」、撃退できる船では「撃退」「港に置く」。取引と雇用では、光っている港のカードを押して取る。「取り終える」「取らない」で番を終える
- 下の欄：自分のコイン・点・剣と、雇った人物（種類ごとの数）。押すと一覧が見られる。下の帯を押すと記録
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。山の並びはのぞかず、見えているカード（港・遠征・捨て札・全員の人物と遠征）を全体から引いて、見えていないカードの割合を見積もる。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう
  - めくるか止めるか：次の1枚で失敗する確率 p（港にある色の船のうち、撃退できないものの割合）を出し、「p × 今止めたときの港の価値」が「(1 − p) × もう1枚めくったときの見込み（港が2枚までは1.2コイン、そのあとは0.35コイン）」より大きくなったら止める。港の価値は、取れる枚数ぶんの、船のコインと人物の価値（点と力の見込みをコインに直して費用を引いたもの）の合計
  - 取るもの：取れる枚数ぶんの取る順を全部試し、点と力の見込みとコインの合計が最も大きい組の最初の1枚を取る。コインは持つほど価値を下げる（使い道は人物を雇うこと）。手番でないときは、1コイン払っても得になるときだけ取る
  - 遠征は、条件を満たしたらすぐ取る。撃退は、同じ色の船と1コインの船だけ
- やさしい：港が3〜4枚になるまでめくる。取るのは、雇えれば点の高い人物、そうでなければコインの多い船。遠征は取らない

```bash
# 試合数・席ごとの強さ（easy・normal）。最初の手番は試合ごとに入れ替える
node scripts/cpu-match.mjs 300 easy,normal
```

| 対戦 | 試合数 | ふつうの勝率 | やさしいの勝率 | 手番の数の平均 |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 300 | 91.0% | 9.0% | — |
| 2人（ふつう・やさしい） | 300 | 93.7% | 6.3% | — |
| 3人（ふつう・やさしい2人） | 300 | 90.0% | 5.0%・5.0% | 30.9 |
| 5人（ふつう・やさしい4人） | 200 | 81.5% | 4.0〜5.0% | 41.8 |
| 2人（ふつう・ふつう） | 300 | 46.0%・54.0%（同点4） | — | 21.0 |

同点で複数が勝ったときは等分して数えた。どの組み合わせでも、止まった試合はない。

自分の番に操作の欄の電球（ヒント）を押すと、ふつうの CPU が選ぶ手を光らせる（めくる・止める・撃退・置く・取らないのボタンか、取る港のカード・果たす遠征）。CPU は見えているカードから残りを数えるだけで、山の並びはのぞかない。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/cards.js` | 120枚のカードのデータ |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない。コインは山のカードを裏のまま持つ |
| `public/js/game-view.js` | 席ごとのビュー（山の並びと、各自のコインのカードの中身を隠す） |
| `public/js/cpu-player.js` | CPU（失敗の確率の見積もりもここ） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率 |

テスト（`test/`）：

- `game.test.js`：カードの構成（枚数・剣の内訳・人物の枚数・5人用の遠征）、準備、発見（最初の1枚、同じ色で失敗、撃退とドクロ、道化、税金2種、遠征の取り方と条件）、取引と雇用（取れる枚数、商人とマドモアゼル、取る順に力が効く、ほかの人の1コイン、総督と提督、道化、コイン不足、残りを捨てる）、終わり（巡の終わりまで、同点はコイン、山が尽きたとき）、点と剣、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（JSON を通しても、途中からでも）、同じシードで同じ山、CPU の判断がゲームの乱数を使わないこと、ランダムな操作を浴びせても断った操作で状態が変わらず再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、失敗の確率の数え方、止める判断、遠征をすぐ取ること
- `game-definition.test.js`：オンライン対戦の定義（受け付け・断る・保存と再現・CPU・抜けた人）と、ビューで隠すもの（山の並び・コインのカード・シード）
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン

### オンライン対戦を入れるとき

netplay-kit の `scripts/sync.mjs` で部屋の処理を写し、`server/src/game-definition.js` を `createHandler` と `startDevServer` に渡す。部屋には参加者・シード・操作の記録だけを保存し、操作のたびに記録から再現する。ビュー（`createGameView`）が、山の並びと各自のコインのカードの中身・シードを入れないので、各端末にはそのまま送ってよい。
