# 五目並べ

縦・横・斜めに自分の石を5つ並べたら勝ちの五目並べ。ブラウザで遊べる（スマホの縦持ち向け、PC でも遊べる）。

- CPU と対局（やさしい・ふつう・つよい。黒・白・おまかせを選べる）
- 2人で1台を使って対局
- 盤は15路（ふつうの五目並べ）と10路（前の版の盤）
- 目隠し（石を見せずに打つ）、待った（1手戻す）、続きから、投了、棋譜、ヒント
- 持ち時間（なし・3分・5分・10分の切れ負けと、3分+2秒・5分+5秒のフィッシャー）
- オンライン対戦（共通のロビー）
- ホーム画面に追加すると、オフラインでも遊べる（PWA）

絵（盤・石・アイコン）はすべて自作の SVG。

## 遊び方

- 黒と白が交互に、線の交点に石を1つずつ置く。黒が先
- 縦・横・斜めのどれかに、自分の石を5つ以上並べたら勝ち。6つ以上（長連）も勝ち（自由ルール。禁じ手はない）
- 置いた石は動かさず、取りもない。盤が埋まったら引き分け。投了もできる
- CPU 戦の「おまかせ」と、オンラインでは、どちらが黒（先手）かをシードで決める

### 操作

- 交点を押すと置く。マウスでは、置く前に薄い石で位置を示す
- **仮置き：** 盤が小さく表示されるとき（指で押す端末で交点の間が 30px 未満。スマホの15路）は、押すと仮に置き、赤い十字の線で行と列を示し、下に座標（H8 など）を出す。指を動かすと仮の石も動く。同じ点をもう一度押すか「ここに打つ」で置く
- 直前の手に金の輪。五連には金の線を引く。盤の下に手数と直前の手の座標
- 上のバー：ホーム／待った・棋譜・目隠し・投了・ヒント・サウンド・遊び方
- **目隠し：** 石を描かず、直前の手の点だけを金の四角で示す。石のある点に置こうとすると知らせる。終わったら石を見せる。タイトル画面と、対局中の目のボタンで切り替える（表示だけの設定なので、オンラインでも使える）

### 前の版（circle-cross-game）から

前の版は、10×10 のマス目に ○ と ● を交互に置く2人用の五目並べ（5つ以上で勝ち）で、「目隠し」「待った」「リセット」と、直前の手の強調があった。

- **残したもの：** 5つ以上並べたら勝ちのルール（長連も勝ち）、10路の盤、目隠し（石を消して直前の手の点だけを示す）、待った、直前の手の強調（金色）、2人で1台
- **変えたもの：**
  - マス目の中ではなく、碁盤の線の交点に黒と白の石を置く（ふつうの五目並べの形）。○ の先手は黒の先手にした
  - 盤は15路を既定にし、10路を選べるようにした
  - 終わりは「勝負あり」の知らせから、結果の画面と五連の線にした。盤が埋まったときの引き分けを足した
  - 目隠しのとき、石のある点に置こうとすると知らせる（前の版は何も起きなかった）。終わったら石を見せる
  - 「リセット」は、タイトルへ戻る・「もう一局」にした
- 前の版にルールの選択はなかったので、連珠（黒の禁じ手）は入れていない

## CPU

`public/js/ai.js` の読み。乱数は盤から作るシードだけを使うので、同じ局面なら同じ手になる。ブラウザでは Web Worker（`cpu-worker.js`）で考え、画面を止めない。

- **形の表：** 点に石を置いたとして、4つの方向それぞれで前後4つずつ（9マス）の並びから形（五・活四・四・活三・三・活二・二）を決める。真ん中以外の8マスの組は 3^8＝6561 通りなので、読み込みのときに表を作る（四は五になる点の数、三は1つ足すと四・活四になるか、二は1つ足すと三・活三になるかで決める）
- **点の値：** 4方向の形をまとめる（五 > 活四・四四 > 四三 > 三三 > 四・活三 > ……）。攻め（自分の形）と守り（相手がそこに置いたときの形）を足して候補を並べる。候補は石から2マス以内の空き点
- **決まった手：** 五にできれば打つ。相手に五の点（四）があれば止める（読みの手数に数えない）
- **VCF：** 四を続けて相手に止めさせ、最後に止められない形（五・活四・四四）を作る勝ち筋を探す
- **αβ探索：** 候補の上位だけを読むネガマックス。葉は、5マスの枠ごとの石の数（石を置く・外すたびに差分で直す）と、残った脅威（活三・四）で見積もる。相手の活四や四四が残る局面は負けとみる

| 強さ | やり方 |
|---|---|
| やさしい | 五は逃さない。相手の四は 85% だけ止め、守りを軽く見て、よさそうな6手から乱数で選ぶ |
| ふつう | 五・四の止め、6手までの VCF、3手先までの αβ（幅 10・8・6） |
| つよい | 16手までの VCF、6手先までの αβ（幅 14・10・8・6・5・4）。上位の手のうち、相手に VCF が残る手を避ける |

持ち時間があるときは、残りの時間から1手に使う時間を決め（`clock.js` の `cpuBudget`）、読みをその時間で打ち切る。時計がなくても、ふつう 1.5 秒・つよい 2.5 秒で打ち切る（安全弁。ふつうは読みの手数で終わる）。

ヒントは「ふつう」の読みで選ぶ。

### 勝率と時間

`npm run cpu-match`（引数なしで、ふつう 対 やさしい・つよい 対 ふつうを15路で20試合ずつ）と `node scripts/cpu-match.mjs <試合数> <強さA> <強さB> <盤>` で測った（開発用の Mac。最初の2手は真ん中の 5×5 に乱数で置き、試合ごとに黒・白を入れ替える）。

| 対戦 | 盤 | 試合数 | 勝率（A） | 1手の平均（最長） |
|---|---|---|---|---|
| ふつう 対 やさしい | 15路 | 20 | 95% | 2ms（16ms）／0ms |
| つよい 対 ふつう | 15路 | 20 | 90% | 47ms（213ms）／2ms |
| ふつう 対 やさしい | 10路 | 20 | 100% | 2ms（7ms）／0ms |
| つよい 対 ふつう | 10路 | 20 | 60%（引き分け 20%） | 50ms（449ms）／2ms |

どの組み合わせでも、止まった対局はない。15路のつよいどうしは100手を超える長い対局になり、1手は平均 0.16 秒・最長 1.1 秒ほど。

## 開発

素の HTML / CSS / JavaScript（ES Modules）。ビルドはない。

```bash
npm test                                            # Vitest
python3 -m http.server 8090 --directory public      # http://localhost:8090/
npm run cpu-match                                   # CPU どうしの勝率
```

### ファイル

| ファイル | 役割 |

| `public/js/rules.js` | 盤・座標・五連の判定（DOM に依存しない） |
| `public/js/game.js` | 進行（手番・五連・引き分け・投了・持ち時間）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現する。断る操作は状態を変えない |
| `public/js/clock.js` | 持ち時間の計算（chess・shogi・go と同じ中身） |
| `public/js/game-view.js` | 席ごとのビュー（盤・色・手順・時計。シードは入れない） |
| `public/js/ai.js` | CPU の読み（形の表・VCF・αβ探索） |
| `public/js/cpu-player.js` | CPU の強さと、ビューから手を決める処理・ヒント（`suggest`） |
| `public/js/cpu-worker.js` | CPU の読みを Web Worker で行う |
| `public/js/game-controller.js` | ローカルの対局（CPU 戦・2人で1台）。待った、保存と続きから、CPU を間を置いて打たせる、持ち時間のタイマー |
| `public/js/ui.js`・`art.js` | 画面と絵 |
| `public/js/music.js`・`sound/bgm.js` | 音（BGM「縁側の午後」と共通の効果音） |
| `public/sw.js`・`manifest.webmanifest` | PWA（自分のファイルはネットワークを先に、字体はキャッシュを先に使う） |
| `server/src/game-definition.js` | オンライン対戦の「ゲームの定義」（netplay-kit の形） |
| `scripts/cpu-match.mjs` | CPU どうしの対局と勝率・1手の時間 |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で（片方を CPU にもできる）、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU（ふつう）が引き継ぐ（記録の players に残るので、部屋を読み直しても CPU のまま）。オンラインでは待ったとヒントを出さない。

盤の大きさ（15路・10路。既定は15路）と持ち時間はロビーで決める。黒の席はサーバーの乱数で作るシードで決める（乱数はこれだけなので、定義は `perfectInformation: true`。シードはビューに入れない）。時間切れは、サーバーの時刻で、次の操作が届いたときと期限（端末は相手の時計が0になったら ping を送る）で確かめる。結果は定義の `result`（勝った席か引き分け）で、利用者ごとの記録に入る。CPU 戦の結果は、終わったときに画面から `recordResult` で送る。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'gomoku' })`。web-games の1つのスタックから `?game=gomoku` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
