# サグラダ

ダイスを自分の窓に置いてステンドグラスを作るボードゲーム「サグラダ（Sagrada、Adrian Adamescu・Daryl Andrews、Floodgate Games 2017）」の基本ゲーム（拡張なし）を、ブラウザで遊べるようにしたもの。2〜4人（あなた＋CPU 1〜3人）と、1人用。スマホの縦持ち・横持ちのどちらでも、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

ダイス・窓・バラ窓の絵とアイコンは、すべて SVG と CSS で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。窓の名前は原作の名前のまま、道具と目標の名前は日本語に直したもの。

## 遊び方（基本ゲーム）

- 90個のダイス（赤・黄・緑・青・紫 × 18）を袋に入れる
- 各人に個人の目標（色）1枚と窓枠カード2枚を配る。カードの表裏の4つの窓から1つを選ぶ。窓の難しさ（3〜6）の数だけ好意トークンを持つ
- 道具3枚と公共の目標3枚を並べる
- 10ラウンド。ラウンドの始めに、スタートの人が袋から人数×2＋1個を引いて振り、ドラフトプールにする
- 手番はスタートの人から順に1周し、最後の人から逆に戻る（1→2→3→3→2→1）。手番では、次の2つを好きな順に行える（どちらもしなくてよい）
  - プールのダイスを1個選んで、窓に置く
  - 道具を1枚使う：だれも使っていない道具には好意トークンを1つ、使われた道具には2つ置く
- ラウンドの終わりに、残ったダイスをラウンドトラックに置く。スタートの人は次の人へ

置き方：

- 最初のダイスは縁か角のマスに。2個目からは、すでにあるダイスに縦横斜めのどこかで接するマスに
- 色のマスにはその色、目のマスにはその目のダイスだけ。白いマスは何でも
- 縦横に同じ色・同じ目のダイスを並べない（斜めはよい）

得点（10ラウンドのあと）：

| 項目 | 点 |
|---|---|
| 公共の目標 | 下の表。同じ目標で何回でも点になる。行・列の目標は埋まった行・列だけ |
| 個人の目標 | 自分の色のダイスの目の合計 |
| 好意トークン | 残り1つにつき1点 |
| 空きマス | 1つにつき −1点 |

同点は、個人の目標の点 → 残りの好意トークン → 最終ラウンドの手番の逆順（その周で手番があとだった人が上）で決める。

| 公共の目標 | 点 |
|---|---|
| 行の色違い（同じ色のない行） | 6 |
| 列の色違い（同じ色のない列） | 5 |
| 行の目違い（同じ目のない行） | 5 |
| 列の目違い（同じ目のない列） | 4 |
| 淡い色合い（1と2の組） | 2 |
| 中くらいの色合い（3と4の組） | 2 |
| 深い色合い（5と6の組） | 2 |
| 目の揃い（1〜6が1つずつの組） | 5 |
| 色の揃い（5色が1つずつの組） | 4 |
| 色の斜め（斜めに同じ色と接するダイス） | 1個1点 |

| 道具（1人用で払う色） | 効果 |
|---|---|
| やっとこ（紫） | 選んだダイスの目を1つ増やすか減らす（1を6に、6を1にはできない） |
| ガラス絵の筆（青） | 窓のダイス1個を、色の制約を無視して動かす |
| 銅箔のへら（赤） | 窓のダイス1個を、目の制約を無視して動かす |
| 鉛線のへら（黄） | 窓のダイスをちょうど2個、決まりを守って動かす |
| レンズカッター（緑） | 選んだダイスを、ラウンドトラックのダイスと入れ替える |
| フラックスの刷毛（紫） | 選んだダイスを振り直す。置けなければプールに戻す |
| 艶出しの槌（青） | プールのダイスを全部振り直す（2回目の手番で、選ぶ前だけ） |
| 続けざまのやっとこ（赤） | 1回目の手番で選んだあと、すぐにもう1個選ぶ。このラウンドの2回目の手番はない |
| コルクの定規（黄） | 選んだダイスを、ほかのダイスと接しないマスに置く |
| 砥石（緑） | 選んだダイスを裏返す（6と1、5と2、4と3） |
| フラックス落とし（紫） | 選んだダイスを袋に戻し、1個を引いて目を選んで置く（置かなければプールへ） |
| タップホイール（青） | ラウンドトラックにある色のダイスを、同じ色どうしで2個まで動かす |

### 1人用

- 好意トークンは使わない。公共の目標2枚、個人の目標2枚（終わりに点の多い方を使う）
- 道具は1〜5枚（タイトル画面で選ぶ。多いほどやさしい）。プールにある、道具の色のダイス1個で払って使う。道具は1回ずつ。払ったダイスはゲームから除く
- 毎ラウンド4個を振り、手番は2回
- 空きマスは1つ −3点。ラウンドトラックのダイスの目の合計（目標の点）より多ければ勝ち（同じ点は負け）

## 資料と、資料で分からない点の決め方

ルールは、Floodgate Games の英語版ルールブック（v1.2）を読んで合わせた。人数ごとのダイスの数、往復の手番、置き方、好意トークン、得点（行・列の目標は埋まった行・列だけ）、同点、1人用（目標の点、道具の払い方、空きマス −3）はルールブックのとおり。

窓枠24枚と道具・目標の中身は、ルールブックに一覧がないので、公開されている実装と照らし合わせた。

| 項目 | 資料 | 照らし合わせた結果 |
|---|---|---|
| 窓枠24枚の並びと難しさ | koenheltzel/bga-sagrada（BGA の実装）、Zomis/Games、CalvinNeo/OpenBoardGame、Vermihunter/Sagrada、Wolverick1996/Prova_finale_ingsw | 21枚は5つで一致。食い違いは3点で、多い方を採った（下） |
| 窓枠カードの表裏の組 | BGA の実装 | 組を持っていたのはこれだけ（CalvinNeo も BGA に合わせたと書いている） |
| 道具12枚の色 | BGA の実装、Zomis/Games | 一致 |
| 公共の目標10枚と点 | BGA の実装、Zomis/Games、CalvinNeo/OpenBoardGame | 一致。ルールブックの例（列の色違い5点・淡い色合い2点・色の揃い4点）とも一致 |

窓枠の食い違い：

- Shadow Thief の最下段の4マス目：BGA の実装だけが「6」、ほかの4つは「4」。「4」にした
- Via Lux の3段目：Vermihunter だけが紫のマスを「/」と書いていた（書き損じ）。ほかの4つの「紫」にした
- Industria の難しさ：Vermihunter だけが「6」、ほかの4つは「5」。「5」にした

テストで、24枚のどれにも縦横に同じ色・同じ目の制約が並んでいないことを確かめている（写し間違いがあれば、まず引っかかる）。

資料で決まらない点と、読み方が分かれる点は、次のように決めた。

- 色の斜め：斜めに同じ色のダイスと接しているダイスの数（つながりの中のダイスを1個ずつ数える）
- 組の目標（淡い色合いなど）：組の数は、必要な目や色のうち一番少ないものの数
- 選んだダイスに手を加える道具（やっとこ・砥石・レンズカッター・コルクの定規）は、置くマスまで1つの操作で決める。手を加えたダイスを置ける場所がないときだけ、プールに戻せる（その手番の「選ぶ」は使ったことになる）
- フラックスの刷毛：置ける場所があれば、必ず置く。フラックス落とし：置かずにプールに戻してもよい（カードの文のとおり）
- レンズカッター：プールのダイスとラウンドトラックのダイスの色と目を入れ替え、入れ替えたダイスを置く
- 動かす道具は、動かすダイスを外してから決まりを確かめる。鉛線のへらとタップホイールは、2個を順に動かす（同じダイスを2回は動かさない）
- コルクの定規：窓が空なら、縁の決まりは守る
- 続けざまのやっとこ：1回目の手番で、選んで置いたあとに使う。1人用でも、そのラウンドの2回目の手番がなくなる
- 置けるダイスがなく、道具も使えない人の番は、自動で飛ばす。選んで置いたあと、道具を使えない（使った・払えない）ときは、自動で番を終える
- 最初のスタートの人はランダム。ラウンドごとに次の人へ
- 個人の目標の色は全員違う（5枚から配る）
- 1人用で目標の点と同じ点は負け（ルールブックの「より多ければ勝ち」）

## 画面

- 縦持ちは、上から ほかの人の窓（小さく）・ラウンドトラック・案内・プール・自分の窓。自分の窓が残りの高さを使い、最小の画面（375×548）でマスは約 50px になる
- 横持ちと PC は、自分の窓を左に、ほかの人・ラウンドトラック・プールを右に置く
- プールのダイスを押すと置けるマスが光り、光るマスを押して置く。ダイスを指でマスまで引っ張って置くこともできる
- 「道具・目標」で、道具（使えるものは「使う」が押せる）・公共の目標・個人の目標と、それぞれの今の点を見る。使える道具があると、ボタンに金色の点が付く
- 道具を使うと、上の案内に手順（ダイスを選ぶ → 増やすか減らすか → 置くマス、など）が出て、押せるものが光る
- ほかの人の窓を押すと大きく見られる。ラウンドトラックを押すと、置かれたダイスを全部見られる
- 操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。CPU は自分の席のビュー（公開された情報と、自分の個人の目標）だけを見て決め、袋から次に出るダイスやほかの人の個人の目標はのぞかない（テストで、それらを入れ替えても手が変わらないことを確かめている）。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう：窓の良さを点にし、置いたあとの点が一番高い手を選ぶ
  - 置ける場所を残す：空きマスごとに、置ける（色・目）の組の数を数え、0になるマスは −2.2、2以下は −0.6、5以下は −0.2
  - 目標に寄せる：行・列の目標は、まだ重なりのない行・列を埋まり具合の2乗で見込む。組の目標と色の斜めは今の点。個人の目標の色の目の合計
  - 置けないときや、置くより十分に良いときは、やっとこ・砥石・コルクの定規を使う（ほかの道具は使わない）
  - 窓は、難しさ（好意トークン）と、個人の目標の色のマスの数で選ぶ
  - 1人用では、取ったダイスと払ったダイスの目だけ目標の点が下がるので、その分を足して比べる
- やさしい：置けるところから、点の見積もりに大きな迷い（0〜12点）を足して選ぶ。道具は使わない。窓は気まぐれに選ぶ

```bash
# 試合数・人数・席ごとの強さ（easy・normal）。席の有利を消すため、試合ごとに強さの並びをずらす
node scripts/cpu-match.mjs 1000 2 normal,easy
# 1人用：試合数・1・強さ・道具の枚数
node scripts/cpu-match.mjs 400 1 normal 5
```

| 対戦 | 試合数 | ふつうの1席あたりの勝率 | やさしいの1席あたりの勝率 | 平均点（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（ふつう・やさしい） | 1000 | 77.9% | 22.1% | 44.5／34.3 |
| 3人（ふつう・やさしい2） | 600 | 71.0% | 14.5% | 50.2／38.1 |
| 4人（ふつう2・やさしい2） | 400 | 43.0% | 7.0% | 52.8／42.0 |
| 2人（ふつう・ふつう） | 600 | 50.0% | — | 44.6 |

どの組み合わせでも、止まった試合はない。見積もりの重み（置けないマスの減点 3.5、個人の目標 1.25、行・列の見込み、窓の難しさの重み、埋めることの重み、道具を使う基準）を変えた版は、どれも今の版との2人戦 300 試合で 42.0〜50.7%（互角か負け越し）だったので、今の重みのままにした。

1人用では、CPU（ふつう）は目標の点を超えられない（道具5枚・1枚とも 400 試合で 0%。目標の点は平均 66、CPU は平均 26 点で、一番近い試合で 3 点差）。1人用は人が遊ぶためのもので、CPU は止まらずに終わることだけを確かめている。

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる（1人で遊ぶのはローカルだけ）。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'sagrada' })`。web-games の1つのスタックから `?game=sagrada` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/data.js` | 色、窓枠24枚と表裏の組、道具12枚、公共の目標10枚 |
| `public/js/rules.js` | 置き方の決まり（置けるか・動かせるか）と得点 |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（個人の目標・配られた窓・選ぶ前の窓を隠す。袋は色ごとの数だけ） |
| `public/js/cpu-player.js` | CPU（ビューだけを見る） |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない。部屋は2〜4人） |
| `server/src/handler.js`・`public/js/online-config.js`・`public/js/netplay/` | オンライン対戦のサーバーの入口・接続先・netplay-kit の写し |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率・平均点（1人用は目標を超えた割合） |

操作の種類：`choose`（窓）・`draft`（ダイスとマス）・`tool`（道具。`die`・`delta`・`track`・`cell`・`from`・`to`・`moves`、1人用は `pay`）・`place`（振り直した・引いたダイスを置くマス。null ならプールに戻す）・`fluxValue`（フラックス落としの目）・`end`（番を終える）。

ゲームの設定 `options` は `{ seed, soloTools（1人用の道具の枚数）, tools（使う道具を決めるとき。テスト用） }`。

テスト（`test/`）：

- `rules.test.js`：窓24枚のデータ（表裏の組、制約が縦横に並ばない）、置き方（縁・接する・同じ色と目・マスの制約・制約の無視・コルクの定規・動かす）、各目標の点、合計と1人用の点
- `game.test.js`：配り方と好意トークン、人数ごとのダイスの数、往復の手番とスタートの人の交代、断る操作で状態が変わらないこと、できることのない番を飛ばすこと、道具12枚それぞれ（コストの1と2、1人用の払い）、終わりと同点、1人用の目標の点
- `replay.test.js`：記録からの再現（1〜4人、途中からも、道具を使う試合も）、CPU の判断がゲームの乱数を使わないこと、道具12枚を割り振ってランダムな操作を浴びせても断った操作で状態とダイスの数が変わらず再現できること
- `cpu.test.js`：CPU どうしの試合が人数（1〜4）・強さ・シードを変えても止まらないこと、ふつうがやさしいに勝ち越すこと、CPU がビューだけを見ること、場面ごとの判断
- `game-definition.test.js`：オンライン対戦の定義と、ビューで個人の目標・配られた窓・シードが漏れないこと
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン
