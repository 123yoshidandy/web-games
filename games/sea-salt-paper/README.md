# シーソルト＆ペーパー

カードを集めて組をそろえ、「ストップ」か「ラストチャンス」でラウンドを終えるカードゲーム「シーソルト＆ペーパー（Sea Salt & Paper、Bombyx 2022）」の基本ゲームを、ブラウザで遊べるようにしたもの（拡張の Extra Salt・Extra Pepper は入れていない）。CPU を相手に 2〜4 人で遊べる（人間 1 人＋CPU 1〜3 人）。スマホの縦画面と PC に対応し、ホーム画面に追加するとオフラインでも遊べる（PWA）。

カードの折り紙の絵、アイコンは自作。

## 遊ぶ

ビルドは要らない。リポジトリのルートで HTTP サーバーを立てて開く。

```bash
python3 -m http.server 8080
# http://localhost:8080/public/ を開く（ルートを開くと public/ へ移る）
```

## ルール

- カードは 58 枚
  - 2 枚組：カニ 9・ボート 8・魚 7・泳ぐ人 5・サメ 5
  - 収集：貝 6・タコ 5・ペンギン 3・船乗り 2
  - 倍率：灯台・魚の群れ・ペンギンの群れ・船長 各 1
  - 人魚 4
- ラウンドの準備：58 枚を切って山札にし、上から 1 枚ずつ表にして、捨て札の山を 2 つ作る。手札は 0 枚から
- 手番
  1. 引く：山札の上から 2 枚を見て 1 枚を手札に入れ、もう 1 枚を表にして好きな捨て札の山に置く（空の山があれば、そこに置く）。または、捨て札の山の一番上を 1 枚取る（捨て札の山の中は見られない）
  2. 2 枚組を出す（何組でも、出さなくてもよい）。出すと効果が働く
     - カニ 2 枚：捨て札の山を 1 つ選んで中を見て、1 枚を手札に入れる
     - ボート 2 枚：手番をもう 1 回行う
     - 魚 2 枚：山札の上を 1 枚手札に入れる
     - 泳ぐ人とサメ：ほかの人の手札から 1 枚をランダムに取る
  3. カードの点（手札と出した 2 枚組）が 7 点以上なら、ラウンドを終えられる
- カードの点
  - 2 枚組：1 組 1 点。出していなくても、手札でそろっていれば数える
  - 貝：1〜6 枚で 0・2・4・6・8・10 点／タコ：1〜5 枚で 0・3・6・9・12 点／ペンギン：1〜3 枚で 1・3・5 点／船乗り：1〜2 枚で 0・5 点
  - 灯台はボート 1 枚につき 1 点、魚の群れは魚 1 枚につき 1 点、ペンギンの群れはペンギン 1 枚につき 2 点、船長は船乗り 1 枚につき 3 点
  - 人魚：1 枚目は一番多い色の枚数、2 枚目は 2 番目に多い色の枚数…が点
  - 色のボーナス：一番多い色の枚数
- ラウンドの終わり
  - ストップ：すぐに終わり、全員がカードの点を得る
  - ラストチャンス：ほかの人が 1 手番ずつ行ってから終わる。宣言した人のカードの点が一番多ければ（同点を含む）、宣言した人はカードの点＋色のボーナス、ほかの人は色のボーナスだけ。そうでなければ、宣言した人は色のボーナスだけ、ほかの人はカードの点を得る
  - 手番の終わりに山札がなければ、そのラウンドは点なしで終わる
  - 次のラウンドは、終わりを宣言した人の次の人から
- ゲームの終わり：だれかが目標の点（2 人 40・3 人 35・4 人 30）に届いたら終わり、点の多い人の勝ち。人魚を 4 枚持ったら、その場で勝ち

### 資料

- ルールは公開されているルールブックの要約（rulespal.com の Sea Salt & Paper のページ）と、有志のルールのまとめ（tekeli.li の Roger's Rules）で確かめた
- カードごとの色は、2 つを照らし合わせた（`public/js/cards.js` の冒頭）
  - 実装のカードのデータ（github.com/th0bo/sea-salt-paper）
  - 箱の色の一覧のカードの、色ごとの枚数（紺 9・水色 9・黄 8・黒 8・黄緑 6・白 4・紫 4・灰 4・薄橙 3・桃 2・橙 1。github.com/JFrusher/SSAP）。上のデータの色を数えると、すべて一致する

## 資料で分からない点の決め方

ルールブックに書かれていない、または読み方が分かれる点は、次のように決めた（`public/js/game.js` の冒頭にも同じことを書いている）。

| 場面 | 決め方 |
|---|---|
| 人魚の白 | 白は人魚だけの色で、色のボーナスにも人魚の点にも数えない（参考にした実装と同じ） |
| 人魚 4 枚の「その場で勝ち」 | 4 枚目が手札に入った時点で勝ち（引く・捨て札から取る・カニ・魚・相手から取る、のどれでも） |
| 同点のときの勝ち | 資料には「最後のラウンドで手番の順が後の人」とある。最後のラウンドの最初の手番の人から数えて、後の人を勝ちにした |
| 山札が 1 枚だけのときに山札から引く | その 1 枚を手札に入れる（捨て札には置かない） |
| ラストチャンスの最中に取られるか | 宣言した人と、最後の手番を終えた人の手札は公開されているので、サメと泳ぐ人で取れない |
| ラストチャンスの最後の手番でボートの組を出す | もう 1 回手番を行える（ラウンドは終えられない） |
| ラストチャンスの最中に山札が尽きた | 手番の終わりに山札がなければ、点なしで終わる（ラストチャンスでも同じ。ストップだけは点を数える） |
| 効果が働かない 2 枚組 | 取れる相手がいない（全員の手札が 0 枚か公開済み）サメと泳ぐ人、捨て札が両方空のカニ、山札が空の魚は、効果なしで出せる（1 点は数える） |
| 山札が尽きたラウンドの次 | 最後に手番を行った人の次の人から |
| ラウンドを終える 7 点 | 色のボーナスは含めない（カードの点だけ） |

## 操作

- 自分の手番では、引けるもの（山札と捨て札の山）が金色に光る。押すと引く
- 山札から引いた 2 枚は手札の上に出る。残す 1 枚を押すと、置ける捨て札の山が光る（置ける山が 1 つなら、すぐに置く）
- 手札を 2 枚押して組になれば、「出す」が出る。1 枚押すと、組になるカードに白い縁が付く。サメと泳ぐ人で、取れる相手が何人もいれば、上の欄の相手を押して選ぶ
- カニの組を出すと捨て札の山が光る。押した山の中身が出るので、1 枚を選ぶ
- 7 点以上なら「ストップ」「ラストチャンス」が出る。「ターン終了」で手番を終える
- 中ほどの欄は、出した 2 枚組・このラウンドの点（7 点以上で金色）・色のボーナス・合計
- 上の欄は相手の合計・手札の枚数・出した組の数。押すと、出した組（ラストチャンスで公開した手札も）を見られる
- 手番でないときにカードを押すと、カードの説明が出る
- 途中で閉じても、タイトルの「続きから」で再開できる（操作の記録を保存して再現する）

## CPU

自分のビュー（自分の手札と、見えているカード）だけで判断する。ほかの人の手札・山札の並び・捨て札の山の中は見ない。

- 引く：捨て札の一番上と、山札（見えていないカードの平均と、2 枚から選べる分の上乗せ）を比べる。カードの値打ちは「今の点＋これから点になる見込み（そろいかけの組・収集の途中など）＋2 枚組の効果」で見積もる
- 2 枚組：出せるものはすべて出す（魚→カニ→サメと泳ぐ人→ボートの順。サメと泳ぐ人は手札の多い人から取る）
- ラウンドの終わり：相手の点を「出した組の点＋手札 1 枚につき 0.75 点」で見積もる。差が十分あればラストチャンス、決めた点（ふつうは 9 点）に届けばストップ。目標の点に届くときと、山札が少ないときは、すぐにストップ
- やさしい・ふつう の 2 段階（画面で選ぶ）。やさしいは、見積もりの揺れが大きく、7 点で早めに止めやすい。`strong`（揺れなし）は強さを測るときだけ使う
- 強さの測定：`npm run cpu-match -- <試合数> <人数> <席ごとの強さ>`（最初の手番は試合ごとに入れ替える）

2026-11-18 に測った勝率：

| 対戦 | 試合数 | 勝率 |
|---|---|---|
| やさしい 対 ふつう（2 人） | 200 | 22.5% 対 77.5% |
| ふつう 対 strong（2 人） | 200 | 51.5% 対 48.5% |
| やさしい・ふつう・やさしい・ふつう（4 人） | 100 | 8%・31%・13%・48% |
| ふつう 3 人 | 100 | 29%・34%・37% |

どの組み合わせでも全試合が最後まで進んだ。1 試合は平均 5〜6 ラウンド。ふつうと strong はほぼ互角で、揺れを減らしても強くならない（強さは、終わり方を決める方針で決まっている）。

## 開発

```bash
npm install
npm test                                  # Vitest（得点・進行・ビュー・CPU・記録の再現・ファズ・ゲームの定義・PWA）
npm run cpu-match -- 200 2 easy,normal    # CPU どうしの勝率
```

- ロジック（`game.js`）は DOM に依存しない。操作の入口は `applyCommand` の 1 つで、受け付けた操作を記録し、`Game.replay` で同じゲームを再現できる（山札の並びと、相手から取るカードはシードから決まる）
- 隠す情報（ほかの人の手札・山札から引いた 2 枚・カニで見ている捨て札の山）は、ビュー（`game-view.js`）で本人以外から消す。出来事も、見てよい人（`visibleTo`）でなければカードを消す
- 画面を確かめるときは、`python3 -m http.server <port>` で配信し、スマホの縦の大きさ（375×548 など）で開く。`window.__app` から画面の状態に触れられる
- service worker（`public/sw.js`）が先に読むファイルの一覧は、JS を足したら書き足す（`test/pwa.test.js` が確かめる）

## ファイルの構成

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。ラウンドの結果は、人がいればだれが進めてもよい。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'sea-salt-paper' })`。web-games の1つのスタックから `?game=sea-salt-paper` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
