# アルハンブラ

お金で建物を買い、自分のアルハンブラ（宮殿）を広げるボードゲーム「アルハンブラ（Alhambra）」の基本ゲームを、ブラウザで CPU と遊べるようにしたもの。2〜6人（あなた＋CPU）。2人のときは、公式の2人用ルール（架空の3人目「ダーク」）で遊ぶ。スマホの縦持ち向け（横向きでも遊べる）。ホーム画面に置くと、オフラインでも遊べる。

絵（建物・お金・アイコン）は、すべて SVG と CSS で自作している。

## 遊び方

- 準備：各自に噴水。お金を1枚ずつ配り、合計が20以上になったら次の人へ。カードの最も少ない人（同じなら合計の少ない人）から始める
- 市場：建物4枚（1〜4番の場所ごとに通貨が決まっている：黄・緑・青・橙）と、お金4枚
- 手番には次のどれか1つ
  - お金を取る：市場の1枚か、合計5までの何枚か
  - 建物を買う：その場所の通貨で、値段以上を払う（おつりはない）。ちょうどの額なら、もう一度行動できる
  - 作り直す：予備の建物を足す・アルハンブラの建物を予備へ戻す・同じ場所で入れ替える（噴水は動かせない）
- 手番の終わりに、買った建物をアルハンブラか予備に置く。そのあと、市場を4枚ずつに補充する
- 置く決まり：向きは変えない。接する辺は両方に城壁があるか両方にない。噴水から城壁を越えずに歩いて行ける。辺で接する。四方を囲まれた空きを作らない
- 得点：お金の山から得点のカードが出たとき（1回目・2回目。山札を5つに分けた2つ目と4つ目の束に入れる）と、終わり（3回目）
  - 建物の種類ごとに、枚数の多い人から 1回目は1位、2回目は2位まで、3回目は3位まで。同じ枚数なら、その順位の点を足して等分（切り捨て）
  - 最も長くつながった外側の城壁、1区画につき1点。予備の建物は数えない
- 終わり：手番の終わりに、建物の袋で市場を4枚にできないとき。できるだけ補充し、市場に残った建物はその通貨を最も多く持つ人が受け取る（同じなら残る）。3回目の得点のあと、点の多い人の勝ち（同じなら引き分け）
- 2人：お金は各1枚抜いて72枚。ダークが最初に6枚、1回目の得点のあとに6枚、2回目の得点のあとに袋の残りの3分の1（切り捨て）の建物を受け取り、建物の多数の得点だけを競う。買った建物をダークに渡してもよい

### ルールブックに書かれていないので決めたこと

- カードの数も合計も同じなら、席の早い人から始める（ルールブックでは最も若い人）
- ちょうどの額で買ったあと、もう一度行動せずに手番を終えてもよい
- お金の山札が尽き、捨て札もないときは、補充できない分を空ける。お金の市場が空で何もできないときは、手番を終えられる
- 最長の城壁は、外側に出ている城壁の区画が、端の点でつながっているものの数とした
- 建物の日本語名（あずまや・後宮・奴隷の家・宮殿・庭園・塔）は、Pavilion・Seraglio・Arcades・Chambers・Garden・Tower の順に当てた

### 画面の操作

- 市場の建物には、手持ちのお金で「ちょうど」払えるか「買える」かの印が出る
- 建物を押すと、その通貨の手札が光り、払い過ぎの最も少ない払い方（ちょうどがあればそれ）が先に選ばれる。手札を押して払い方を変えられる。ちょうどなら「もう一度行動できる」、多ければ払い過ぎの額が出る
- お金は、市場のカードを押して選び「取る」。何枚か選んで合計が5を超えると、そのことが出る
- 置くときは、置ける場所が金の点線で出る。押すと置いたときの姿と、次の得点の見込みの増え方が出る。「予備へ」「ダークへ」（2人のとき）も選べる
- 予備の建物を押すと、足せる場所と入れ替えられる建物が光る。アルハンブラの建物を押すと、予備へ戻せる（戻せないときは理由が出る）
- 右上の「見込み」を押すと、種類ごとの全員の枚数・次の得点の点・城壁・見込みの表が出る。得点のたびに内訳の表が出る
- 上の名前を押すと、その人のアルハンブラと予備が見られる。途中でホームに戻っても、「続きから」で再開できる

## CPU

公開の情報（市場・各自のアルハンブラ・ダーク）と自分の手札だけを見て打つ（相手の手札・山札・袋はのぞかない）。建物の価値を「残りの得点の回数で見た、その種類の順位が上がって増える点」と「置いて伸びる城壁」で見積もり、払い過ぎの少ない買い物を選ぶ。ちょうどの額なら、もう一度行動できるので高く見る。買う価値が低ければ、欲しい建物を買えるようになるお金を取る。予備の建物を置けるなら、作り直しも考える。

強すぎないように、市場の建物の見落とし・評価の揺れ・買えるのに見送る・置き場所をよく考えない・多数の争いを甘く見る、を混ぜている。「やさしい」は「ふつう」より多い。

CPU 同士の対戦で、勝率と得点を測れる（strong は見落としのない比較用で、画面では選べない）。

```bash
# 試合数・席ごとの強さ（2〜6人）
node scripts/cpu-match.mjs 400 easy,normal
```

測った結果：やさしい 対 ふつう は 37%：63%（400試合）。ふつう 対 つよい は ほぼ互角で、ふつうは先読みのない作戦の上限に近い強さ。2〜6人で、すべての試合が最後まで終わる。

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）
python3 -m http.server 8000 --directory public

# テスト（Vitest）
npm install
npm test
```

| ファイル | 役割 |
|---|---|
| `public/js/cards.js` | 建物タイル54枚・お金・通貨・得点の表 |
| `public/js/layout.js` | 置く決まり・外す・入れ替え・最長の城壁 |
| `public/js/game.js` | ルール。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存 |
| `public/js/ui.js`・`art.js` | 画面・絵 |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |
| `server/src/handler.js` | オンライン対戦のサーバーの入口（AWS Lambda） |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/netplay/` | netplay-kit のクライアントとロビーの画面の写し（同期で置く。手で直さない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦 |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜6人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'alhambra' })`。web-games の1つのスタックから `?game=alhambra` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
