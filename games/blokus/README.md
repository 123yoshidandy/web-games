# ブロックス

4色のピースを角でつなげて盤に置いていくゲーム「ブロックス（Blokus、Bernard Tavitian 2000）」の基本ゲームを、ブラウザで CPU と遊べるようにしたもの。2〜4人（あなた＋CPU 1〜3人）。スマホの縦持ち向けで、20×20 の盤とピースの置き場と操作のボタンが、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

絵とアイコンは、すべて自作（公式の画像は使っていない）。

## 遊び方（基本ゲーム）

- 20×20 の盤。4色（青・黄・赤・緑）が21個ずつのピースを持つ（1マス1個・2マス1個・3マス2個・4マス5個・5マス12個、合わせて89マス）
- 青 → 黄 → 赤 → 緑 の順に、1個ずつ置く
- 各色の最初のピースは、その色の角のマスを覆う（青は左上、黄は右上、赤は右下、緑は左下）
- 2個目からは、同じ色のピースと角で1か所以上接するように置く。同じ色とは辺で接してはいけない。ほかの色とは辺で接してよい
- 置けない色はパスする。どの色も置けなくなったら終わり
- 人数
  - 4人：1人1色
  - 3人：1人1色。4色目（緑）は3人が順番に置き、緑の点は数えない
  - 2人：先手が青と赤、後手が黄と緑を持つ。点は2色の合計
- 得点（タイトル画面で選ぶ）
  - 基本：残ったピースのマスの数が少ない人の勝ち
  - 上級：残り1マスにつき −1点。全部置けたら +15点、最後に置いたのが1マスのピースなら、さらに +5点（合わせて +20点）

### 資料と、資料で分からない点の決め方

ルールは、公式のルールブック（Mattel の英語版。本文を RulesPal の頁 https://rulespal.com/blokus/rulebook で読んだ）で確かめた。ピースの数と形、置き方、パス、終わり、基本と上級の得点、2人と3人の遊び方は、ルールブックのとおり。

資料で分からない点と、どう決めたか：

- 最初の角：ルールブックは「盤の角のマスを覆う」とだけ書く。4人で各自が1つずつの角を使うことになるので、色ごとに角を決めた（青は左上から右回り）。好きな空いた角を選べる遊び方は入れていない
- パス：ルールブックは「置けないときはパスする」。置けるのにパスすることはできない（置ける手がなくなったら、自動でパスになる）。一度置けなくなった色は、それ以降も置けないので、その色は終わりにする
- 同点：ルールブックに書かれていない。同点の人がみな勝ち（結果の画面では「引き分け」）
- 先手：ルールブックは青から始めるとだけ書く。青を持つ人（2人なら青と赤を持つ人、3人なら緑を最初に置く人も）は、ゲームごとにランダムに決める
- 3人の緑は、青を持つ人から順に置く。緑が置けなくなっても、残りの3色は続ける
- 上級の得点の「最後が1マス」は、その色の最後に置いたピースが1マスのピースで、かつ全部置けたときだけ（ルールブックのとおり）

### 画面の操作

- 上の帯：4色の残りのマス（今の色は枠で囲む）。自分の色は名前が太字
- 下の置き場のピースを押して選ぶ。置ける位置があれば、盤にそこへ影が出る
- 盤の上で指を動かすと、影がその分だけ動く（指でピースが隠れないように、指の下ではなく動いた分だけ動かす）。押しただけなら、押したマスに影の中心を寄せる
- 回す（右回り）・裏返すで向きを変える。影がはっきりした色（白い縁）なら置ける位置で、✓ で置く。×で選び直す
- 盤の小さな点は、今の色を置ける角（起点）。最初は色の角に印がある
- 下の帯を押すと記録が見られる。操作のたびに途中経過を保存し、タイトル画面の「続きから」で再開できる

## CPU

強さは「ふつう」と「やさしい」。ブロックスには隠す情報がないので、盤をそのまま見る。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）（`public/js/cpu-player.js`）。

- ふつう：置ける手を、大きいピースから最大400手まで試し、「ピースの大きさ・自分の置ける角（起点）の増え方・相手の起点を塞いだ数・序盤は盤の中央へ」を点にして一番大きい手を選ぶ。味方の色（2人のとき）の起点は塞がない。上級の得点法では、1マスのピースを最後に残す。3人の緑は、相手の起点を塞ぐことだけを考える
- やさしい：置ける手から、大きいピースほど選びやすく気まぐれに選ぶ

```bash
# 試合数・席ごとの強さ（easy・normal）・得点法。先手（青）は試合ごとに入れ替える
node scripts/cpu-match.mjs 100 easy,normal advanced
```

| 対戦（上級の得点法） | 試合数 | ふつうの勝率 | やさしいの勝率 | 点の平均（ふつう／やさしい） |
|---|---|---|---|---|
| 2人（やさしい・ふつう） | 100 | 99.0% | 1.0% | −13.3／−56.4 |
| 3人（ふつう・やさしい2人） | 60 | 98.3% | 0.0%・1.7% | 0.9／−30.9・−28.1 |
| 4人（ふつう・やさしい3人） | 60 | 98.3% | 0.0%・0.8%・0.8% | 2.7／−28.9・−31.2・−26.3 |
| 4人（同じ、基本の得点法） | 60 | 98.3% | 0.0%・0.8%・0.8% | −4.3／−28.9・−31.2・−26.3 |
| 2人（ふつう・ふつう） | 100 | 61.5%・38.5%（引き分け3） | — | −24.6／−28.2 |

引き分けは勝った人で等分して数えた。どの組み合わせでも、止まった試合はない。ふつうどうしでは、先手（席0）と後手が試合ごとに入れ替わるので、席の差ではなくシードの偏り（100試合）と見ている。

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

| ファイル | 中身 |
|---|---|
| `public/js/pieces.js` | 21個のピースの形と向き、盤の大きさ、色の角 |
| `public/js/game.js` | 進行（DOM に依存しない）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現できる。断る操作は状態を変えない。置けるかの判定と、置ける手の一覧もここ |
| `public/js/game-view.js` | 席ごとのビュー（隠す情報はないので、シードだけを除く） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | 人間1人と CPU のローカル対戦（途中経過の保存） |
| `public/js/ui.js` | 画面と、ピースの操作 |
| `public/sw.js`・`manifest.webmanifest` | PWA（オフラインでも開ける） |
| `server/src/game-definition.js` | オンライン対戦用のゲームの定義（netplay-kit の形。まだつないでいない） |
| `server/src/handler.js` | オンライン対戦のサーバーの入口（AWS Lambda） |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/netplay/` | netplay-kit のクライアントとロビーの画面の写し（同期で置く。手で直さない） |
| `scripts/cpu-match.mjs` | CPU 同士の対戦と勝率 |

テスト（`test/`）：

- `game.test.js`：ピースの数と形（どれも違う形、向きの数）、人数ごとの色の持ち主、最初の角、角で接して辺で接しない置き方、ほかの色とは辺で接してよいこと、置ける手の一覧がルールと一致すること、パスと終わり、3人の緑の交代、基本と上級の得点、2人と3人の点の数え方、同点、断る操作で状態が変わらないこと
- `replay.test.js`：記録からの再現（JSON を通しても、途中からでも）、CPU の判断が何度考えても同じこと、ランダムな操作を浴びせても断った操作で状態が変わらず再現できること
- `cpu-player.test.js`：CPU どうしの試合が人数・強さ・シード・得点法を変えても止まらないこと、ふつうがやさしいに勝ち越すこと
- `game-definition.test.js`：オンライン対戦の定義（受け付け・断る・保存と再現・CPU・抜けた人）とビュー
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'blokus' })`。web-games の1つのスタックから `?game=blokus` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
