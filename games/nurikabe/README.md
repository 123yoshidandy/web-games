# ぬりかべ

マスを塗って壁にし、残りのマスで、数字と同じ大きさの島を作る論理パズル。どの問題も答えが1つに決まり、理屈だけで解ける。

## 遊び方

- 数字のマスは、その数と同じ大きさの島（塗らないマスのたて・よこのつながり）に1つずつ入る。数字のない島や、数字が2つある島は作れない
- 塗ったマス（壁）はすべてたて・よこにつながる。壁が 2×2 にかたまってはいけない
- 下の「塗る」「・」で付けるものを選び、マスを押すかなぞる（なぞったマスをまとめて。数字のマスは飛ばす）。同じ印のマスを押すと消える。島とわかったマスには「・」を付けておける
- 大きさどおりに閉じた島の数字は薄くなる。2×2 の壁・数字が2つの島・大きすぎる島・閉じたのに小さい島や数字のない島・閉じこめられた壁は赤くなる
- 大きさ：やさしい 5×5・ふつう 7×7・むずかしい 9×9（仮に置いて考えないと進めない所がある）
- **フリープレイ**：難しさを選んで、1問ずつ解く。時間は計るが、ヒントの加算はない
- **今日のパズル**：日付で決まる3問（やさしい・ふつう・むずかしい）。誰が開いても同じ問題になる。合計の時間（ヒントは1回15秒の加算）を、日ごとに記録する
- **タイムアタック**：難しさと問題の数（3・5）を選び、続けて解いた合計の時間を競う。設定ごとに自己ベストを記録する。CPU のライバルを付けると、ライバルの進み具合が並んで出る
- **オンライン**：同じ問題の組を全員で解く早解きレース。合計の時間（ヒント15秒・まちがった盤面30秒の加算）の短い順に順位が付く
- ヒント（電球）は、1つの理屈で決まるマスを光らせ、その理由を出す（大きさどおりの島のまわりは壁・2つの数字の島にはさまれたマスは壁・2×2 にならないように島・出口が1つの島や壁はそこへ伸びる・どの島からも届かないマスは壁・仮に置くと行き詰まる）。まちがった印があれば、先にそれを消すよう示す。待った（1手戻す）と、最初からやり直すこともできる
- **記録**：タイトル画面の「記録」に、フリーの解いた数と最短（ヒントなし）、タイムアタックの自己ベスト、今日のパズルを解いた日数と連続、オンラインの対戦の数と1位の数が出る（端末に保存）。ログインしていれば、共通の利用者ごとの記録（netplay-kit の user-stats）にも送る

## CPU

- CPU は、実際にヒントを当て続けて問題を解き、その手数から解き終わる時間を決める（`js/cpu-player.js`）
  - 時間 = (4秒 + 手数 × 秒数) × 強さの倍率（やさしい 1.8・ふつう 1・つよい 0.55）× ばらつき（0.8〜1.2倍）。1手は1つの理屈で決まるマス（まとめて決まることもある）で、秒数は種類の `cpuSecondsPerStep`
  - ばらつきは、渡された乱数（オンラインはサーバーの乱数、タイムアタックは組のシードから作った乱数）で決める
- タイムアタックのライバルと、オンラインの CPU（ロビーで足す。強さはロビーの設定）に使う。オンラインで部屋を出た人の席も、その時点から CPU が解く
- `npm run cpu-match` で、難しさごとに、ヒントで最後まで解けること・強さごとの時間・強さどうしの勝率を確かめる

## オンライン対戦

- netplay-kit の共通のロビー（公開の部屋）から遊ぶ。2〜4人（CPU を足せる）。ロビーで難しさ・問題の数・CPU の強さを選ぶ
- サーバーが問題の組を作り、問題（数字）だけを配る。シードはビューにも保存にも入れない（問題は見えてよいので、端末で答えを計算されるのは割り切る）
- 端末で解けたら、その盤面を送る。サーバーは種類の `check` で確かめ、解いた時間をサーバーの時刻で記録する（始まる前の 3.5 秒のカウントダウン中に送られたものは 0 秒として数える）
- 人（退出していない人）が全員解き終わるか、30分たったら終わる
- 定義は `server/src/game-definition.js`（中身は puzzle-kit の `public/js/race-definition.js`）

## 開発

このゲームは、パズルのゲームの共通部品 `packages/puzzle-kit` の写し（画面・遊びのロジック・オンラインの定義）に、このゲームの種類を載せたもの。共通の部分は `packages/puzzle-kit` で直して同期する（写しを直接直さない）。手順は `packages/puzzle-kit/README.md`。

```bash
npm test -w games/nurikabe          # 種類の共通の検査・ロジック・記録の再現・オンライン・PWA・記録
npm run cpu-match -w games/nurikabe # CPU の強さと、ヒントで解けるかの確かめ
npm run sw -w games/nurikabe        # sw.js の先読みの一覧を作り直す
node scripts/build-pool.mjs 100     # games/nurikabe で。ふつう・むずかしいの問題の組（pool.js）を作り直す（4〜5分）。直したら npm run sw も
node packages/puzzle-kit/scripts/sync.mjs nurikabe   # web-games の直下で。puzzle-kit を同期する（check で確かめる）
npm run dev:online                  # web-games の直下で。手元のオンライン対戦のサーバー（ws://localhost:8787）
```

画面は `public/` を静的に配れば動く（`python3 -m http.server` など。8080 は避ける）。`?play&difficulty=hard&seed=3` で、その問題のフリープレイがすぐ始まる。

| ファイル | 中身 |
|---|---|
| `public/js/game.js` | このゲームの設定（名前・種類・曲・保存の名前の頭） |
| `public/js/puzzles/nurikabe/` | 種類のロジック（`logic.js`）・問題の組（`pool.js`）・画面（`render.js`）・入口（`index.js`） |
| `scripts/build-pool.mjs` | ふつう・むずかしいの問題の組を作り、1問ずつ理屈で解けることを確かめて `pool.js` に書く |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/sound/bgm.js` | BGM「石庭」 |
| `public/css/theme.css` | このゲームの色 |
| `public/js/main.js` ほか | puzzle-kit の写し（`puzzle-kit.lock.json` に一覧） |

記録：1人用の遊びは、操作（入力・ヒント・待った・最初から）を、遊び始めてからの時間（止めていた間は数えない）と一緒に記録する。`replay(setup, commands)` で同じ局面になり、「続きから」もこれで戻す。

## 決めたこと

- **理屈だけで解ける問題だけを使う**。理屈（`logic.js` の `deduce`）はどれも正しい推論なので、理屈で最後まで解ければ解は1つ。ヒントも同じ理屈で出す
- 問題の作り方：島を1つずつ育てて（ほかの島に触れず、壁のつながりを切らない）答えの盤を作り、2×2 の壁のかたまりを島のマスで崩し、島ごとにでたらめなマスへ大きさを書く。理屈で解けなければ作り直す。小さな島が多いほど解が1つになりやすいので、島の大きさは小さめに偏らせる
- **やさしいはその場で作り、ふつう・むずかしいは前もって作った組から選ぶ**。解が1つの問題になる割合が低く、その場で作ると 7×7 で 0.3 秒、9×9 では 10 秒を超えることがあるため。`scripts/build-pool.mjs` が 100 問ずつ作って確かめ、`pool.js` に並べた。遊ぶときは、シードで1問を選び、回す・裏返すの 8 通りから向きを選ぶ（向きを変えても解は1つのまま）。難しさごとに 800 通りになる
- 難しさの差：やさしい 5×5・ふつう 7×7 は、仮に置かずに解ける問題。むずかしい 9×9 は、「仮に置くと行き詰まる」理屈が1回以上（1〜23回）要る問題だけを組に入れた
- 今日のパズルは、やさしい・ふつう・むずかしいを1問ずつにした（1種類のゲームなので、難しさで変化を付ける）
- ご褒美や集める要素は入れない
