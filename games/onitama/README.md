# オニタマ

動きのカードで師匠と弟子を動かす2人のボードゲーム「オニタマ（Onitama、佐藤 晋平、Arcane Wonders 2014）」の基本ゲームを、ブラウザで CPU と遊べるようにしたもの。スマホの縦持ち向けで、スクロールなしで1画面に収まる。ホーム画面に置くと、オフラインでも遊べる。

盤・駒・カード・動物の墨絵・アイコンは、すべて SVG で自作している（公式の画像は使っていない）。説明の文も自分で書いたもので、公式の文は写していない。

## 遊び方

### 準備

- 5×5 の盤。各自、師匠1つを手前の段の真ん中（神殿の門）に、弟子4つをその左右に置く。あなたは藍（下）、CPU は朱（上）
- 動きのカード16枚から5枚を使う。各自2枚を手札にし、1枚を脇に置く。残りは使わない
- 脇のカードの印（右上の小さな四角）の色の人が先手

### 手番

1. **動く**：手札のカード1枚を選び、自分の駒（師匠か弟子）1つを、カードの図の色の付いたマスへ動かす。図の真ん中の黒いマスが駒で、図は持ち主から見た向き
   - 盤の外と、自分の駒のいるマスには動けない。ほかの駒は飛び越えてよい
   - 相手の駒のマスに動いたら、その駒を取る
2. **入れ替える**：使ったカードを相手の向きに回して脇に置き、脇にあったカードを手札に入れる

動ける手があれば、必ず動く。どのカードでも動けないときだけ、駒を動かさずにカード1枚を脇と入れ替える。

### 勝ち方

- **石の道**：相手の師匠を取る
- **川の道**：自分の師匠を、相手の神殿の門（相手の師匠が最初にいたマス）に入れる。弟子が入っても勝ちにならない

### 資料と、資料で分からない点の決め方

読み比べた資料：

- [A] Arcane Wonders 版の英語のルールブック（© 2015）：https://www.arcanewonders.com/wp-content/uploads/2021/05/Onitama-Rulebook.pdf
- [B] CodinGame の対戦の実装（カードの動きの表）：https://github.com/eulerscheZahl/onitama （`src/main/java/Onitama/Board.java`）
- [C] 有志の実装のカードのデータ（動きと印の色）：https://github.com/JoeTheDave/game-hub （`server/src/games/onitama/data.ts`）
- [D] 有志の実装のカードの印の色：https://github.com/arijit-dasgupta/OnitamaAI （`Onitama_source.py`）

確かめたこと：

- 盤・駒の置き方・カードの配り方・先手の決め方・手番の2つの段階・カードを相手の向きに回すこと・取り方・勝ち方2つ・動けないときの入れ替えは、[A] に従った
- **カード16枚の動き**：[B] と [C] で16枚すべて一致した。[A] の図で見える龍・兎も一致した（[A] には16枚すべての図はない）。テストでもこの表と照らし合わせている
- **印の色**：[C] と [D] で16枚すべて一致した（藍8枚・朱8枚）。[A] の例の龍は朱（赤）で一致する
- 食い違いは見つからなかった。ルールの要約のサイトの一部（https://lehi-innovation.github.io/boardgame-rules/rules/onitama/ ）は蛇の動きを違う形で書いていたが、図も表もない言葉だけの説明なので採らなかった

名前：カードの名前（虎・龍・蛙・兎・蟹・象・鵞鳥・雄鶏・猿・蟷螂・馬・牛・鶴・猪・鰻・蛇）、師匠・弟子、石の道・川の道は、指定された日本語版の呼び方に合わせた。日本語版のルールブックそのものは見ていない。Temple Arch は「神殿の門」と訳した。

資料に書かれていない点は、次のように決めた：

- **千日手**：同じ局面（盤・両者の手札・脇・手番）が3回目に現れたら引き分け。オニタマには引き分けの決まりがないが、CPU どうしや人どうしで同じ手を繰り返すと終わらないため。手札の2枚の並びは区別しない
- **手数の上限**：300手（両者150手ずつ）で決着がつかなければ引き分け（千日手にならずに長引く場合の安全弁）
- **席**：あなたはいつも藍で下。先手は脇のカードの印の色で決まるので、先手・後手は試合ごとに変わる

### 画面の操作

- 自分の駒を押すと、動ける先のマスが光る。光るマスを押すと動く。相手の駒のあるマスには赤い輪が出る
- 先に手札のカードを押すと、そのカードの動きだけが光る（もう一度押すと外れる）
- 2枚のどちらのカードでも行けるマスを押したときは、使うカードが光るので、押して選ぶ
- 動けないときは、カードを押すと脇のカードと入れ替える
- 相手のカードは、相手から見た向き（逆さ）で上に並ぶ。脇のカードは、次に受け取る人（手番の人）の列に「次」として出る
- 直前の手の元のマスと行き先は、色が付く。駒は元のマスから滑って動く
- 同じ局面が2回目になると、上のバーに「同じ局面 2回目」と出る
- 途中で閉じても、「続きから」で再開できる（操作の記録から作り直す）

## CPU

強さは「やさしい」「ふつう」「つよい」。CPU は自分の席のビュー（盤・両者の手札・脇のカード。どれも公開）だけを見て決める。CPU の判断にはゲームの乱数を使わない（記録の再現がずれないように）。同じ点の手は、ビューから作った別の乱数で選ぶ（`public/js/cpu-player.js`）。

- 読み：アルファベータ法のミニマックス（ネガマックス）。読む深さは手の数と局面の数で決め、時間では打ち切らない（端末の速さで手が変わらないように）
  - **やさしい**：2手（自分の手と相手の返し）。勝てる手と、すぐ負ける手は必ず分かる。そのうえで点に大きな迷いを足す
  - **ふつう**：3手
  - **つよい**：必ず5手まで読み、そのあとは読んだ局面の数が15万に届くまで1手ずつ深くする（8手まで）。前の深さで良かった手から試す。上限に届いた読みは捨て、前の深さの答えを使う。勝ち負けが決まったら、それ以上読まない
- 勝ちは早いほど、負けは遅いほど良いとする。勝ち負けの決まった手には迷いを足さない
- 局面の点：弟子1つ 100。師匠と相手の神殿の門の近さ（相手との差）、前に出た弟子、動ける手の数、相手の駒に効いているマス（師匠は重く）
- 千日手の引き分けは読みに入れない

```bash
# 試合数・強さA・強さB（試合ごとに藍と朱を入れ替える）
node scripts/cpu-match.mjs 400 normal easy
```

| 対戦 | 試合数 | 勝率 | 引き分け | 1試合の手数 |
|---|---|---|---|---|
| ふつう 対 やさしい | 400 | 90.5% 対 9.3% | 0.3% | 21.3 |
| ふつう 対 ふつう | 400 | 53.8% 対 46.3%（藍 54.8%・朱 45.3%） | 0% | 19.9 |
| つよい 対 ふつう | 200 | 98.5% 対 1.5% | 0% | 18.5 |
| つよい 対 つよい | 400 | 44.5% 対 53.5%（藍 53.0%・朱 45.0%。先手の勝ち 48.8%） | 2.0% | 40.3 |

どの組み合わせでも、止まった試合はない。つよいどうしは、はじめ100試合で 38.0% 対 61.0%（藍 56.0%・朱 43.0%）と偏って見えたので、400試合で測り直した。同じ強さどうしなので、A と B の差（44.5% 対 53.5%）は試合数による揺れで、400試合でもこのくらいは揺れる。席の差（藍が 8 ポイント多い）は、ふつうどうしの 400 試合（藍 54.8%・朱 45.3%）と同じ向きなので、藍がやや有利な傾向はありそうだが、400試合の揺れ（標準誤差でおよそ 2.5 ポイント）と比べて決め手になるほど大きくはない。先手・後手の差はほぼない（先手の勝ち 48.8%）。決着の内訳は、川の道 255・石の道 137・千日手 8。

1手にかかる時間（開発用の Mac で計測）：ふつうは平均 0.6ms、つよいは平均 103ms・最長 171ms。スマホでは数倍かかる。

上の帯の電球（ヒント）を押すと、強い CPU が読んだ手を示す（駒と行き先を選んでおき、使うカードを光らせる。カードを押せば動く）。盤と手札はすべて公開の情報。

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'onitama' })`。web-games の1つのスタックから `?game=onitama` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

## 開発

```bash
npm install
# 画面（http://localhost:8000/ を開くと public/ へ移る）
python3 -m http.server 8000
# テスト（Vitest）
npm test
```

テスト（`test/`）：

- `rules.test.js`：16枚の動きが照らし合わせた表のとおりであること、印の色、左右が逆の組、駒の置き方、席1の向き（盤を180度回す）、最初の局面の動ける手
- `game.test.js`：使う5枚と先手の決め方（同じシードで同じ）、動いてカードを入れ替える、飛び越え、断る操作で状態が変わらないこと、取る、動けないときだけの入れ替え、石の道・川の道（弟子では勝ちにならない、朱の場合）、千日手（作った局面と、実際に行き来する試合）、手数の上限
- `replay.test.js`：CPU どうしの試合の記録からの再現（途中でも何度も）、でたらめな操作を浴びせても断った操作で状態が変わらず再現できること
- `cpu-player.test.js`：CPU どうしの試合がどの強さでも止まらないこと、どの強さも勝てる手を指すこと、すぐ負ける手を避けること、同じビューなら同じ手、ふつうがやさしいに・つよいがふつうに勝ち越すこと、動けないときの入れ替え
- `game-definition.test.js`：オンライン対戦の定義（2人用、操作の受け付けと断り、CPU、抜けた人の代わり）と、ビューにシードと局面の記録が入らないこと
- `game-controller.test.js`：CPU との対戦の進行、断られた操作の知らせ、保存からの再開
- `pwa.test.js`：service worker が画面のファイルを全部先に読むこと、manifest とアイコン
- `offline.test.js`：service worker を差し替えた入れ物で動かし、ネットワークが切れてもページと JS をキャッシュから返すこと
