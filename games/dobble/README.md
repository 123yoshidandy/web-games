# ドブル（Dobble / Spot it!）

2枚のカードに1つだけある同じマークを、誰よりも早く見つけるカードゲーム「ドブル」のブラウザ版です。タワー（CPU 対戦）・タイムアタック・オンライン対戦で遊べます。スマホ縦向き。

## 遊び方

- カードは 55 枚。どのカードにも 8 個のマーク（全部で 57 種類）があり、**どの2枚にも、同じマークがちょうど1つ**だけあります
- マークの大きさと向きはカードごとにばらばらです（カードの番号で決まり、同じカードはいつも同じ絵）
- **タワー**：全員に1枚ずつ配り、残りを真ん中に表向きで積みます
  - 自分のカードと真ん中のカードの、同じマークをタップします（どちらのカードのマークでもよい）
  - 正しければ真ん中のカードを取り、それが新しい自分のカードになります
  - 違うマークをタップすると、2秒は取れません（点は減りません）
  - 真ん中の山がなくなったら終わり。取った枚数（点）の多い人の勝ち
- **タイムアタック**：1人で、真ん中の山（54 枚）を取り切るまでのタイム。ベスト5を端末に残します
- **オンライン**：2〜4人（足りなければ CPU）で、同じ真ん中のカードを取り合います
- ヒント：真ん中のカードの、同じマークを光らせます。対戦では1点減り、タイムアタックではタイムに5秒足します
- 結果の画面から、記録を時刻どおりに見直す「リプレイ」（×1〜×8）を見られます

## CPU

- 真ん中のカードが変わってから、強さに応じた時間がたつと、共通のマークをタップして取ります。CPU はまちがえません
- 時間は「強さの基準 ×（0.55〜1.45。真ん中ほど出やすい）」で、ときどき見落として 0.8 倍ぶん長くかかります（下限あり）
  - やさしい：基準 4.3 秒（見落とし 20%）、ふつう：2.9 秒（12%）、つよい：1.9 秒（6%）
- 時間の乱数はゲームの乱数を使わず、「シード・席・真ん中の版」から作った別の乱数で決めます。同じ記録からは同じ時刻になり、記録の再現がずれません
- `npm run cpu-match` で、強さの組ごとに 200 試合ずつ戦わせ、勝率と止まる試合がないかを確かめます。1試合で 53 回の早取りを重ねるので、強さが1段違うと、ほぼ強い方が勝ちます

## オンライン対戦

- netplay-kit の「ゲームの定義」（`server/src/game-definition.js`）。部屋には参加者・シード・操作の記録・始まりの時刻だけを保存し、記録から再現します
- 早い者勝ちの判定はサーバーで行います
  - 端末は、タップしたマークと、見ていた真ん中のカードを送ります。時刻はサーバーの時計で付けます（端末の時刻は使いません）
  - サーバーは届いた順に確かめ、最初に届いた正しいタップが取ります。もう取られた真ん中のカードへのタップは、まちがいにせず「先に取られました」と断ります（待ちも付きません）
  - まちがいの2秒の待ちも、サーバーの時刻で確かめます
- CPU は、取る時刻を期限（`deadline`）にし、届いたメッセージのたびに確かめます（Lambda はタイマーを持てないため）。CPU のいる間は、端末が1秒ごとに ping を送ります
- 対戦中に部屋を出た人の席は CPU が続けます（保存と再現のあとも CPU のまま）
- ビューに、シードと真ん中の山の並びは入れません（入れると、これから出るカードを計算できるため）。各自の一番上のカードは表向きなので入れます

## 決めたこと

- 山札は、位数 7 の有限射影平面（57 点・57 直線、1本の直線に 8 点、どの2本も1点で交わる）から作り、原作と同じく 55 枚を使います。性質はテストで全組を確かめます
- マークの絵（57 種類）はすべてオリジナルの SVG です
- 原作のミニゲームのうち、ここでは「タワー」と、それを1人で遊ぶタイムアタックを入れました
- 早い者勝ちで時間を巻き戻せてしまうので、「待った」はありません

## 開発

```bash
npm test -w games/dobble          # ルール・山札の性質・CPU・再現・ヒント・コントローラー・オンライン・PWA のテスト
npm run cpu-match -w games/dobble # CPU どうしの対戦
npm run dev:online                # 手元のオンライン対戦のサーバー（web-games の直下で）
```

- `public/js/deck.js`：射影平面からの山札と、マークの名前
- `public/js/game.js`：ルールと状態（DOM に依存しない）。操作は `applyCommand(seat, { type, symbol, center, t })` の1つの入口で、時刻 `t` も記録に入る
- `public/js/cpu-player.js`：CPU の取る時刻、おすすめ（`suggest`）
- `public/js/game-controller.js`：ローカルのコントローラー（時計・CPU・途中経過の保存）と、リプレイのコントローラー
- `public/js/game-view.js`：ビュー（席から見てよい情報だけ）
- `public/js/symbol-art.js`：マークの絵と、カードの上の並べ方
- `public/js/main.js`：画面と入力
- `server/src/`：オンライン対戦の定義と、Lambda の入口
