# チグリス・ユーフラテス

Reiner Knizia のボードゲーム「チグリス・ユーフラテス（Euphrat & Tigris、Hans im Glück 1997）」の基本ゲームを、ブラウザで CPU と遊べるようにしたものです。2〜4人。スマホの縦持ちでも遊べ、ホーム画面に置けばオフラインでも開けます（PWA）。絵はすべて自作です。

## 遊び方

`public/` を配信して開きます。

```bash
python3 -m http.server 8080 --directory public
```

タイトルで人数（2〜4）と CPU の強さ（やさしい・ふつう）を選んで始めます。あなたは席0（王朝の印は弓）で、ほかの席は CPU です。途中で閉じても「続きから」で再開できます。

### 操作

- 下の段でタイル・指導者・大災害・交換・見送りを選ぶと、盤の置けるマスが光ります
- 盤を押すと、押した点にいちばん近い置けるマスに下書きが出ます（縦持ちでは1マスが約19〜23px なので、少しずれても吸い付く）。「決定」か、同じマスをもう一度押して確定します。下書きの効果（点・内乱・外乱）は、盤の下に出ます
- 盤の自分の指導者を押すと、動かす先を選ぶか「戻す」で手元に戻せます
- 虫眼鏡のボタンで盤を2倍にし、指でスクロールして見られます
- 争いでは、出す枚数を −／＋ で決めて「出す」。守るときは、同点にできる枚数が最初から入っています

### ルールの要点

- 手番に2アクション：タイルを置く／指導者を置く・動かす・戻す／大災害（1人2回）／手札の交換（1〜6枚）／見送る。手番の終わりに手札を6枚に補充
- 王国（指導者のいる地域）にタイルを置くと、同じ色の指導者の持ち主がその色の1点。いなければ王（黒）の持ち主がその色の1点
- 内乱：同じ色の指導者がいる王国に指導者を置く。強さはとなりの神殿の数＋手札から出した赤
- 外乱：タイルで2つの王国をつなぎ、両方に同じ色の指導者がいる。強さは自分の側の王国のその色のタイルの数＋手札から出した同じ色
- 記念碑：同じ色の4枚の正方形。手番の終わりに、記念碑の色の指導者がその王国にいれば、その色の1点
- 宝物：2つ以上ある王国に商人（緑）がいれば、持ち主が1つを残して取る
- 終わり：盤の宝物が2つ以下になるか、手札を補充できない。4色のうちいちばん低い色の点で比べ（宝物は好きな色に足す）、同じなら次に低い色

点と取った宝物は、原作では衝立の裏に伏せるので、画面には自分の分だけ出します（終わると全員の分を見せます）。ログには、だれが何点取ったかが出ます（原作でも、点を取るところは全員が見ているため）。

## 盤と部品

- 盤は横16 × 縦11。川と、最初に神殿と宝物が置かれる10か所は `public/js/board.js` の `MAP` にある
- 文明タイル 153枚：赤（神殿）57・青（農地）36・緑（市場）30・黒（集落）30。赤のうち10枚は最初から盤にあり、袋には143枚
- 指導者は各自4人（王・神官・農民・商人）、大災害は各自2枚、記念碑は2色の組み合わせ6つ、宝物10個

### 盤の配置を照らし合わせた結果

次の4つを、マスごとに照らし合わせました。

| 資料 | 内容 | このゲームの盤と |
|---|---|---|
| cubenations（npm、boardgame.io による実装） | 川・宝物・縁取りのある宝物（`static/board.js`） | 一致 |
| Ken1f/tigris_e（Go の実装、GitHub） | 川・神殿（`board.go`） | 一致 |
| denilis/tigris-euphrates-online（GitHub） | Board Game Arena の120試合の記録から復元した川・神殿・縁取りのある神殿（`game/vendor/engine/boards.js`） | 一致 |
| 0b01/tigris-and-euphrates（Rust の実装、GitHub） | 川・神殿（`src/game.rs` の `BOARD`） | 4か所違う |

Rust の実装だけが、行6（上から0）の神殿・行7と行8の川の端・行9の神殿を、右へ1列ずらしています。ほかの3つが一致しているので、Rust の実装の誤りと見ました。

縁取りのある宝物（商人が先に取る宝物）は、盤の四隅にいちばん近い4つ（左上・右上・左下・右下の寄り）です。ルールの「隅の神殿の宝物を先に取る」と、BGA の記録（縁取りが二重の4つ）と、cubenations が一致しています。Rust の実装は2つだけでした。

ルールの細部は、次の資料で確かめました。

- 1997年版の公式の英訳ルール（Kevin Jacklin・Reiner Knizia）と、Knizia が確認した FAQ v2.3（Chris Lawson のページ。Web Archive から）
- 2015年版のルール本文（rulespal.com）、Board Game Arena のゲームヘルプ、gamerules.com と edp.org の要約

ほかに、PyTigris（Python）と tigrisgame（Java。Craig Moffitt の AI の fork）の盤も、上の3つと同じでした。Mayfair 版の盤の絵には誤りがあり、(5,13) は川ではなく陸です（FAQ）。このゲームの盤も陸です。

### 版の違い

- Hans im Glück 1997（ドイツ語の原版）のあと、Mayfair（2008）と Fantasy Flight Games（2015）から英語版が出ている
- Mayfair 版から盤が両面になり、裏は上級の盤（宝物の神殿14か所。このゲームでは扱わない）
- 統一タイルは、1997年版は全員で1枚、2015年版は1人1枚（同時に使うのは1枚）。遊びは変わらない
- 2015年版は、外乱の強さを「その時点の形」で数える、宝物を「特別な縁のマス」と書く（標準の盤では四隅の4つで同じ）、完全な同点は勝ちを分け合う、と書き足している
- Mayfair 版は、ルールは原版と同じ（FAQ）。盤の絵に1か所誤りがある（上記）

## 資料で分からない点の決め方

ルールブックの書き方がはっきりしない点や、版で揺れている点は、次のように決めました（`public/js/game.js` の先頭にも書いています）。

ルールで確かめたこと（ルールのとおりに作った点）：

- 外乱を起こしたタイルには点が入らない
- 手番の人が関わらない外乱は、手番の人の次（時計回り）の人が攻める。争いが2つ以上なら、手番の人が順番を決める
- 赤の外乱で負けた側の神殿を取り除くとき、宝物の載った神殿と、争いに関わらない指導者のとなりの神殿は残す
- 大災害は、空きマスかタイルの上に置き、宝物・記念碑・指導者のマスには置けない
- 手番の終わりは、記念碑の点 → 全員の補充（手番の人から時計回り。6枚より少ない人が全員。争いで手札を出した人もここで戻る） → 終わりの判定、の順（FAQ）
- 終わりは、手番の終わりに盤の宝物が2つ以下のときか、袋のタイルで補充できなかったとき。アクションや手番の途中では終わらない
- 外乱の強さは、2015年版の書き方に合わせ、その争いを始めるときの盤の形で、つないだタイルから見て自分の側につながっている同じ色のタイルを数える（1997年版は「元の王国」を数える。違いが出るのは、1枚で2つ以上の争いが起きたときの2つ目から）
- 赤の外乱で残す神殿も、強さには数える。点にはならない
- 内乱は、指導者を動かしたときにも起きる
- 最後まで同じ点なら、勝ちを分け合う（2015年版）

分からない点・自分で決めた点：

- **宝物を取る順**：縁取りのある宝物を先に取るのはルールどおり。どれを取るかは自動で選ぶ（縁取りのあるもの、次にマスの番号の小さいもの）。原作では商人の持ち主が選ぶ
- **記念碑**：正方形が2つ以上できたときは、左上のマスがいちばん小さい正方形に建てる（資料に扱いが見つからなかった。1枚で2つの正方形ができることはまれ）
- **記念碑で裏返ったタイル**：色を失い、神殿としても数えない（指導者を支えない）。地域のつながりには数える。宝物は残る
- **争いで出したタイル**：攻める側も守る側も捨てる（袋に戻さない）
- **袋が足りないとき**：手番の終わりの補充で足りなかったら、その手番の終わりで終わる。交換で引ききれなかったときは、引けるだけ引いて続ける（FAQ は「手番のどこかで補充できなかったら」と書くが、交換は補充ではないと見た）
- **見送り**：ルールは「2アクションまで」なので、アクションを使わずに見送れるようにした（打つ手がないときに止まらないように）
- **大災害**：空きマスにも置ける。宝物の神殿・指導者・記念碑・大災害の上には置けない
- **最初の人**：シードから決める

## CPU

CPU は、自分から見えるもの（ビュー：盤・自分の手札と点・ほかの人の手札の枚数）だけを見て手を決めます。ほかの人の手札や点、袋の並びはのぞきません。

- **やさしい**：半分は点が入る手から選び、残りはでたらめ。争いで出す枚数もでたらめ
- **ふつう**：手を1つずつ見える範囲で試し、局面の値がいちばん高い手を選ぶ
  - 局面の値：自分の点を低い順に並べ、低い色ほど重く数える（いちばん低い色を伸ばす手が選ばれる）。宝物は、いちばん低い色に足して数える。盤の指導者は、王国の大きさと守りの強さに応じて足し、ほかの人に点が入る手は引く
  - 争い：相手の手札にその色が何枚あるかを、見えていないタイルの色の割合から二項分布で見積もり、勝つ見込みを出す。仕掛ける手は、勝ったときと負けたときの値を見込みで重み付けして比べ、見込みが低ければ仕掛けない。攻めるときは見込みが8割に届く最小の枚数を出し、守るときは同点にできれば必要な分だけ出す

### 勝率（`npm run cpu-match`）

| 対戦 | 試合 | 結果 |
|---|---|---|
| やさしい 対 ふつう（2人） | 100 | ふつうの勝率 100%（最終得点の平均 2.7 対 18.8） |
| ふつう 対 ふつう（2人） | 60 | 50% 対 50%（席の有利・不利は見えない） |
| やさしい2人 対 ふつう（3人） | 40 | ふつうの勝率 100%（平均 14.6 対 2.5・2.2） |
| やさしい3人 対 ふつう（4人） | 40 | ふつうの勝率 100%（平均 12.0 対 1.7・1.3・1.2） |

どの試合も止まらずに終わりました。やさしいは、指導者を盤に残せず、いちばん低い色が0〜3点で終わることが多く、かなり弱いです。ふつうは大災害を使いません。

```bash
npm install
npm test                      # Vitest
npm run cpu-match -- 100 easy,normal   # CPU 同士の勝率
```

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜4人で、足りない席は CPU で埋められる。ほかの人の手のタイルと袋の中身はビューに入れない。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'tigris-euphrates' })`。web-games の1つのスタックから `?game=tigris-euphrates` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
