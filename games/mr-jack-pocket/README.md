# ミスター・ジャック・ポケット

Bruno Cathala・Ludovic Maublanc の2人用ゲーム「ミスター・ジャック・ポケット（Mr. Jack Pocket、Hurrican 2010）」を、ブラウザで CPU と遊べるようにしたものです。ジャック側か刑事側を選んで遊びます。スマホの縦持ちに合わせ、ホーム画面に置けばオフラインでも開けます（PWA）。絵はすべて自作です（霧のヴィクトリア朝ロンドン）。

## 遊び方

`public/` を配信して開きます。

```bash
python3 -m http.server 8080 --directory public
```

タイトルで、あなたの側（ジャック・刑事）と CPU の強さ（やさしい・ふつう）を選んで始めます。途中で閉じても「続きから」で再開できます。

### 操作

- 下の行動タイルを押して選び、盤の光る行き先やタイルを押して、「決定」
  - 刑事を進める：光る1マス先・2マス先を押す
  - ジョーカー：盤の刑事を押してから、光る1マス先を押す（ジャック側は「動かさない」も選べる）
  - 回転：同じタイルを押すたびに、右回りに向きが変わる
  - 入れ替え：タイルを2枚押す
  - アリバイ：そのまま「決定」
- 下書きは盤に点線で出ます。下書きの盤で刑事から見える容疑者には目の印が付き、盤の下に「見える容疑者 n人」（ジャック側には、ジャックが見えるかどうかも）が出ます
- ジャック側では、ジャックのタイルを赤い点線で囲みます。上の欄に、ジャックの肖像と、引いたアリバイカード（砂時計の数）が出ます
- 上の欄の砂時計は、刑事側からは目撃で得た分だけが見え、伏せたアリバイの枚数が添えられます

### ルールの要点

- 3×3 の街区タイル（容疑者9人）。各タイルは1辺に壁がある T 字の通り。まわりの道（12マス）を、刑事3人（ホームズ・ワトソン・トビー）が時計回りに動く
- ジャックは、アリバイカード9枚から1枚を引いて決める（ジャック側だけが知る）。残り8枚がアリバイの山
- 8ラウンド。奇数ラウンドは行動タイル4枚を投げ、刑事側1枚 → ジャック側2枚 → 刑事側1枚。偶数ラウンドは4枚を裏返し、ジャック側1枚 → 刑事側2枚 → ジャック側1枚
- 行動タイル（表と裏）：ホームズ／アリバイ、ワトソン／トビー、回転／入れ替え、回転／ジョーカー
- ラウンドの終わりに目撃：ジャックが見えていれば、見えていない容疑者が全員無実。見えていなければ、見えている容疑者が全員無実になり、ジャック側が砂時計1つ
- 勝ち：目撃のあとで、残った容疑者がジャックだけなら刑事側。ジャック側の砂時計（目撃の分とアリバイの分）が6つならジャック側

## 資料と照らし合わせた結果

| 資料 | 内容 |
|---|---|
| 公式のルール（Hurrican の英語版 PDF・rulespal.com の本文） | 準備、行動、ラウンドの順、目撃、勝ち（両方を同時に満たしたときの扱いを含む） |
| Board Game Arena のゲームヘルプ（Gamehelpmrjackpocket） | 行動の細部（回転は同じラウンドに同じタイルを2回選べない、ジョーカーはジャック側だけ動かさなくてよい）、目撃、勝ち |
| jreyes935/mr-jack-pocket（Java の実装、GitHub） | 容疑者9人、アリバイカードの砂時計（マダム2、グッドリーとレストレード0、ほかは1）、最初の刑事の位置（ホームズは左上のタイルの左、ワトソンは右上のタイルの右、トビーは下のまん中のタイルの下）と、その3枚の壁を刑事に向けること、タイルの形（9枚とも T 字。ジョセフ・レーンのタイルだけ、無実の面が十字路） |
| mdaubie/MrJackPocket（Java の実装、GitHub） | アリバイカードの砂時計の内訳（0が2枚・1が6枚・2が1枚） |
| cmorrec/mrjackpocket（BGA Studio 向けの PHP 実装）、theophile-wallez・Nitokie・Walfal・husseinfakharany の Java の実装 | 容疑者の色、アリバイの砂時計、レーンの裏が十字路、刑事の位置、行動タイルの表裏、両方を同時に満たしたときの扱い（cmorrec）。どれも上と一致 |

### 資料で食い違う点

- **ジャックだけが残り、砂時計も6つになったあと**：公式のルールは「そのあとジャックが見えたラウンドで刑事側の勝ち」。jreyes935 の実装は、8ラウンドまで決着させず、8ラウンドの終わりにジャックが見えているかで決めている。公式のルールに合わせた
- **バリケード**：公式のルールは「灰色の人物（ジョセフ・レーン）のタイルのバリケードは壁として数える」と書く。絵が建物ではなくバリケードになっているだけで、壁と同じ扱いなので、このゲームでは壁として描いている
- **レーンの裏の十字路**：公式のルールの文には書かれておらず（絵でだけ示されているとみられる）、実装5つ（jreyes935・cmorrec・Walfal・Nitokie・husseinfakharany）で一致した

- **両方の勝ちを同時に満たしたとき**：BGA のゲームヘルプは「8ラウンド目はジャックが見えていれば刑事側」とだけ書き、8ラウンドより前の扱いを書いていない。公式のルールは「8ラウンドより前なら続け、そのあとジャックが見えたラウンドで刑事側の勝ち。8ラウンドの終わりまで見えなければジャック側」。公式のルールに合わせた

## 資料で分からない点の決め方

- **8ラウンドで決着しないとき**：ジャック側の勝ち（刑事側が正体を突き止められなかった）
- **刑事側のアリバイで、すでに無実の容疑者を引いたとき**：何も起きない（札は刑事側の前に置く）
- **入れ替えたタイル**：そのラウンドに回したタイルを入れ替えても、そのタイルはもう回せない（回したことはタイルについて回る）
- **最初の人**：ラウンド1は刑事側から（ルールどおり）
- **両方の勝ちを満たして続けている間**：砂時計やアリバイはそのまま数えるが、勝ち負けはジャックが見えるかどうかだけで決まる

## CPU

CPU はビュー（自分から見てよい情報）だけを見て決めます。刑事側の CPU は、ジャックの正体も、ジャック側が引いたアリバイも見ません。

- **やさしい**：6割はでたらめな手、4割は1手だけ読んだ手
- **ふつう**：このラウンドの残りの手を、相手の手も含めて読む（ミニマックス。手が多いときは2手、少なければ3手まで）。読んだ先は「今、目撃が起きたら」で評価する
  - 刑事側：まだ無実でない容疑者のだれがジャックでも同じ重みとして、目撃のあとに残る容疑者の数の平均と、ジャック側が砂時計を得る見込みを小さくしたい
  - ジャック側：自分の正体で、目撃のあとに残る容疑者の数と、砂時計を得るかを大きくしたい
  - アリバイは、引く札が見えないので見込み（容疑者が減る見込み・砂時計の平均）で数える。砂時計が6つに近いほど、砂時計の重みを上げる

### 勝率（`npm run cpu-match -- 300 normal,normal`、各300試合）

| ジャック側 | 刑事側 | ジャック側の勝率 | 刑事側の勝率 |
|---|---|---|---|
| ふつう | ふつう | 47.7% | 52.3% |
| ふつう | やさしい | 92.7% | 7.3% |
| やさしい | ふつう | 3.0% | 97.0% |
| やさしい | やさしい | 27.7% | 72.3% |

どの試合も止まらずに終わりました。1手を決めるのにかかる時間は、ふつうでも数ミリ秒です。

## オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で、足りない席は CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'mr-jack-pocket' })`。web-games の1つのスタックから `?game=mr-jack-pocket` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）

## 開発

```bash
npm install
npm test                                  # Vitest
npm run cpu-match -- 300 normal,easy      # CPU 同士の勝率（ジャック側,刑事側）
```

| ファイル | 役目 |
|---|---|
| `public/js/game.js` | ルールと進行（DOM に依存しない）。操作は `applyCommand` だけ。記録から `Game.replay` で再現できる。席0がジャック側、席1が刑事側 |
| `public/js/board.js` | 盤の形（3×3 と、まわりの道12マス）、見通しの線 |
| `public/js/data.js` | 容疑者・刑事・行動タイル・アリバイの砂時計 |
| `public/js/game-view.js` | 席から見てよい情報だけのビュー（ジャックの正体・アリバイの山・ジャック側の札を隠す） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦のコントローラー（CPU の間合い、途中経過の保存） |
| `public/js/ui.js`・`art.js`・`main.js` | 画面と絵 |
| `server/src/game-definition.js` | netplay-kit 形式のオンライン対戦の定義 |
| `server/src/handler.js`・`public/js/online-config.js`・`public/js/netplay/` | オンライン対戦のサーバーの入口・接続先・netplay-kit の写し |
| `public/sw.js`・`manifest.webmanifest` | PWA |

テストは、ルール（見通しと壁、目撃、各行動、ラウンドの順と行動タイルの面、勝ち負けと両方を同時に満たしたとき）、記録からの再現、ランダムな操作を浴びせても断った操作で状態が変わらないこと、CPU どうしの試合が強さとシードを変えても止まらないこと、ビューで隠すもの、オンライン対戦の定義、PWA の設定、オフラインでの起動（service worker）を確かめます。
