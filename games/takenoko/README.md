# タケノコ

区画を並べて竹を育て、パンダに食べさせて目標を達成するボードゲーム「タケノコ」（基本ゲーム）を、ブラウザで CPU と遊べるようにしたもの。2〜4人（あなた＋CPU 1〜3人）。スマホの縦・横、PC で遊べ、ホーム画面に追加すればオフラインでも遊べる。

区画・竹・改良・庭師・パンダ・天気の絵と画面はすべて自作。

## 遊ぶ

```bash
python3 -m http.server 8000 --directory public
# http://localhost:8000/ を開く
```

ビルドは要らない（素の HTML / CSS / ES Modules）。

## テスト

```bash
npm install
npm test             # Vitest
npm run bench:cpu    # CPU の強さと試合の長さを測る（node tools/cpu-bench.mjs [試合数] [名前で絞り込み]）
```

## 実装したルール（基本ゲーム、公式のルールブック 2020年の版に合わせた）

- 池（中央）と区画27枚（緑11・黄9・桃7。改良の印つきは各色3枚：緑は池2・囲い2・肥料1、黄と桃は各1）
- 改良のチップは各3つ、水路は20本
- 最初に全員が区画・庭師・パンダの目標を1枚ずつ持つ。最初の手番の人はランダム
- 天気のダイス（2巡目から）：晴れ（行動が3つ、すべて違うもの）、雨（灌漑された区画の竹を1つ）、風（同じ行動を2回してよい）、嵐（パンダを好きな区画へ、竹を1つ食べる）、雲（チップを取って改良のない区画に置く。チップがなければ置いたチップを動かせる）、？（5つから選ぶ）。雨・嵐・雲は使わないこともできる
- 行動（違うものを2つ）
  - 区画：3枚引いて1枚を置き、残りは山の下へ。池の隣か、置いてある2枚以上の隣
  - 灌漑：水路を取ってすぐ置く。2つの区画の境目で、池の縁ではなく、池（の角）か水路につながる場所
  - 庭師：まっすぐ1マス以上進む（池は通れて止まれる、空きは越えられない）。止まった区画と、隣の同じ色の区画の竹が1つ伸びる
  - パンダ：まっすぐ1マス以上進み、止まった区画の竹を1つ食べる（囲いの区画では食べない）
  - 目標：好きな種類の山から1枚引く（手札は5枚まで）
- 竹は灌漑された区画（池の隣・水路に面する・池の改良）でだけ伸び、最大4つ。肥料の区画は2つ伸びる。初めて灌漑された区画には竹が1つ生える
- 目標は手番の中ならいつでも達成できる
  - 区画：その形と色に並び、すべて灌漑されていること（回してよい）
  - 庭師：その色・高さ（ちょうど）・改良の条件の竹があり、庭師がその区画（複数本なら、そのどれか）にいること
  - パンダ：食べた竹を使う（使った竹は戻す）
- 2人は9枚、3人は8枚、4人は7枚の目標を最初に達成した人が皇帝のカード（2点）。ほかの人があと1回ずつ手番をして終わり
- 得点は達成した目標の点と皇帝の2点。同点ならパンダの目標の点が多い方、それも同じなら勝ちを分け合う

### データの出典

区画タイルと目標カード45枚の内容・点数は、公開されている2つの実装を突き合わせ、すべて一致したものを使った。

- [zdimension/takenoko](https://github.com/zdimension/takenoko)（`GameData.java`）
- [marcpinet/takenoko](https://github.com/marcpinet/takenoko)（`ObjectiveDeck.java`・`TileDeck.java`・`TilePatternObjective.java`）

区画の目標の形（まっすぐ・曲がり・三角・ひし形）と、2色のひし形の色の分け方（端と、隣の真ん中が同じ色）も両方で一致した。決まりは、公式のルールブック（英語、2020年の版）で確かめた。

### 解釈したところ

- 区画の目標の形は回してよいが、鏡写し（裏返し）は別の形とした（カードは裏返せないため）
- 雨と肥料：雨でも「伸びる」ので、肥料の区画は2つ伸びる
- 初めて灌漑されたときの竹は、肥料の区画でも1つ
- 改良のチップは、竹のある区画にも置ける（2020年の版のルールブックに「竹のない区画に限る」という決まりがないため）
- 竹の数は数えない（ルールブックに「足りなくなったら、ほかの色で代わりに表してよい」とあるため。なお、竹の数は版によって緑36・黄30・桃24 と 緑28・黄26・桃24 の2通りがある）

## CPU

`public/js/cpu-player.js`。1つずつ命令を決める（その場の盤面から毎回考える）。

- 達成できる目標があれば、すぐ達成する
- 天気：雨は庭師の目標に近づく区画、嵐はパンダの目標に要る色、雲は庭師の目標に要る改良をその色の区画へ、？は雨か晴れ
- 行動：庭師（竹が目標の高さに近づく・庭師が乗ったまま達成できる）、パンダ（要る色を食べる、自分の庭師の目標の竹は食べない）、灌漑（新しく灌漑される区画）、区画（庭が小さいうちは高め）、目標を引く（手札が少ないほど高め）を見積もって選ぶ
- 強すぎないように、行き先の見落としと見積もりのぶれを入れている

| 強さ | 見落とす確率 | 見積もりのぶれ |
|---|---|---|
| やさしい | 35% | ±2.5 |
| ふつう | 12% | ±0.8 |

CPU の判断には、ゲームの乱数を使わない（状態から作った別の乱数を使う）。

測った結果（`npm run bench:cpu 60`、各 60 試合。終わらない試合は 0）：

| 組み合わせ | 結果 |
|---|---|
| ふつう 同士（2人） | 平均 34.8点・目標 8.1枚、約36手番 |
| ふつう 同士（3人） | 平均 29.3点・目標 6.8枚、約43手番 |
| ふつう 同士（4人） | 平均 23.4点・目標 5.5枚、約46手番 |
| やさしい 対 ふつう | やさしいの勝率 25% |
| ふつう 対 ランダム | ふつうの勝率 100% |

| ファイル | 内容 |
|---|---|
| `public/js/data.js` | 区画タイルと目標カードのデータ |

| `public/js/main.js` | 画面と入力 |

| `tools/cpu-bench.mjs` | CPU の強さを測る |

### オンライン対戦を入れるとき

netplay-kit の「サーバーがゲームを進める型」にそのまま差し込める形にしてある。天気のダイスもゲームのシード付き乱数で振るので、記録から再現できる。

- `create`：`new Game(players, { seed })`
- `persist` / `restore`：`{ players, options: { seed }, commands }` と `Game.replay`
- `view`：`createGameView(game, seat)`
- 操作は README の上の一覧と `game.js` の冒頭を参照。断る操作は状態を変えない
- CPU：`runCpuStep(game)`
