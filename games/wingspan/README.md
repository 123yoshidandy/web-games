# ウイングスパン

鳥を集めて自分の生息地（森林・草原・湿地）に出し、得点を競うボードゲーム「ウイングスパン（Wingspan）」の基本セットを、ブラウザで CPU と遊べるようにしたもの。2〜5人（あなた＋CPU 1〜4人）。スマホの縦持ち向け（PC でも遊べる）。ホーム画面に置くと、オフラインでも遊べる。

絵（鳥・餌・巣・生息地のアイコン）は、すべて SVG で自作している。

## 遊び方

- 準備：鳥5枚・ボーナスカード2枚・餌5つ（各種1つ）を配る。鳥を残した数だけ餌を捨て（鳥と餌を合わせて5つ）、ボーナスカードを1枚残す
- 4ラウンド。手番は第1ラウンドから 8・7・6・5 回ずつ。手番には次のどれか1つを行う
  - 鳥を出す：住める生息地の左から置く。餌を払い（どれでも2つで、好きな1つの代わりにできる）、2羽目からは卵も払う（2・3羽目は1個、4・5羽目は2個）。白い能力はここで働く
  - 森林：餌箱のサイコロから餌を取る（すべて同じ面なら振り直せる。空なら振り直す）
  - 草原：卵を産む（鳥ごとに上限がある）
  - 湿地：場の3枚か山札からカードを引く（場は手番の終わりに補充する）
- 森林・草原・湿地の量は、その列の鳥の数で増える（森林 1・1・2・2・3・3、草原 2・2・3・3・4・4、湿地 1・1・2・2・3・3）。2・4・6番目の位置では、ボーナスの交換（森林：カード→餌、草原：餌→卵、湿地：卵→カード）を1回できる
- 行動のあと、その列の茶色の能力を右から順に使える
- ラウンドの終わりに、そのラウンドの目標（緑の面）を採点する。1〜3位に順位点（第1ラウンド 4・1・0、第2 5・2・1、第3 6・3・2、第4 7・4・3）。同じ数なら占める順位の点を足して人数で割る（切り捨て）。0 の人は点なし。場の3枚を入れ替え、先手を次の人に回す
- 得点：鳥の点・ボーナスカード・ラウンドの目標・卵・貯えた餌・差し込んだカード（各1点）。同点なら、残った餌の多い人の勝ち

### 鳥のカードの選び方

- 基本セット（北アメリカの鳥）から、**ピンクの能力（ほかの人の番に働く）を持たない鳥を 135 羽**選んだ。森林 58・草原 72・湿地 62 羽（2つ以上の生息地に住む鳥は重ねて数える）
- 茶色（行動のとき）と白（出したとき）の能力は、次の種類を入れた：餌箱から取る・貯える・サイコロで狩る・山札をめくって捕らえる（翼開長の比べ）・手札を差し込む・卵を産む・カードを引く・全員が得る・卵や餌を捨てて得る・餌を替える・ボーナスカードを引く・もう1羽出す、など
- 入れなかった能力：ピンクの能力全部、「右端なら別の生息地へ移る」「ほかの鳥の茶色の能力をくり返す」「手番の終わりに手札を捨てる」など、手番の流れを大きく変えるもの
- 点・餌・巣・卵の上限・翼開長・能力は、本家のカードに合わせたつもりだが、手元の資料から起こしたため、一部が本家と違う可能性がある（`public/js/birds.js` の表を直せば変わる）
- 名前に頼るボーナスカード（解剖学者・地図製作者・写真家・歴史家）は、日本語の名前では成り立たないので入れなかった。ピンクの能力に頼るもの（行動学者）も入れない。残りの 23 枚の点の数え方も、手元の資料から起こしている
- ラウンドの目標は、生息地の鳥・生息地の卵・巣の種類ごとの卵・卵のある巣の鳥・鳥の数の 15 種類から4つ選ぶ。採点は緑の面（順位点）

### ルールで割り切った・自分で決めたこと

- 茶色の能力は、選ぶものがないもの（貯える・狩る・捕らえる・この鳥に卵・1枚引く・全員が得る など）は自動で使う。本家では「使ってもよい」だが、使わない理由がほぼないため。選ぶものや払うものがある能力（差し込む・卵や餌を捨てる・餌を替える・好きな鳥に卵）は、使うかどうかを選べる
- 餌箱から取る能力で、欲しい餌がなく、サイコロがすべて同じ面なら、自動で振り直してから取る
- 2つで1つの代わりにする払い方は、そのままでは払えないときだけ候補に出す（ルール上はいつでもできる）
- 草原のボーナスの交換は、産める場所が足りないとき、湿地のボーナスの交換は引けるカードが足りないときは、選べないようにした
- 準備は全員が同時に選ぶ。最初の手番（本家では「最近鳥を見た人」）は、ランダムに決める
- 餌の補給所は無限にある

### 画面

- 押せるもの（行動の札・手札・餌箱のサイコロ・卵を産める鳥）を金色に光らせる
- 手札の鳥を押すと、中身と出す場所・払い方（餌の組み合わせ・卵を取る鳥）のシートが出る。自分の場や相手の名前を押すと、中身を見られる
- 上の「目標」から、4ラウンドの目標と各人の途中経過・結果を見られる
- 途中でホームに戻っても、「続きから」で再開できる

## CPU

- 手番の行動は、候補（出せる鳥を出す・3つの生息地の行動と、ボーナスの交換）ごとに写したゲームで手番の終わりまで進め、さらに自分の手番を2回だけ単純な方針で進めてから、盤面の価値（今の得点＋目標の見込み＋餌・手札・列の鳥・茶色の能力の、残りの手番で生きる分）を比べて選ぶ
- 写したゲームでは、山札とこの先のサイコロを混ぜ直す（見えない情報をのぞかない）。ゲームの乱数も使わない（記録の再現がずれないように）
- 手番の中の細かい選択（どの餌を取るか、どの鳥に卵を置くか、能力を使うか）は、手札の鳥に足りない餌・目標・ボーナスカードから見積もる

| 強さ | 中身 |
|---|---|
| やさしい | 先読みをせず、出せる鳥があれば出し、なければ足りないものを取る。ときどき迷う |
| ふつう | 上の先読みで選ぶ |

CPU 同士の対戦：

| 対戦 | ふつうの勝率 | 得点の平均（ふつう／やさしい） |
|---|---|---|
| 2人：ふつう 対 やさしい（200 試合） | 93.5% | 70.3／50.4 |
| 3人：ふつう1 対 やさしい2（200 試合） | 89.5% | 69.2／49.1 |
| 5人：ふつう1 対 やさしい4（100 試合） | 83.0% | 68.1／47.1 |

重みは、変えた版と元の版を直接対戦させて決めた。先読みの「自分の手番を2回」は、0 回の版に 150 試合で勝率 49%（公平なら 33%）、得点 +4.8 だった。3回・4回にしても強くならなかった。

```bash
# 試合数・人数・席ごとの強さ（easy・normal・random はでたらめ）
node scripts/cpu-match.mjs 200 3 normal,easy,easy
```

## 開発

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。

```bash
# 画面（http://localhost:8000/）。?cpuDelay=50 を付けると CPU の間を縮められる
python3 -m http.server 8000 --directory public

# テスト（Vitest。web-games の直下で）
npm test -w games/wingspan
```

| ファイル | 役割 |
|---|---|
| `public/js/birds.js` | 鳥・ボーナスカード・ラウンドの目標のデータ |
| `public/js/game.js` | ルール。操作は `applyCommand` に通して記録し、`Game.replay` で再現できる。カードの効果は手順の列に積み、選ぶものがあれば選択待ちで止まる |
| `public/js/game-view.js` | プレイヤーから見てよい情報だけのビュー（ほかの人の手札・ボーナスカード・準備の配り札は伏せる） |
| `public/js/cpu-player.js` | CPU |
| `public/js/game-controller.js` | ローカル対戦の進行と、途中経過の保存（`wingspan.save`） |
| `public/js/ui.js` | 画面 |
| `public/js/art.js` | 絵（餌・巣・生息地・鳥）と、能力の説明文 |
| `server/src/game-definition.js` | オンライン対戦（netplay-kit）用のゲームの定義 |
| `server/src/handler.js` | オンライン対戦のサーバーの入口（AWS Lambda） |
| `public/js/online-config.js` | オンライン対戦の接続先 |
| `public/js/netplay/` | netplay-kit のクライアントとロビーの画面の写し（同期で置く。手で直さない） |

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2〜5人で、足りない席は CPU で埋められる。ほかの人の手札と山札の並びはビューに入れない。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'wingspan' })`。web-games の1つのスタックから `?game=wingspan` で呼ばれる）
- ゲームの定義は `server/src/game-definition.js`（記録だけを保存して再現する。各席には、その席から見えるビューだけを送る）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
