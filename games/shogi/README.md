# 将棋

本将棋（平手）をブラウザで遊べる。スマホの縦持ち向けで、PC でも遊べる（幅の広い画面では、盤の右に棋譜を出す）。

- CPU と対局（やさしい・ふつう・つよい・とてもつよい。先手・後手を選べる）
- 2人で1台を使って対局
- 待った（1手戻す）、投了、棋譜、続きから
- ホーム画面に追加すると、オフラインでも遊べる（PWA）

駒は CSS の五角形に漢字で描く。アイコンは自作の SVG。

## ルール

日本将棋連盟の対局規定（本将棋）に合わせた。

- 9×9 の盤。先手（▲）が下、後手（△）が上。先手から交互に1手ずつ指す
- 成り：敵陣（奥の3段）に入るとき、敵陣の中で動くとき、敵陣から出るときに成れる（任意）。行き所のなくなる駒（一段目の歩・香、二段目までの桂）は必ず成る。金と玉は成らない
- 持ち駒：取った駒は元の駒に戻して持ち駒になり、空いた升に打てる
- 禁じ手：二歩、打ち歩詰め（突き歩詰めはよい）、行き所のない駒を打つ・成らずに動かす、王手の放置（自玉が取られる手）
- 詰み：手番の側に指せる手がなければ負け
- 千日手：同じ局面（盤・持ち駒・手番）が4回現れたら終わり。連続王手の千日手は、王手をかけ続けた側の負け（同じ局面が最初に現れてから4回目までの、その側の手がすべて王手だったとき）
- 投了

### ルールと違う点・決めた点

- **禁じ手は指せないようにしている。** 実際の対局では禁じ手を指すと反則負けだが、画面では指せない手を選べない（操作として送っても断る）
- **千日手（連続王手でないもの）は引き分け。** 規定では指し直しだが、画面では引き分けで終わる
- **入玉宣言・持将棋は入れていない。** 手数の上限もない。双方が入玉して詰まなくなったら、投了か待ったで終える
- **待った** は規定にはない。ローカルの対局だけで使える（オンライン対戦の定義には入れていない）
- **持ち時間・秒読み** は入れていない

## 操作

- 自分の駒を押すと、動ける升に点が付く（取れる升は枠）。点の升を押すと指す。別の自分の駒を押すと選び直す
- 成れるときは「成る／成らない」を聞く。行き所がなくなるときは聞かずに成る。外を押すと選び直す
- 持ち駒は、押してから打つ升を押す（打てる升に点が付く）
- 直前の手の升を色で示し、その元の升も薄く色を付ける。王手のときは玉の升を赤くし、上のバーに「王手」と出す
- 上のバー：左がホーム、手番と直前の手。右が棋譜・待った・投了・遊び方
- **待った**：CPU 戦では、あなたの直前の手とそのあとの CPU の手をまとめて戻す。2人のときは1手ずつ戻す。投了や詰みのあとでも戻せる
- **続きから**：手を指すたびに記録を保存する。タイトル画面の「続きから」で再開する。決着したら消す
- CPU 戦で後手を選ぶと、盤を回して自分の側を下に描く。2人のときは先手が下

### 棋譜の表記

「▲７六歩」「△同　歩」「▲２二角成」「▲３三桂不成」のように書く。打つ手は、盤の同じ駒もその升へ行けるときだけ「打」を付ける。同じ駒が2枚以上その升へ行けるときは、動き（上・引・寄）、位置（右・左）、まっすぐ上がる手（直。龍・馬には使わない）で区別する。日本将棋連盟の表記に合わせたつもりだが、3枚以上が同じ升へ行けるときなど、まれな形は確かめきれていない。

## CPU

CPU は局面と、これまでの局面（千日手の判定に使う）を見て決める（`public/js/cpu-player.js`）。ゲームに乱数はなく、CPU の判断にも使わない。迷いを足す強さでは、局面から作った別の乱数を使うので、同じ局面なら同じ手になる。

読みは `public/js/engine.js`：

- **局面の点**：駒の価値（持ち駒は少し高く）＋ 相手の玉に近い駒への加点（攻め）＋ 自分の玉に近い金銀への加点（守り）＋ 玉が自陣の奥にいるほどの加点
- **読み**：反復深化のアルファベータ法（ネガマックス）。置換表・キラー・履歴で手を並べる。深さが尽きたら、取る手と成る手だけを読む（静止探索）。王手をかけられた局面は深さが尽きても1手延ばす
- 読む量は、深さと局面の数（node の上限）で打ち切る。時間では打ち切らない（端末の速さで手が変わらないように。テストで再現できるように）
- **千日手**：対局で現れた局面と、読みの途中の局面に戻る手は 0 点（引き分け）と見る。指すとちょうど4回目になる手は、連続王手かどうかまで判定して点を決める（連続王手の千日手で負ける手は指さず、相手の連続王手で勝てる手は指す）
- CPU は投了しない

| 強さ | 読み |
|---|---|
| やさしい | 1手（取り合いは読む）。点に大きな迷い（最大 300 点。歩3枚ほど）を足す |
| ふつう | 2手。点に少し迷い（最大 40 点）を足す |
| つよい | 3手 |
| とてもつよい | 必ず3手。局面の数が上限に届くまで1手ずつ深く（6手まで） |

### 勝率と1手の時間

`node scripts/cpu-match.mjs <試合数> <強さA> <強さB>` で測った。同じ強さの CPU は同じ局面で同じ手を指すので、最初の4手をシード付きの乱数で指してから CPU に任せ、試合ごとに席（先手・後手）を入れ替えた。400手で打ち切るが、打ち切った試合はなかった（すべて詰みで終わった）。

| 対戦 | 試合数 | 勝率 | 平均の手数 |
|---|---|---|---|
| ふつう 対 やさしい | 20 | 100% 対 0% | 76手 |
| つよい 対 ふつう | 20 | 90% 対 10% | 97手 |
| とてもつよい 対 つよい | 16 | 75% 対 25% | 98手 |

試合数が少ないので、勝率の揺れは大きい（16試合で ±10 ポイントほど）。どの組も強い方が勝ち越した。

1手の時間（開発用の Mac、Apple M2 Pro、Node 22。上の対戦の計測から）：

| 強さ | 平均 | 99% | 最長 |
|---|---|---|---|
| やさしい | 1ms | 3ms | 4ms |
| ふつう | 17〜35ms | 100〜200ms | 225ms |
| つよい | 9〜29ms | 100〜140ms | 167ms |
| とてもつよい | 317ms | 672ms | 898ms |

スマホでは、この数倍（およそ3倍と見込む）かかる。とてもつよいの最長は、スマホで約3秒の見込み。局面の上限は、つよい 6万・とてもつよい 25万。最低の深さ（3手）は上限の2倍まで読む（4倍にしていたときは、とてもつよいの最長が 1.35 秒だったので下げた。勝率は変わらなかった）。

CPU は、前の手が見えるように 0.45 秒おいてから考え始める。CPU は Web Worker（`public/js/cpu-worker.js`）で考えるので、考えている間も画面は動き、待った・投了・ホームのボタンが効く（考え中の Worker は止めて、その返事は捨てる）。Worker が使えない環境（テスト・`cpu-match.mjs`）や、Worker がエラーになったときは、その場で考える。

## 開発

素の HTML / CSS / JavaScript（ES Modules）。ビルドはない。

```bash
npm test                                         # Vitest（web-games の直下からは npm test -w games/shogi）
python3 -m http.server 8080 --directory public   # http://localhost:8080/
node scripts/cpu-match.mjs 20 strong normal      # CPU どうしの勝率と1手の時間
```

### ファイル

| ファイル | 役割 |
|---|---|
| `public/js/rules.js` | 盤・駒の動き・局面（指す・戻す・利き・ハッシュ・SFEN）・合法手（二歩・行き所のない駒・王手の放置・打ち歩詰めを除く）・perft |
| `public/js/notation.js` | 駒の名前と棋譜の表記 |
| `public/js/game.js` | 進行（手番・詰み・投了・千日手）。操作は `applyCommand` だけで受け、記録から `Game.replay` で再現する。断る操作は状態を変えない |
| `public/js/game-view.js` | 席ごとのビュー（盤・持ち駒・手番の人の指せる手・王手） |
| `public/js/engine.js` | CPU の読み（局面の点、アルファベータ法、静止探索、置換表） |
| `public/js/cpu-player.js` | CPU の強さと、手を決める処理（千日手で終わる手の判定） |
| `public/js/cpu-worker.js` | CPU の読みを別のスレッドで動かす Web Worker（記録から局面を作り直して手を返す） |
| `public/js/game-controller.js` | ローカルの対局（CPU 戦・2人で1台）。待った、投了、保存と続きから、CPU を間を置いて Worker で指させる |
| `public/js/ui.js`・`art.js` | 画面と絵 |
| `public/sw.js`・`manifest.webmanifest` | PWA（自分のファイルはネットワークを先に、字体はキャッシュを先に使う） |
| `server/src/game-definition.js` | オンライン対戦の「ゲームの定義」（netplay-kit の形） |
| `scripts/cpu-match.mjs` | CPU どうしの対戦と勝率・1手の時間 |

### テスト

- `rules.test.js`：升の番号、最初の配置、SFEN の読み書き、指して戻すと元に戻る、手順が違っても同じハッシュ、perft（最初の局面から 1〜4手で 30・900・25470・719731）、ルールとは別に素朴に書いた合法手の生成とランダムな対局の数千局面・中盤の局面の2手先で突き合わせ、二歩・打ち歩詰め（突き歩詰めはよい、逃げ道や取る駒があれば打てる）・行き所のない駒（先手・後手）・王手の放置とピン・成れない駒・敵陣から出る成り・成り駒を取ると元に戻る
- `notation.test.js`：同・成・不成・打・右・左・直・寄・上・引（後手の向きも）
- `game.test.js`：手番、断る操作で状態が変わらない（ランダムな操作を大量に送る）、成りの指定、詰み、打ち歩詰めを断る、投了、千日手（引き分け）、連続王手の千日手、ランダムな試合の終わり方と記録からの再現、持ち駒を打つ
- `cpu-player.test.js`：どの強さも1手詰めを指す、ただで取られる飛をそのままにしない、同じ局面で同じ手、連続王手の千日手で負ける手を避け勝てる手を選ぶ、局面の数で打ち切る、CPU どうしの試合が終わり、ふつうがやさしいに勝ち越す
- `game-controller.test.js`：CPU が人の番で止まる、後手を選ぶと CPU が先に指す、待った（CPU 戦・2人・投了のあと）、続きから、Web Worker で考える流れ（偽の Worker で：返事で指す、考え中の投了で Worker を止める、待ったで取り消した返事を捨てる、Worker のエラーでその場で考える）
- `game-definition.test.js`：オンライン対戦の定義（受け付け・断る・投了・再現・CPU の代行）とビュー
- `pwa.test.js`・`offline.test.js`：PWA のファイルとアイコン、オフラインでの起動（service worker をキャッシュとネットワークを差し替えて動かす）

### オンライン対戦

netplay-kit の「サーバーがゲームを進める型」。2人で、相手がいなければ CPU で埋められる。対戦中に部屋を出た人の席は CPU が引き継ぐ。オンラインではヒントを出さない。

- 手元で遊ぶ：web-games の直下で `npm run dev:online`（全ゲームのテスト用サーバー。ws://localhost:8787）を起動し、`public/` を localhost で開いて「オンラインで遊ぶ」
- 入口とロビーの画面は、netplay-kit の `netplay-lobby.js`（`public/js/netplay/` の写し。ここでは直さない）
- 接続先は `public/js/online-config.js`。`DEPLOYED_SERVER_URL` が空のあいだは、公開したページで「オンラインで遊ぶ」を出さない（web-games のサーバーをデプロイしたら書く）
- サーバーの入口は `server/src/handler.js`（`createHandler(定義, { keyPrefix: 'shogi' })`。web-games の1つのスタックから `?game=shogi` で呼ばれる）
- テストは `test/online.test.js`（test-kit の `testOnline` で、部屋の作成・開始・終局まで・再接続・退出を確かめる）
